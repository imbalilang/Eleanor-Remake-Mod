# 美术管线验证

> 本文件是美术管线验证的唯一记录。所有验证过程、结论与更正都追加在这里，不再另建文档。
> 原始证据（图片、请求日志、JSON 摘要）按日期留在 `Art/` 下的试验目录，本文件只引用不复制。
>
> 我们的角色：为项目做**技术管线验证**，判断哪个模型适合哪个环节、什么参数、什么失败模式。
> 不直接生产运行资产；`Art/` 是候选区，`Textures/Items/` 是运行区，没有作者指令不写入。

## 一、已确立结论

### 1.1 中转接入（OpenRouter）

- 图像模型只在 `GET /api/v1/images/models`（70 条）里；`GET /api/v1/models` 的 480 条不含图像模型。
- OpenRouter 只认 `Authorization: Bearer`。DSH 的 `google` provider 发 `x-goog-api-key` 且用 Gemini 请求体，**接不上**：先 401 `No cookie auth credentials found`，补 Bearer 后 400 `invalid_prompt`。
- 带参考图必须用 `input_references`，元素为 `{"type":"image_url","image_url":{"url":"data:..."}}`。**字段名写错不报错、静默忽略**，会按纯文字重新生成。
- `POST /api/v1/images/edits` 返回 404，插件三种编辑格式全部打这个端点，因此经 OpenRouter 只能文生图。
- 地区封锁只压 `chat/completions`；`/images/generations` 直连可用。

### 1.2 参数名的静默陷阱

- xAI 的档位参数是 **`resolution`（1K/2K）**。`size` 会明确报错并提示正确参数名；**`image_size` 被静默丢弃**，返回 200 但尺寸不变。
- 判断参数是否生效只能看返回图真实像素，不能看请求是否成功。
- **作者决定**：不为此单独付费穷举测试。改为三条零成本规则——顺带记录、只在成为约束时查、以像素为准。

### 1.3 两轴容忍度

以两张实测参考图为锚：**T1** = 大尺度蕾丝连体衣母图；**T2** = 更直白的动作参考图。

| 供应商 | T1 图片 | T1 文字（原提示词） | T2 图片 |
|---|---|---|---|
| Grok 2.0 | 通过 | 通过 | **通过** |
| Seedream 5.5 | 通过 | 通过 | 拒，6.3 s |
| OpenAI 2.6-flare | 通过（概率性） | 拒，中性改写后才过 | 拒，7.9 s |
| Gemini 3.1 flash | 拒 `IMAGE_PROHIBITED_CONTENT` | 通过（纯文本） | 未测 |
| Qwen image-3-pro | 拒 | 拒 | 未测 |
| 腾讯混元 v3.5 | 通过 | 通过 | **通过** |

- T1 上 Seedream 与 OpenAI 都接受图片，差别只在文字。
- T2 上两者同时失效，共同天花板落在 T1 与 T2 之间。
- Gemini 图窄字宽：拒母图，但原提示词纯文本能过。

### 1.4 通过率是确定性还是概率性

| 模型 | 重复 | 结果 | 结论 |
|---|---|---|---|
| 腾讯混元 v3.5 | 7 | 7/7 通过 | 确定性 |
| Seedream 5-5 系 | 5 | 拦截文案与耗时一致 | 确定性 |
| Grok 2.0 | 4 | 4/4（换装要求除外） | 确定性 |
| OpenAI 2.6-flare | 3（同一请求） | **200 / 400 / 400** | **概率性** |

OpenAI 单次成功不算能力，单次失败也不能证明某型号更严；实践上被拒重试 2–3 次比研究哪家宽松划算。

### 1.5 次级型号没有更宽松的

- Seedream 4.5 / 5-0-pro / 5-0-flash / 5-0-lite：与主型号拦截完全一致。
- OpenAI：`gpt-image-1`、`gpt-5-image` 在 OpenRouter 映射到不存在的上游模型，不可用；`gpt-image-2`、`2.5-flare` 拒；mini 型号同样拒。
- **八家筛查**（T2 图 + 中性指令）：recraft、krea、tencent 通过；black-forest-labs、microsoft、minimax、sourceful、meta 在图像入口即拒。recraft 与 krea 只支持单张参考图。

### 1.6 清晰度门槛

用 `tools/check_repaint_sharpness.py`（lap_var ≥ 270、sobel ≥ 3.4）测同场景角色图：

| 模型 | 尺寸 | lap_var | sobel | 判定 |
|---|---|---|---|---|
| Seedream 5.5 | 2048×1152 | 529.3 | 9.69 | PASS |
| Grok 2.0 | 1280×720 | 919.9 | 13.31 | PASS |
| OpenAI 2.6-flare | 1536×864 | 705.8 | 13.21 | PASS |
| 腾讯混元 | 2732×1536 | 894.9–1073.4 | 11.65–12.41 | PASS |

### 1.7 输出尺寸

- Seedream 2048×1152（16:9）；OpenAI 1536×864；腾讯 2732×1536（16:9）/1536×2048（3:4）。
- Grok：1280×720（1K）、**2816×1584（16:9 + `resolution:"2K"`）**。
- 四家都能满足 CG 目标 1664×936，**分辨率不构成筛选条件**。

### 1.8 输出格式与有损风险

按磁盘上文件真实字节统计（不是 API 声明的 `media_type`）：

| 模型 | 实际格式 | 说明 |
|---|---|---|
| Seedream 5.5 | PNG | 1536×2048 / 2048×1152 |
| OpenAI 2.6-flare | PNG | 1152×1536 / 1536×864 |
| 腾讯混元 v3.5 | PNG | 1536×2048 / 2732×1536 |
| Gemini 3.1 flash | PNG | 1376×768 |
| Grok 2.0（1K 档） | **JPEG** | 864×1152 / 1280×720 |
| **Grok 2.0（`resolution:"2K"`）** | **PNG** | 2816×1584 |
| Recraft v4 | **WebP** | 1080×1401 |

三个坑：

1. **`media_type` 字段不可信。** Recraft 声明 `image/jpeg`，实际字节是 WebP；我们的脚本按声明取扩展名，产生了 `screen_recraft.jpg` 里装着 WebP 的文件。
2. **看图工具的预览会重编码。** 读图时显示为 `image/jpeg` 可能只是附件副本被转码，不代表原文件有损。腾讯那批一度被误判为 JPEG，实际都是 PNG。
3. **格式可能与档位绑定。** Grok 1K 给 JPEG，2K 给 PNG——同一模型不同档位格式不同。

对管线的意义：

- 画像母图要送 B/detail 的 detail 采样的，**只用 PNG**：Seedream、OpenAI、腾讯、Gemini，或 Grok 的 2K 档。
- **Grok 1K 与 Recraft 属有损输入**，格式本身就不适合当母图。
- 所有模型输出都是 **RGB、无 alpha**，说明"拿不到透明度"是普遍情况，不是某家的缺陷。

**有损程度实测**（以 Seedream PNG 母图为基准，模拟编码后缩到 960×540 再比）：

| 处理 | 960×540 下 PSNR | lap_var | sobel |
|---|---|---|---|
| PNG 直接缩 | 基准 | 533.5 | 9.95 |
| JPEG q95 4:4:4 | 46.74 | 528.5 | 10.14 |
| **JPEG q95 4:2:0（Grok 实际参数）** | **43.44** | 523.0 | 10.12 |
| JPEG q90 4:2:0 | 41.58 | 523.5 | 10.13 |

Grok 的 JPEG 经量化表反推为 **4:2:0 色度抽样、约 q95**。色度分辨率减半，实测比 4:4:4 低约 3.3 dB。

结论：**在 960×540 交付尺寸下，肉眼无差别**（4× 最近邻放大对照无可辨差异，PSNR 43 dB 高于常用 40 dB 视觉无损线）。真正要注意的是分辨率——Grok 1K 只有 1280×720，够 960×540，不够 1664×936。

**尺寸策略（作者决定）**：尺寸按交付目标定，不按模型上限。

- 交付 288×212 画像、960×540 CG：1K 档就够，默认用 1K。
- 只有需要 1664×936 的 A 规制母图才上 2K。
- 理由不只是省成本：**要求更大尺寸时，模型会往画面里补更多未要求的细节**，包括没让它画的道具、背景元素和装饰纹理，反而污染内容。小尺寸的克制是有价值的。

已知的未要求元素案例：卧姿测试里 Seedream 与 OpenAI 都自行在床头柜上加了杯子和书，提示词里没有这些。这是"补细节"倾向的直接证据，但尚未做分辨率对照实验。

同 prompt 的 1K/2K 免费对照（Grok 苹果图）无法判定，因为主体过简且边缘指标随分辨率反相——要验证需用有场景的角色图做对照。

### 1.10 腾讯混元作为大尺度兜底

- 唯一通过"整身换装"的模型（Grok 在同要求上 400，OpenAI 400）。
- 7/7 稳定通过，支持 16:9。
- 硬要求：服装必须写进文字（同参数三次出现过两种服装解释）、必带画风锁、必锁景别。
- 定位：别人拒了它能接，不当主力。

### 1.11 服装设计 pilot

- 换装指令有效：`replace it completely` 后六张都没有照抄基底服装。
- 常服与内搭用分档基底可行：常服基底（连帽衫母图）偏置小，内搭基底（蕾丝连体衣母图）品类对口。
- **brief 过具体会收敛**：写了 `apron-like`，三家全画围裙——那考的是服从性不是创造性。
- 结论：设计类测试要用"同一宽 brief 重复采样看发散度"，单张读不出创造性。

### 1.12 P 规制锚定母图与运行资产的一致性

锚定母图：`Art/main-menu-reference-2026-11-23/menu_background_bazaar.png`（960×540，RGB，128,212 B，与根目录副本同哈希 `654b77de…`）。

**结构判定**

| 项 | 值 | 含义 |
|---|---|---|
| 画布 | 960×540 | 与 P 规制交付尺寸一致，1×1 原生像素，无最近邻放大块 |
| 唯一色数 | 601 | — |
| 90% 像素覆盖 | **30 色** | 极高压缩，实际是按材质分组的有限调色板 |
| 零梯度相邻像素 | **83.2%** | 大片纯色块 |
| 微梯度（1–4） | **1.2%** | **几乎无抗锯齿**，硬边 |
| 平均亮度 | 66.3 | 偏暗；25.7% 像素 L<40 |
| 平均饱和度 | 71 | 低饱和底 + 局部高饱和点缀 |

主色（5bit 量化）：`#282030`、`#303040`、`#282838`、`#404048`、`#583848`、`#482838`、`#382838`、`#88B8B8`。
即：**近黑紫为底，青绿为冷色锚，暖红与赭为点缀**。

**画法特征**（4× 放大判读）

- 每材质 2–5 个色阶，平涂，靠色阶而非渐变表现体积
- 描边 1–2 px，纯黑或深紫
- 抖动仅用于特定材质（毛领、地面、灯笼辉光），非全局
- 轮廓光用 1 px 亮色描边（右侧人物为青色轮廓光）
- 灯笼辉光是同心色带，不是连续渐变

| 90% 覆盖色数 | **30** | 439 | 592 | 321 |

**结论：三张运行结尾 CG 不是锚定母图的像素语言。** 它们的微梯度占比高 33 倍、色数是 200–280 倍、更亮更饱和——属于"平滑插画 + 像素质感"，而不是硬边像素画。4× 放大对照见 `Art/main-menu-reference-2026-11-23/crops/anchor_vs_runtime_4x.png`。

**建议的 P 规制验收门槛**（供讨论）

**模型转换路线：不可行**（作者判定，2026-11-23）

尝试过两条路径：① 缩到 480 宽再 2× 最近邻放大；② 1:1 缩放到 960×540 后映射锚定母图调色板。配合 Grok 与 OpenAI 的风格转换各跑一轮（OpenAI 对含蕾丝连体衣的内容连拒 3 次，仅常服稿成功）。

结果全部是"色阶化的插画"：色带按亮度渐变分布，不按材质与形状分布；小画布路径把脸部细节毁掉，1:1 路径虽可读但仍是等高线。达不到锚定母图的画法水准。

**结论：P 规制不采用"生成 + 转换"路线，该项需手绘或另行制作。**

产物仅作证据保留：`Art/main-menu-reference-2026-11-23/pixelize-test/`。

上面的门槛表只用于手绘评审的粗筛，不能替代人眼——实测它无法区分真像素画与量化插画（3×3 全同率 52.7% vs 50.6%）。

**场景画法规则（从六张归纳）**

1. **价值链固定**：近黑紫打底（亮度 60–87），中间调结构，极少数亮色只给招牌与光源。
2. **空间靠结构线而非描边**：墙板接缝、管线走向、地板缝构成空间；不靠外轮廓线。
3. **玩家面对的场景是"柜台优先"构图**：一条水平台面把画面分成"我在内侧 / 来客在外侧"，柜台后通常是店主或暗龛。当铺与博士工坊是同一构图。
4. **招牌承担世界观**：价签、OPEN、通缉令、涂鸦、海报——文字与图形是画面里的信息层。
5. **单一主光源**：顶部灯带、单侧暖光或灯笼辉光，没有全局平光。

**对 CG 背景的约束**

- 当铺 CG 必须出现 **内凹售货窗 + 水平窗台 + 台面下暗龛 + 磨损金属墙板**，否则读不出是这个摊位。这与 `CLAUDE.md` 的店铺空间规则一致。
- 空间站材质标记：舱壁接缝、管线、外露设施、紧凑尺度。`Art/environment-reference-audit-2026-11-18/README.md` 记录过一次失败——恋爱书 CG 画成了现代校园图书馆（整面木书架 + 大采光窗 + 窗外绿树 + 满室金光），缺了舱壁与设施就丢了世界观。
- 上层区可用金属玻璃拱架、石阶、黄铜、栽培绿植；下层区用磨损金属、外露管线、窄通道。
- A 规制是高分辨率插画，不必照搬 960×540 的像素统计；但**价值链与结构线逻辑**要继承。

**画法细部测量**

| 项 | 实测 | 含义 |
|---|---|---|
| 同色游程中位数 | 2–4 px（横/纵） | **细节极密**，每 2–3 px 就变色，不是大块像素 |
| 2×2 棋盘抖动占比 | 0.10–0.28% | **几乎不用抖动**，明暗靠色阶不用网点 |
| 每 64×64 色数 | 9.8–29.1 | 局部色彩克制 |
| 显著亮度阶（16 级量化，占比>1%） | 6–10 级 | 全图不到十档明暗 |
| 90% 覆盖色 | 13–30 | 固定有限色板 |

五张累计主色：`#292234` 16.0%、`#2F2B3A` 8.6%、`#373541` 6.6%、`#392E3C` 6.0%、`#44464C` 5.6%、`#5F6868` 5.5%、`#453943` 4.3%、`#5A3D4C` 3.7%、`#88948A` 3.3%、`#4A2F38` 3.0%。即：**近黑紫打底约四成画面，冷灰青做中景，酒红与绛紫点缀，亮色只给招牌与光源。**

**为什么"生成后转换"达不到**

AI 输出是连续渐变；限色会把渐变切成**按亮度分布的等高线色带**，而锚定母图的色块是**按物体与材质分布**的。结构线若从这些色带边界生成，得到的是"玻璃彩绘"式的碎线。实测加 1px 边界线能把 lap 从 1386 推到 2495（接近锚定 2030），但视觉上只是给碎色块描边，质感没有变对。

**三条可选产出路线**

| 路线 | 做法 | 代价 | 适合 |
|---|---|---|---|
| **模块化拼装**（推荐） | 建一套 P 规制模块库：墙板、管线、卷帘、招牌、地面、道具、角色；每个模块按锚定色板与 1px 结构线制作；场景 = 模块拼装 + 局部手绘 | 前期投入大，之后复用便宜 | 多张 P 规制 CG、需要风格绝对统一。原作本身有 `wall_36.png` 这类提取贴图，说明它是模块化的 |
| **AI 平涂稿 + 手工像素化** | AI 只出平涂赛璐璐场景稿（5–8 色阶、无渐变），本地映射固定 30 色板，人再补 1px 结构线并清理关键区 | 每张都要手工过一遍 | 单张、构图特殊的 CG |
| 纯手绘 | 直接按锚定母图画 | 最慢最稳 | 量少且要求高 |

关键结论：**手工的结构线环节无法省。** 目前没有任何本地处理能替代"按物体边界画线"这件人工判断。

**已试过的算法路线与失败特征**（无手工前提下）

| 方法 | 失败特征 |
|---|---|
| 缩到 480 + 2× 最近邻 | 2×2 块，脸与蕾丝被毁；游程从 2–3 px 变成 2 px 块但细节全失 |
| 1:1 缩放 + 限色（32/48） | 色带按亮度成等高线，不按物体 |
| 限色后加 1px 边界线 | lap 从 1386 升到 2495，但线跟着色带碎边，成"玻璃彩绘" |
| SLIC 超像素压平 + 区域描边（S=5/8/12） | **网格状线网**覆满画面，像层纱；且锚定母图色板缺肤色，映射后脏 |
| 模型转像素 + 1:1 + 锚定色板 | 最接近，但仍偏"高细节插画"，亮度过高 |
| 模型按五张场景重画 + 降采样 + 色板 + 保线 | lap 追到 1876（锚定 2027），线是**断续斑点**不是连续笔画 |
| 模型"压平成 8 色海报" + 降采样 + k-means | 模型不服从极限制色（仍 1913–3009 色）；压平后细节整体消失，成色块 |
| 压平结果按区域边界描线 | 边界覆盖 31% 画面，整张糊成黑块 |

共同点：算法只能按**像素相似度**分组，无法做"哪些边界值得画线"的语义判断；而锚定母图的线全在语义边界上。

**最终判定：仅用生图模型 + 算法，达不到原作像素水准（作者判定）。**

适用范围限于本管线：OpenRouter 上的四家通用模型（Seedream / Grok / OpenAI / 腾讯混元）+ 本地后处理。未覆盖的边界：专门的像素画模型或 LoRA（无接入条件）；纯场景或纯道具题材（全部测试内容均为"角色 + 室内场景"）。若其中任一条成立，应重新评估，而不是把本判定当作"AI 永远做不到"。

**"1920 生成 → 降到 960"能否模拟 1px 笔触**

能模拟**线宽**，不能模拟**笔触**。关键在两点：

1. **缩放算法决定成败**：Lanczos 会产生过渡色（微梯度 20.7%、lap 335）；**多数投票降采样**（每个 2×2 取出现最多的颜色）保住硬边，lap 升到 605。
2. **顺序反过来才行**：必须在高分辨率先量化到极少色，再多数投票降采样。先缩放后量化会重新引入渐变。

最佳组合的数值（与锚定对比）：

| 步骤 | lap | 游程 | 零梯度 | 微梯度 | 线覆盖 |
|---|---|---|---|---|---|
| 锚定母图 | 2027 | 2.0 | 82.3% | 0.4% | — |
| 24 色 → 多数投票 | 700 | 2.0 | 85.2% | 0.3% | — |
| ＋强边界描线（top 4%） | **1821** | 2.0 | 81.1% | 1.0% | 10.6% |

**四项指标同时对齐**，是全部尝试里最接近的一次。但视觉上描边仍是断续的点，不是连续笔画——数值达标，观感未达标。

当前最接近的配方（未达标，仅存档）：

```
模型生成 1920 宽 → k-means 24 色 → 多数投票降到 960×540 → 按边缘对比度 top 4% 描 1px 暗线
```

**扩大画布能否解决线不连续**

不能，这是结构性的。实测同一张源图走 2× 与 4× 下采样（放大后量化再多数投票）：

| 路径 | 线覆盖 | 断头占比 | 线条平均邻居数 |
|---|---|---|---|
| 2× 下采样 | 11.1% | 1.1% | 5.31 |
| 4× 下采样 | 11.2% | 0.8% | 5.31 |
| 锚定母图 | 11.5% | 0.3% | 5.69 |

断头从 1.1% 降到 0.8%，其余几乎不变。原因是**放大器不创造信息**：把 2048 拉到 3840 只是插值，4×4 归并回 1 像素与 2×2 归并回 1 像素得到的是同一批颜色。

真正的限制不是采样密度，而是模型画什么：
- 线宽不随分辨率成比例增加（模型通常固定画 2–3 px 线），分辨率越高，线的**相对宽度越细**，降采样时反而更容易断
- 填充是带渐变的，不是平涂，任何采样都无法还原"没有的"平涂

**对模型直出像素风图的后处理测试**（样本 `20261123-160548.jpg`，1536×864 霓虹摩托 CG）

基线（缩到 960×540）：微梯度 30.7%、零梯度 3.6%、游程 1.0、90% 覆盖色 2290、亮度 107。

| 方法 | 微梯度 | 零梯度 | 游程 | 90%色 | lap | 边相关 | 判断 |
|---|---|---|---|---|---|---|---|
| 锚定母图 | 0.4 | 82.3 | 2.0 | 30 | 2027 | — | 目标 |
| k24 | **0.3** | 68.5 | **2.0** | 17 | 2499 | **0.953** | 平衡最好 |
| k48 | 0.9 | 57.7 | 1.0 | 37 | 2383 | **0.970** | 细节最多 |
| 中值+k24 | 0.6 | **76.6** | 2.0 | 17 | 1334 | 0.876 | 最平，细节损失大 |
| 锚定色板 48 色 | 2.5 | 60.9 | 1.0 | 24 | 2256 | 0.929 | 不如自身色板 |
| k24 + 强边界描线 | 0.6 | 65.0 | 1.0 | 25 | 4360 | **0.543** | 细节被毁，弃用 |
| 升 1920→量化→多数投票 | 0.7 | 67.9 | 2.0 | 17 | 3624 | 0.910 | 对比过强，细节降 |

**必须记住的坑：全局 k-means 会吃掉小面积的识别色。** 这张图的绿虹膜被量化成蓝紫色；补一个绿色保护色只恢复了一部分。角色 CG 不能直接用全局限色，调色板需要按区域保护（虹膜、发色、肤色）。

结论：k24 是"画风最接近且细节损失最小"的一档（边相关 0.953）；要更多细节用 k48；中值滤波和描边都会明显伤细节。所有结果亮度仍在 107，与原作 66 的差距来自内容（霓虹夜景 ≠ 暗调街景），不是处理能解决的。




本轮已穷尽的七条路线，失败模式一致：统计指标可对齐（游程、零梯度、90% 覆盖色、甚至 lap 都能追到锚定值），但视觉上始终是"色块化插画"或"斑点描边"，缺的是**按物体语义绘制的连续 1 px 结构线**。这不是调参问题，是"生成"与"绘制"的差别。

对项目的影响：

- **P 规制 CG 不进生成式管线。** 该轨的资产需要原作素材、专门的美术工作，或改变呈现方式。
- **A 规制不受影响**，画像与事件 CG 继续走验证过的路线。

| 步骤 | lap | 游程中位 | 零梯度 | 微梯度 | 亮度 |

数值上已经几乎对齐，但视觉仍是"带斑点的色块画"——线是断续的点，不是连续的 1 px 笔画。**指标能对齐，观感不能。**

### 1.15 后处理算法：本轮的改进与上限

实验目录 `Art/main-menu-reference-2026-11-23/pixelize-test/algo/`，评测口径见 `algo/eval.py`。
两张母图：室外 `20261123-160548.jpg`（霓虹摩托）、室内 `20261123-162448.jpg`（暗背景人物）。

**先看内容难度差**（锚定母图对照）：

| | 强边>20 的像素 | 平均梯度 | 亮度标准差 |
|---|---|---|---|
| 锚定母图 | 22.3% | 14.1 | 34.4 |
| 室外母图 | **39.6%** | 27.5 | 56.5 |
| 室内母图 | **10.2%** | 7.3 | 60.9 |

室外比锚定密 1.8 倍、室内稀一半。**能不能贴到锚定的平涂度，首先取决于内容密度**，不是算法参数。室外要压平必须删细节；室内平涂度天然超标，缺的是细节。

**最终结果**

| 图 | micro | zero | run | n90 | lap | corr | 文件 |
|---|---|---|---|---|---|---|---|
| 锚定母图 | 0.4 | 82.3 | 2.0 | 30 | 2027 | — | — |
| 室外 | **0.40** | 76.5 | **2.0** | **30** | 2096 | 0.961 | `algo/final/20261123-160548_A_iris2.png` |
| 室内 | 0.96 | **87.2** | 1.0 | 25 | 1976 | 0.961 | `algo/final/20261123-162448_A_iris2.png` |

**真正起作用的一步：多次迭代的小核双边滤波。** 它把渐变抹平而保住边缘：
- 室外 zero 68.5 → 76.5，corr 0.953 → 0.961（同时变好）
- 室内 lap 438 → 1989（k12 到 A 支最优）

对照：导向滤波次之；中值／Kuwahara／PM 各向异性扩散都明显毁边。

**四条件被证伪或修正的结论**

1. **"原始像素画的线是连续长笔画"是错的。** 锚定母图自身 1px 特征覆盖 10.40%，但断头率 19.3%、碎片率 42.4%、平均连通块 4.6px——原作是"大量短线 + 少量长线"。
2. **加线只对平滑底有用。** 室外底 lap 已 2095（锚定 2027），再加线 → lap 4297–8735、corr ≤0.92。室内底 lap 481 时加线才有意义。
3. **corr ≥0.95 对像素化本身过严。** 用锚定母图自标定：对 σ=0.7 平滑版 corr 只有 0.9186，对 640→960 只有 0.9055。像素画相对平滑源的 corr 上限就在 0.90–0.92。纯描线在 corr 0.95 时 lap 上限约 850。
4. **全局量化会吃掉小面积识别色**，绿虹膜会被并成紫。修法：把虹膜区域单独聚成 2 色再贴回，指标零代价（室外 zero 76.5→76.5、corr 0.961→0.961）。

**改不动的地方**

- 全局对比拉伸能拉 lap（室内 438→1126），但会把肤色打爆、色相偏移，不可用。
- 感知空间（Oklab）聚类只小幅改善 corr（+0.005~0.011），平涂度略降，边际改进。
- 量化后标签众数滤波：全图用 corr 0.809（太狠），限制在低梯度区只有 +1.8 个点，瓶颈不是碎点而是边缘密度。

**三支并行探索的结果**

| 分支 | 室外（zero / lap / n90 / corr） | 室内（zero / lap / n90 / corr） |
|---|---|---|
| 锚定母图 | 82.3 / 2027 / 30 / — | 同左 |
| A 边缘保持平滑 | **76.5 / 2095 / 30 / 0.961** | **87.2 / 1989 / 25 / 0.962** |
| B 区域化量化 | 76.1 / 2127 / 42 / 0.960 | 85.8 / 413 / 51 / **0.978** |
| C 结构线 | 76.5 / 2095 / 30 / 0.961（不加线） | 87.3 / 1445 / 16 / 0.952 |

- **A 的双边滤波路线整体最优**：室外 n90 与 micro 完全对上锚定，室内 lap 也进了目标区间。
- B 只在室内"色彩保真"一项跑赢（corr 0.978 vs 0.962），但 lap 413 需要补结构线才能用。
- C 证明了描线的适用条件：只对平滑底有效，且锚定自身的线是"大量短线"形态。

**当前可复用的处理链条**

```
母图缩到 960×540
→ 多次迭代小核双边滤波（压平保边）
→ k-means 量化（室外 k44、室内 k48）
→ 众数清理 + 梯度保护
→ 室内再加：unsharp 或暗侧边缘过冲 + 调色板吸附
→ 虹膜等小面积识别色单独聚 2 色贴回
```

产物：`algo/final/20261123-160548_A_iris2.png`、`algo/final/20261123-162448_A_iris2.png`（均 960×540）。

**脸部红晕细节：室外丢失的因果链**

作者观察：室内成品的红晕有层次（浅色内带红色点缀），室外只剩平涂浅红。实测确认，并定位到原因：

| 处理 | zero | corr | 脸颊区色数 | 前2色占比 |
|---|---|---|---|---|
| 源图 | — | — | 985 | 45.8% |
| 无平滑 + k44 | 60.1 | 0.973 | 32 | 72.0% |
| 全量双边 s10×2 + k44 | 75.9 | 0.962 | 29 | 72.1% |
| 脸部轻平滑 + k44 | 75.6 | 0.963 | 32 | 70.2% |
| 无平滑 + k96 | 50.6 | 0.985 | 63 | 68.7% |

结论：**红晕点缀是 1px、约 5–10 级的低对比纹理**。室外构图中脸只占画面约 1/6，点缀在 960×540 下就是一两个像素，两边都不放过它——σr=10 的双边滤波先把它当噪声抹平，44 色全局调色板也没有它的位置。补调色板色无效（平滑后那些像素已不存在）；提高色数有效但平涂度崩到 50.6。

室内没这个问题是因为脸占画面近一半，点缀有十几个像素，量化和平滑都留得住。

要保住它只有三条路：脸在画面里更大、输出分辨率更高、或接受 zero 掉到 50 量级。分区轻平滑能让脸颊色数从 29 回到 32，但肉眼看不出明显差别。
