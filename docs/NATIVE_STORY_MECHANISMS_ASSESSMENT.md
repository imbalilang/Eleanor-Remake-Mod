# 原版剧情、交易交互机制与埃莉诺剧情适配评估

核对日期：2026-11-08。依据本机游戏内部版本0.46D的实际程序集及当前MOD源码，不依据旧版攻略推测。本文为设计评估，没有实施新剧情，也没有发布工坊更新。

文中的第12～28章均为**阅读章**，与当前侍从文案的章节一致；例如阅读第12章对应运行时主线13，阅读第16章对应运行时主线17。不要据此直接修改运行时章节编号。

## 判断

值得优先补充的是三类体验：开门时发生的事、玩家亲手处理的东西、人物不来店里也能看见的后续。让关键节点各有一种动作，可以同时改善持续纯对话、章节间隔后忘记前情、玩家帮助她的过程只有口述这三个问题。

并非所有列出的机制都是现成的MOD注册接口。下表区分已经存在的底层表现与我们还要写的角色规则。可以复用原版的显示、物品、事件和生命周期，但不能调用原角色专用方法来假装发生埃莉诺剧情。

当前MOD也不是完全没有使用这些机制：赃物箱放上柜台触发逮捕、原版保释调度、实际纪念物、撤案新闻已经存在；垃圾填埋场协助事件在本地已完成但未发布。真正缺少的是把这些表现手段用于中后段关系与合作过程。

本汇总现同时覆盖特殊表现与通用交易交互。交易使用状态以当前工作区运行源码为准，包括已发布0.74及之后未发布的本地改动；“部分使用”表示原版底层已经继承或已有相似流程，但尚未专门用来组织埃莉诺剧情，不能简单视作完全没用过。

## 已有机制清单

成本为相对估计：低＝主要增加内容和少量状态；中＝增加一条独立流程及恢复逻辑；高＝涉及原版全局状态、操作竞争或新子系统。不是工期承诺。

| 机制 | 已确认的原版实例与行为 | 埃莉诺可用的位置 | 代价及选择 |
|---|---|---|---|
| 1. 开门即候客 | 卢、执法人员、打手等可预先站在柜台前；开门后自动进入晨间对白，不需要点下一位 | 第13章威胁，或第16章救母结果；后期少量熟悉关系后的早到 | 中，优先选择一个重大节点 |
| 2. 晨间留下实物 | 卢线会隔夜留下刻字弹药、柜子、感谢便笺与礼物；开门流程也处理其他原版奖励 | 第18章工作痕迹、第24章办妥的通行文件、第27章开张后的账单 | 低，最适合减少本人跑来报告 |
| 3. 可阅读、保存、翻页的文书 | 原版手写便笺，以及PaperBook/PaperUI；MOD有公开的注册、打开、生成文书物品接口 | 第12章研究摘要，第14～15章交涉回执，第24章证件副本，后期账本 | 低到中，优先；适合简短且可重看的事实 |
| 4. 摆放物品触发反应 | 来客有物品进入柜台、秤盘、展示柜等回调；卢会对明放在柜台的发信器反应；本MOD赃物箱也已使用此类触发 | 玩家出示文件、交回她委托的东西、把旧手镯或吊坠放在面前触发一次短反应 | 中，优先；不是必须完成买卖才有回应 |
| 5. 托管箱与内容状态 | 卢的箱子区分未动、打开过、拿走内容；发信器藏在被带走的容器中会改变结果 | 第12章保管研究资料；第25章准备样品箱、归还验货工具 | 中到高，第二批；现成的是容器操作，不是通用信任任务 |
| 6. 闭店/夜间异步处理 | 卢的柜子在夜间检查是否摆在前柜台及装了多少货；次晨才反映后果 | 第15章递交材料、第18章整理工作、第25章样品交付后的回执 | 中，优先用于后台结果，谨慎加入长对话 |
| 7. 夜间结果日志 | 举报、警告、转介绍、服务、塞尔皮科食物援助等在夜间结果中反馈 | 让玩家看见“材料已送达”“她完成了第一份验货记录”“合作账新增多少” | 低，优先；不是另发一次相同奖励 |
| 8. 新闻与延迟世界事件 | 塞尔皮科证据结局改变新闻，卢线行动之后可延时登报；本MOD已有撤案新闻 | 乙线撤案、第一单获认可、事业开张后的外部回响 | 低到中；当前撤案机制继续保留，不把私人恋爱登成新闻 |
| 9. 玩家主动打电话 | 原版供应商、治安部、王尔德等使用电话号码、通讯录、状态和电话对白 | 第14～15章联络核实，第24章后联系上层区的埃莉诺，筹备期间主动问进度 | 中，第二批；不是现成的剧情来电系统 |
| 10. 电脑上的收货委托 | 原版市场请求有新任务提示、指定物品及数量、信用点和声望奖励、期限 | 第25章后的公开补货小单，第27章以后她的长期客户需求 | 中，第二批；减少“她每次必须本人来收货” |
| 11. 外出地点里的真实操作 | 塞尔皮科线会识别留在垃圾填埋场的食物，并在离开时计入援助；有到达/离开地点钩子 | 前期见识她学习拾荒；后期协助时留下材料或取回约好的样品 | 中，第二批；原版离开地点不是一个泛用上交任务接口 |
| 12. 有效期明确的地点事件 | 垃圾倾倒、乔治奥协助等以地点卡片显示持续时间与效果 | 本地已做的“埃莉诺的协助”；也可承接她对旧货区域的了解 | 低，已接入；不重复叠加新的永久收益 |
| 13. 拔枪/举报/逮捕后的专属反应 | 卢和塞尔皮科有拔枪反应、收枪恢复、存活或逮捕变体；执法表现会用到附加角色槽位 | 黑市威胁者被真正举报或控制后的短反馈 | 高，暂缓扩张；本MOD已有的箱子逮捕/保释继续使用 |
| 14. 环境状态改变 | 原版报复会在夜间造成店面破坏；清洁、供电和封锁会影响经营与可见状态 | 威胁线的压力、后期她帮忙收拾店面 | 中到高，谨慎；改这些状态会产生真实费用和其他系统后果 |
| 15. 雇员远征与隔日返回 | 原版有雇员装备、派遣、逐夜执行与返回流程 | 事业稳定后可考虑她引荐一名普通供货伙伴 | 高，暂缓；不把她直接改成可受伤或失踪的通用雇员 |
| 16. 实物磁带与店内播放 | 原版磁带机实际读取装入的磁带，并有播放/停止/曲目状态 | 恋爱确认后，一件她挑选的旧磁带作为私人小礼物 | 中，备选；需要合适的声音内容，不是现成的角色语音留言功能 |

## 通用交易交互清单与当前使用情况

交易不能只按`BUY/SELL/...`枚举计数。同一种买卖可以同时具有品类限制、验货、批发、议价和追加需求；一个枚举存在也不代表当前版本平板支持它。以下分交易形式与过程变化两层，避免把普通议价误列为尚未使用。

### 交易形式、交付与服务入口

| 编号 | 原版已有形式与操作 | 当前MOD使用情况 | 适配判断 |
|---|---|---|---|
| T01 | 普通单向买卖：选货、出价、分次成交 | **已使用**。她购买食物、日用品，出售旧物/拾荒货；后期350/900预算采购也属此类 | 保持为基础，不需要为了多样性全部替换 |
| T02 | 可选批发：逐件谈价或整批收下 | **已使用**。`SetWholesale`用于旧物、拾荒及归来篇小批现货 | 不能把它算作新的未用机制 |
| T03 | 只接受整单批发，不允许拆零 | **尚未使用**。原版供应商有`isRegularSellDisable=true`；我们只提供可选批发 | 适合她后期带来的“一包配好的验货耗材”；须允许不买继续剧情 |
| T04 | 同次来访双向购销`SELLNBUY`：对方既带货卖，也从玩家处买东西 | **尚未使用**。原版废品商、部分供应商会这样做；我们目前每次固定一个买卖方向 | 适合筹备期她出售收来的旧货，同时补购工具。它仍是两笔报价，不自动等于以货抵款 |
| T05 | 真正以物易物`BARTER`：按指定物品/标签/状态条件交换，不经普通现金报价 | **尚未使用**。MOD没有`SetBarterOffer`；对白说交换、零价赠送或先买后卖均不算 | 适合早期缺现金或筹备期，以普通生活物资/工具交换一批旧货；不绑定吊坠等唯一纪念物 |
| T06 | 同一要约内切换货包：平板翻看不同offer set，再确认整组交换 | **尚未使用**。原版`BarterOffer.AddOfferSet/ShowSetByOffset`及食物交换有实例 | 第24章目前是对白先选工具/材料，不能在原生平板中反复切换比较。两者体验不同 |
| T07 | 代客估价：顾客带物品，玩家检视并报价，原版判断准确度、耐心和估价费 | **已使用**。阅读第19章与重复估价日常使用`APPRAISAL_SERVICE`，不是普通收购物品 | 可逐步增加适合她货源的品类，但普通工具基价估值不等于已经覆盖全部专业鉴定玩法 |
| T08 | 参数化验收、必需条件及额外条件加钱 | **尚未使用**。原版枪械订单有mandatory/bonus要求，满足额外要求会提高报酬 | 第25章样品订单很合适；我们现有“2件工具+1件材料”仅检查类别/数量，不是性能或成色验收 |
| T09 | 顾客自带实物加工/改装，玩家完成后归还并收服务费和零件费 | **尚未使用**。原版枪械服务单带来客户自己的枪，原物处理后结算 | 可考虑她带来待整理/换部件的器具，但不能把枪械专用服务直接用于净水器或普通工具 |
| T10 | 付费情报交易：买消息而非商品，消息标出即将发生的市场事件 | **尚未使用**。原版`INFORMATION_DEALER`使用服务费，成交后安排已知的未来事件及情报单 | 后期她提供一条有来源的供货消息，帮助玩家备货；少量可选经营内容，不重复收费购买救母线索 |
| T11 | 先约定、隔日交货，允许分批完成 | **已使用其交互形式，未使用旧协议**。现有可选600预算商单、独立来访、分批累计、截止和失约反馈已实现 | 不要误称我们完全没有委托单。当前用原版BUY承接，旧`PROCUREMENT_*`另见下方兼容说明 |
| T12 | 免费报酬/赠品领取、候选奖励包选择 | **部分使用**。净水器/香水选择、纪念物、P3零价样品已有；未使用`BarterOffer.isFreeReward`的原生奖励包入口 | 现有赠品正常工作，不为换入口重做一遍；未来多件打包奖励才考虑使用 |

### 价格、验货与成交后的变化

| 编号 | 原版已有形式与操作 | 当前MOD使用情况 | 适配判断 |
|---|---|---|---|
| T13 | 四向议价：卖便宜/卖贵一点，买方主动多给/要求少付 | **已使用**。原版议价按钮保留，多给她钱或少收她钱已有成交分类与部分章节反馈 | “高估她的商品、多付钱”并非尚未使用；扩展时应保留当前功能 |
| T14 | 预算、品类、种类多样性与数量限额 | **已使用**。预算40/220/350/500/600/900等，分类采购、`SetVariety`及工具/材料配额 | 这些可以组合出不同需求；不能把每个预算数值当成一种新玩法 |
| T15 | 工具检验与真假/成色辨识：照看、试纸检测、开箱及物品专属检查 | **部分使用**。原版物品自然带有检查能力，MOD保留原版物品和估价入口；没有围绕“玩家检查得出发现”设计完整的埃莉诺验货场景 | 优先补充的方向：检查她带来的旧货，发现具体问题后，价钱和对白都回应这一发现 |
| T16 | 依据发现揭穿商品、重新估价；买方发现玩家卖的货有问题并中断交涉 | **部分使用**。`CompleteClientCreation`按派系配置默认识别能力，MOD并未全局关掉；没有专门组织她的成长或关系反馈 | 应区分“原版底层可能发生”与“剧情已经表现她学会识货”。后者尚未系统设计 |
| T17 | 同次来访成交后追加相关需求，切换到下一段业务 | **尚未使用专门的连带采购**。原版交枪后可改为买配套弹药/近战武器；我们主要是成交接剧情收尾 | 适合第25～27章：“工具够了，再看看装样品的小箱子。”必须可跳过，不再强迫点下一位才结束 |
| T18 | 商品使用后的回头客、退款/赔偿、再次购买 | **部分继承，未专门设计**。原版`SoldItem`和化学品反馈有真实效果；我们有脚本引荐买家，但没有按她那笔货的实际使用情况建立一套售后链 | 第25章可少量做样品回访。正常成功也应有反馈，不把埃莉诺日常全变成追责和罚款 |
| T19 | 行情、派系、商品特性与关系影响报价 | **底层已使用，剧情化不足**。商品沿用原版价格；本地王尔德项目也已增加声望优惠，但后者是筹备付款，不是每件商品的关系定价 | 适合把一条供货消息与后续实际报价连接起来；先不新增不透明的恋爱税率或全局价格补丁 |
| T20 | 威胁/勒索式压价及其声望后果 | **原版入口保留，未设计专属剧情后果**。普通交易可出现对应按钮，当前没有为她另外编写整条胁迫交易路线 | 不列为关系推进的优先项目，也不应未经设计就把该按钮解释成双方认可的私下称呼关系 |
| T21 | 售罄、批发完成、预算耗尽后自动收束；无交易也可结束 | **已使用并已修复过**。现有结束拦截、订单满额和剧情收尾都处理这些情况 | 新玩法必须接上现有收束和读档恢复，不能重现无法下一位的阻断问题 |

这里“已使用”表示至少已有实际可达的对应交互，不表示每一章或每一种商品都覆盖；不据此计算交易种类占比。

### 可以明确列为“我们还没用过”的八种模式

1. **强制整单成交的批发包**（T03）。与现有可拆零的批发选择不同。
2. **同次来访双向买卖**（T04）。与不同日期分别BUY/SELL不同。
3. **真正以物易物**（T05）。与对白选项送物或扣钱不同。
4. **原生平板中的可切换货包**（T06）。与第24章对白中先选一批货不同。
5. **参数/质量验收加可选奖金**（T08）。与现有类别和件数配额不同。
6. **顾客自带物件的加工归还服务**（T09）。与代客估价不同。
7. **付费市场情报**（T10）。与直接在剧情里告诉玩家消息不同。
8. **成交后同场追加相关采购**（T17）。与自动播放收尾对白不同。

工具检验、真假揭穿、售后、威胁压价等没有列入这八种，因为原版默认行为可能已经在普通交易中运行，不能断言从未出现；准确说法是**尚未系统用于埃莉诺剧情设计**。

### 对当前章节最有价值的交易变化

- **前期拾荒/筹备期：一次可选以物易物。** 她拿来一小批普通旧货，希望换日用品或工具。原版交换条件负责接收与交付，玩家直接看到她的实际需求；拒绝仍能继续交谈。初期是求生需求，后期可换成双方合作的物资调配，不必让她始终处于贫困求助状态。
- **第18～19章：一起验货。** 检查一件有明确可检问题的货，埃莉诺先提出判断，玩家完成操作后指出依据；后续她能独立复用这项判断。这比只在对白里说“我学会了”更能表现成长。现有第19章估价保留，可以把可观察的细节嵌入该流程，不额外叠一个收费事件。
- **第24章：货包或双向买卖二选一。** 当次场景只选一种新形式。前者让玩家比较几包现货；后者让她带来货物，同时为自己的工作补货。无需为两个相邻场景都做复杂新入口。
- **第25章第一单：基础验收+额外品质加钱。** 必需条件应宽松、清楚，额外条件只增加本次报酬，不锁感情、项目结果或分红资格。原版现成参数系统绑定枪械；要用普通工具需另写有限的检查规则，不能只把类型设为GUNSMITH就视为支持。
- **第27章以后：一次短追单。** 正常采购完成后，她可追加与刚买商品有关的小需求，明确新预算，并可直接跳过。相比再加一位专门来买东西的顾客，更适合保持经营节奏。
- **事业稳定后：少量供货情报。** 她提供上层区真实的供需消息，玩家可据此准备库存。需和官方事件调度一致，不能收费讲一个不会发生的行情；私人关系不是必须付钱听她说话。

第一批建议只新增**一次以物易物、一个验货协作节点、一段可跳过的追加采购**。参数订单、双向买卖和服务加工放在后续独立验证；不为了收集所有模式给每章增加新规则。

### 兼容边界与本次核对发现

- 当前新版议价平板的`ResolveMode`明确支持BUY、SELL、SELLNBUY、BARTER、INFORMATION_DEALER、GUNSMITH；APPRAISAL_SERVICE走其他原版估价交互。不能因后者不在这个switch里就误称它不可用。
- 旧`PROCUREMENT_OFFER/PROCUREMENT_COLLECT`仍有示例与数据类，但当前平板没有相应模式。现有600商单已经用可靠的BUY承接，保持这一实现，不为补齐枚举重新启用旧协议。
- `WHOLESALE`枚举也不等于另一套正在使用的批发界面。可用批发由SELL/SELLNBUY上的`isOfferWholesale`等字段驱动；这部分我们已使用。
- 原版`SELLNBUY`的默认“业务结束”判断直接返回false，不能照搬SELL售罄即离开。若新增，必须为双向交易提供清楚的主动结束/收尾条件，避免玩家再次只能赶人或被困。
- 货包切换会清理未购买的旧展示货并重摆新包。需要明确已购买物件的所有权、切换后的余货和存读档回执；不能把我们当前的出货回执直接当作可无限翻包的实现。
- 原版以物易物支持指定ID、标签、排除物品状态及多项条件；它不是现成的通用“任意两边估值差额自动找零”功能。顾客双向买卖也不等于抵扣货款。
- 原版GUNSMITH除了武器购买要求，还包括客户原枪的加工服务和额外条件奖励；普通家电维修需要适配，不能从`CreateRetiredGunsmith`的名字误认成维修服务——这个退休枪匠实例实际是SELL卖货。
- 默认`CanReturn/CanReturnAsBuyer/IsPersonalConsumption`为true，当前MOD没有统一禁止；普通商品的原版后续不应写成“从未使用”。新增专属售后时应避免又生成一条内容相同的官方反馈。
- 租金、银行借款、债务与赎买等特殊付款虽然也属于游戏经济交互，但绑定店铺/债务全局规则。这里不把RENT或LOAN_SHARK当作可直接套给埃莉诺的新交易类型，更不据枚举推导原版存在通用抵押典当系统。

## 卢的开门事件能复用什么

`PlayerStore.OnLateShutterOpen`判断晨间来访，`SetupWaitingClient`令角色立即到达并创建当前顾客，`RunMorningDialogue`在约2秒后启动对白。`CreateWanted5Morning`再写入卢自己的对白和状态。

因此可复用的是**开门时机、已经在门外等候的站位、晨间对白节奏**。没有据此确认一个通用的“惊吓特效API”，也不需要让埃莉诺照抄卢的吓人语气。

`SetupWaitingClient`对`lou/sec/mob/...`有固定分支。新增埃莉诺不能仅换一个传入字符串，也不能调用`SetupWaitingClient("lou")`后篡改原版卢的标记。应创建MOD自己的晨间来访，并保留原版执法、卢与其他紧急来访的优先级。发生竞争时延后，不覆盖当前顾客。

## 最适合优先加强的六处

### A. 第12章：研究资料成为可以亲手处理的东西

保留当前坦白旧伤、协商保管人的内容。新增一份短小的研究摘要副本或交接记录，让玩家在柜台上出示/归档，埃莉诺对这个动作回应。盘由她携带时，玩家持有的只能是经她同意的副本或核验记录，不能凭空拥有第二块原盘。

真正增强的不是多读一页背景，而是让“他答应保管”与“他已经接手并妥善处理”有可见区别。摘要中只留后续要核对的人、材料或编号，约80～120个中文字即可；大段研究背景仍可选读，不要求背编号才能救母。

复用文书与柜台物品回调。**原版电脑没有因此被确认具有插USB读取研究盘的通用机制**；若设计插盘解谜，那是另做功能，不计为直接复用。

### B. 第14～15章：让玩家的核验判断落到回执上

当前这些章节已经增加了核验、争执与修正安排，但大部分仍由对白陈述。可把两件关键事实放到短回执中，例如经手人的身份、交换时先确认母亲安全的顺序。玩家提出先核对，再收到一张“已核实/待补”的记录。

正文依然按原剧情推进。具体文书可以在柜台上再次出示，后续对话引用玩家确实核实过的那一点。选择与结果记录需要我们新写，原版只提供文书显示和物件触发，并不存在拿来就能用的完整核验谜题。

这一处与前面A组成一次实际协作，最能支持第18～19章“她开始依赖他的判断”的动机。不能只给玩家一个“已读文件”按钮，紧接着就把称呼当作奖励。

### C. 第16章：救母结果改为一次开门前已经在等的来访

第15章准备已完成、原有间隔已到且甲／乙路线具备第16章结算条件时，在合适开门让她预先站在外面。可用很短的开场：“我等了一会儿。……我母亲已经接出来了。”后接现有团聚与稍后收束，不再新增一场内容相同的午后来访。

这样她来找玩家的迫切性由出现时机表达，玩家开门时就能感到事情有了结果。同时明确说“我母亲”，不留下“她救回来了”的指代问题。

这是一次重大场景，触发一次即可。母亲安全与研究盘结果仍在第16章末尾一并提交，不能将`MotherState==1`反过来设成本章开播条件。原版保释桥接处理的是埃莉诺本人被捕／获释，与MOD母亲救出结果不同；本段于2026-11-09审查晚会设计时纠正了先前将两者混称的表述。若与官方执法或卢的晨间事件冲突，保留待处理状态；需要设计普通到店的兜底，不能让开门槽位永久卡住章节。

第13章威胁也适合晨间堵门，但若只做第一批，优先选救母结果；威胁者仍按原访客来。后续要做威胁堵门时，限制为一次，避免两个相邻高潮都使用相同手法。

### D. 第18章前后：用一张留下的工作记录表现她开始认真参与

把当前对她如何清点、标记、识别旧货的一部分叙述，变成下一次开门看得见的简短便笺。可以标记一件她实际经手的普通货，不随机动玩家库存，不擅自卖掉东西。

示意语气：“那件接头松了。我放在一边了，别和好的混着卖。——埃莉诺”。这应当是已经发生的工作结果，不能在玩家没有参与这项工作时凭空生成。

后续本人来访只保留一两句对此的反应，删去原本重复汇报。这里强调工作、判断和逐渐信赖，不提前出现“主人”、女仆装或行礼；当前首次称呼/完整立绘在第19章、告白在第20章的顺序不变。

### E. 第24章：把合法返回上层区的成果交到玩家手里

P2已付款且对应结果完成后，给一份可重看的通行手续副本/收据，作为她办妥手续的实物证据。用途是让玩家明确“这笔钱办成了什么”，并在下次来访前能翻看。

它是剧情文书，不调用原版许可证授予逻辑，不额外解锁玩家的枪证、经商许可或新地图权限。新声望优惠以及旧人脉付款的差异可以体现在经手备注，不能把“不消耗声望”写成又欠了必须偿还的人情债。

### F. 第25～27章：她的事业在本人不来访时也有动静

第一批可先做一次样品箱交接和一条隔夜结果日志。箱子只装本次约定的样品/工具，不把整仓普通物品自动当成上交材料；确认交付后再消耗，空箱、未准备好可以以后再办。

第二批再选一种主动渠道：**电脑上的普通补货单**或**玩家拨打她的电话**。不同时做两个常用渠道，以免增加操作负担。

- 电脑单适合一种常规物品和明确数量，单子署名或描述点明来自她的供货关系。它应当是可选经营收入，不成为已有救母、恋爱或分红的新门槛。
- 电话适合上层区办事进度或当前合作的短问答，不适合把第27章开张报告整章搬到话筒里。电话不是“每天打一次收钱”；分红保持每天累计、来访领取。
- 新增可选补货单与现有600预算商单区分，不叠发同一任务的两笔报酬，也不再无限增加第三条等待期访客序列。
- 夜间日志可以写合作账当日新增数和待领数，但不能把它计入当日已收到现金；到账仍由来访收据的既有提交点负责。

## 第二批与暂缓项

第20章告白或第28章最终约定很适合闭店后的私人场景，但原版闭店会中断对白、隐藏前区并延时遣散当前顾客，不能只把长对白挂到`OnShutterClosedLate`。需要独立的场景占用/恢复流程，处理外出面板、睡眠、存读档，因此放第二批，先保留现有可靠情感收束。

第13章黑市施压可以加入真实举报后的后续反应；暂不增加强制拔枪、店铺破坏、爆炸倒计时或新增救母死线。这些原版机制确实存在，但会改变数值与路线规则，且与目前减轻特殊逻辑、保持官方调度兼容的方向相冲突。

不要把“母亲+埃莉诺同时站在柜台”算作零成本复用。原版确有执法人员附加角色槽位，但不是通用的任意双人对话舞台；要另外处理站位、立绘、清场和存档中断。第一批使用现有母亲单独来访即可。

远征、完整新外出地点、录音/新音乐磁带均可留作后续扩展，不应为了丰富表现先引入一个同等体量的新系统。

## 实施顺序与约束

建议第一批顺序：**短文书与便笺 → 第16章晨间结果 → 第12/14/15章实物协作 → 第24章成果文书 → 第25章的一次样品交接/夜间回执**。每项承接已有事实，尽量替换重复的报告，不单纯增加篇幅。电脑订单或电话选其一留第二批。

重要事件只触发一次；日常轻反馈建议至少间隔4～7天，不与现有每4天经营/分红来访逐项叠加。普通交易仍是游戏骨架，不把每一天都改成等待剧情演出。

共用实现要求：

1. 新事件使用独立ID、阶段和提交标志。旧存档不补演第一次，不重置救母/称呼/付款/分红。
2. 官方晨间事件、执法与当前对话优先。没有空闲状态时保留待处理，不强制覆盖当前顾客。
3. 实物在放置成功后才登记交付；前柜台满、物件丢失或读档中断时有重试/副本渠道。显示回执不等于重新发放原奖励。
4. 为物品触发补充回调时组合现有行为，不覆盖`AddTrapWatcher`装在埃莉诺身上的柜台回调。只有目标角色、目标物件和正确章节才响应，防止反复放下拿起刷对白/收益。
5. 纸条、地点和电脑是表达与可选互动，不把已可靠的剧情改成玩家必须猜到隐藏操作才继续；明确告诉玩家下一步，并给不去外出地点、未解锁市场或不打电话的存档留原有推进路径。
6. 当前四个王尔德项目的可见门槛、单一现金/声望优惠、每日分红累计和来访领取规则不因表现方式改变。
