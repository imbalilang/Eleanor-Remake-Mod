日期：2026-11-06。范围：EleanorRomanceDev、当前安装包、原版 0.46D 程序与简中资源、工坊 MOD 3832595288（本地 1.0.6）。

本文是本轮检查形成的调整建议，不表示建议已写入游戏。优先级以用户本轮七项约束及补充意见为准，旧交接文档中的“已锁定”方案不视为不能修改。

## 二、原作依据与可调整边界

直接核对了原版打 `StoreClientUniqueList`、`StoreClientManager`，并读取游戏简中 Dialogue 表，而非只采信旧文档。

### 2.1 应当保留的角色基础

- 初遇时她有真实的阶级偏见和优越感。原句：“呵，你们下层区管这种地方叫‘商店’啊？”不能开场就成为懂事温柔、立即爱慕玩家的人。
- 她的母亲经营大型水培农场，被指控挪用公款。她最初想恢复旧生活，后来承认下层区的社区精神。
- 她会主动拾荒、出售物品、攒钱请侦探，不只是等待玩家搭救。原句：“给个公道价，好吗？每一个信用点都能让我离目标更近一步。”
- 她会感谢、回礼和作出自己的决定。保留这些能使恋爱成为双向关系。
- 数据盘的核心价值是让普通营养果重新结籽，从而破对帕斯泰尔种子的依赖；不是单纯的财务账本。

### 2.2 应纠正的事实误读

| 现有稿件或实现 | 原作证据 | 调整方式 |
|---|---|---|
| 多处称“舅舅”，容易写成真实亲戚 | 自称叔叔；Eleanor 明说“我根本没有叔叔” | 统一“假叔叔/冒充叔叔的男人”，除非明确标注这是有铺垫的新改编 |
| 箱内定位器、伪造清单作为既定真相 | 原机制是报失窃的 `luxury_supply_crate`，借转移持有栽赃；举报对方可揭穿谎报盗窃 | 恢复赃物与所有权机制。定位器不是行为化的必要前提，建议删除 |
| 笔记写“产量养活三倍人口”，盘是原始账本 | 原版是恢复结籽能力的基因研究 | 改写笔记，以研究为主；附加栽赃证据可以扩展，但不能替换研究核心 |
| 她亲自进实验室，门锁是母亲生日 | 原版侦探找到盘，数据盘密码是 Eleanor 生日 | 可改编取证方式，但要明确谁取得、谁解密，保留母女联系的细节 |
| “回归线”母亲被流放后回不来 | 原版流放到下层区，母女一起拾荒 | 母女下层区团聚可直接作为温暖成功线，无须强制回上层区 |
| 帕斯特/帕斯泰尔、舅舅/叔叔混用 | 当前原版简中使用“帕斯泰尔”“叔叔” | 建术语表，正文、笔记、英文同步 |

原版 `dialog_eleanor3_no_family` 的“我已经没有家人了”与母亲仍在世存在上下文歧义，不应据此新造亲属死亡事实。以整条剧情的一致性判断。

### 2.3 可以主动改编的内容

允许新增“保护研究、救出母亲、母女留在下层区”的较优结果；允许母亲对关系给予认可；允许她以后获得返回上层区的机会。前提是玩家前期行为积累出相应条件，Eleanor 参与计划，有明确的时间顺序与代价。

“阶级反差恋爱”不要求她恢复财富才能成立。她见识、生活习惯与身份背景仍保留，恢复自由后仍主动选择当铺老板，已经能兑现目标。公司地方代表被调查也不等于整家公司一夜倒台。

## 三、需要优先处理的具体问题

以下分为代码可直接确认的问题与仍待实机复现的风险。

### P0：剧情和状态正确性

1. **陷阱已经脱离物品行为。** `EleanorStory.cs:670` 起用菜单设置 UncleChoice，第 5 章在第 751 行以 `UncleChoice == 2` 判逮捕。没有原版放柜台、所有权、举报成功的完整因果。需要重新连接物品实例和事件。
2. **新闻不分结局。** 第 1278 行建立倒台新闻，第 1281 行接到共同结束节点，返还、泄露、卖盘和放弃等均共享；第 1305 行附近的多方行动摘要还在选择前播放。必须按已完成结果生成，不能预报尚未做出的行动。
3. **数据盘的拒绝与持有不一致。** 第 1100 行构造客户时便设 HasDrive=true；拒绝只设 RefusedFlag。最终资格检查只排除 DriveLost 等，不验证实际保管/证据状态。修复后“拒绝代保管”应表示盘由她持有，不能让玩家出售不存在于自己手里的盘；拒绝代保管也不必自动等于感情失败。
4. **访客过早记为完成。** `StoryDirector.cs:182` 入队就递增 VisitorIndex。关店、队列被清、读档等是否会丢访客需实测；应改为 pending/arrived/completed，完成后提交。
5. **新开局日程错位。** 主章节有第 5 天起的提前表，访客仍固定 26/32/36/41/44 天。于是退婚施压可能发生在提前版尾声之后。访客应绑定剧情状态和相对间隔，而非另一套绝对日表。
6. **重置清理范围不完整。** RomanceState 的清理匹配 `eleanor*`，MOD 客户 ID 是 `er_story_*`，旧 MOD 队列可能留下。需区分原版记录与本 MOD 所有事件，且不影响其他 MOD。
7. **发物失败仍记已发。** `Items.cs:51–52、67–68` 在 GiveItem 内部失败后仍置 Given=true。改为成功返回后提交；同样审计 Spend 失败但继续给剧情结果的问题。
8. **行为与章完成时点不一致。** 第 1、2 章讲完菜单即推进，交易可能随后发生；第 6 章有结束对话及 OnDismiss 等多个完成入口。需要统一事件生命周期、幂等处理，并实测离店、拒绝、存读档。

### P1：体验和内容一致性

- 吊坠 `unitValue=450`，剧情把支付 100 称市场价、300 称高价；未来按成交价判定时会互相冲突。正常收购价不等于零售价，须使用游戏实际收购体系和状态修正作为基准。
- 伪造芯片是在选项成功后发到玩家背包，尚不是玩家拿出并交给威胁者的解法。首版建议删去这个独立道具与路线，降低物品状态复杂度。
- 第 11 章“三个月后”在第 43 天播放，之后还继续原周目，时间不一致。改成“几天后”且按实际相对日安排；多年以后只放最终游戏结局回顾。
- 当前任一派系高声望即可播放所有势力同时帮助的叙述，贡献没有对应。应只展示玩家真正调用成功的渠道。
- README 提到革命声望门控，最终代码只查黑市、上层区、安保、下层区。决定是否支持革命路线后统一，不宣称“任意派系”。
- 以 800/2500 信用点和好感阈值统一买到最佳结果，容易把恋爱写成付费回报。资金可改变风险和速度，不能代替信任与她的决定。
- 部分文本在单人柜台访客中让 Eleanor 同时发言，需要明确“她此时在场”的呈现方式。不能靠更换说话人名字冒充已有双人场景。
- 随机生成的维克多第二次立绘可能与第一次不同。命名常驻角色必须固定原版 sprite key 并存档，不依赖每次随机。
- 周常目前仅少量台词反复给钱和声望；需要有不重复的关系内容，控制奖励，避免通关后变成固定提款。

### P2：技术边界和发布准备

- VersionGate 实际接受所有以 0.46 开头的版本，空版本也放行；不等于只支持 0.46D。采用已验证版本列表，或明确说明宽松兼容的范围和失败行为。
- 中途停用、版本升级、同改 Eleanor 调度的 MOD、载入已有世界变化的旧档，均须测试。重置关系状态不应声称能回滚已经解锁的种子或播过的新闻。
- 现有 bash 构建直接写安装目录，资源复制部分忽略失败。后续使用 staging 目录，验证资源清单后再部署，保留可回滚安装包。

## 四、调整后的内容定位

核心承诺：玩家凭自己已经会做的经营与风险判断，成为 Eleanor 信任的人；她从轻视下层区到看见玩家的能力，再主动维护、帮助和选择玩家。母亲可以获救并在下层区与女儿团聚，恋爱结局不要求社会地位恢复。

建议保留从第 23 天介入的方案，但减少对原版机制的重做：复用买食品、买日用品、出售家当、免费食物援助、假叔叔举报、拾荒攒款、数据盘决策及原版世界效果。在这些事件前后扩写关系，不把所有原生事件改成新菜单。

不继续沿用“每章检查一档声望并付钱”的统一格式。声望用于合理的差异解法，店主的基本能力首先来自识货、交易、留证、承担风险和守约。原版结局保留为可达路径；新增较优结果建立在更充分准备上。

建议的六个关系阶段：

1. **看不起环境，但记住这个老板。** 留住尖刻、挑剔和自尊，玩家可以有边界。
2. **发现他会做事。** 从识破陷阱、公平收货、留住急需物资体现能力，少用自报靠山。
3. **不只是接受帮助。** 她学习识货、攒款、为店里带回需要的材料；帮助有来有往。
4. **主动保护这段关系。** 面对上层区旧关系，她先表明自己的立场，玩家不必总替她说话。
5. **共同承担有真实风险的决定。** 她提供密码、研究理解和行动意愿，玩家提供经营网络与证据保全。
6. **有退路以后仍选择你。** 母亲安全、去留恢复自由后，由她明确表达心意，后续通过日常经营兑现。

爽点分布至少包括：识破对手、她承认玩家专业、她主动回礼、她当面维护玩家、双方共同救母、恢复选择权后仍来当铺。不能把爽点全部压到终章的一句告白。

## 五、行为设计：按实际事件结算

行为占比以“改变剧情状态的关键决定”为口径，建议至少 70% 来自交易、物品和既有处置；不按鼠标点击数量计数。显式选项保留在警告、风险同意、恋爱确认、最终去向等需要表达意愿的地方。

| 节点 | 玩家实际行动 | 判定依据与后果 | 未做到的处理 |
|---|---|---|---|
| 初遇食品/日用品 | 正常挑货、报价、成交 | 实际商品、数量、成交金额与有效价格基准；她记住公平或趁火打劫 | 没有库存不等于恶意；合理拒绝不永久锁线 |
| 出售家当 | 正常收购；保留或转售纪念物 | 记录成交和物品去向；在后续对话兑现记忆 | 一次正常交易不要求让利才能恋爱 |
| 假叔叔箱子 | 接货、检查原有信息、举报、保留、转售；对她来访时放柜台 | 基于原版箱子实例、持有权、当前访客和捕获结果；成功举报才计破局 | 先判断可疑但未举报不自动加安保声望；留仓库不等于已交给她 |
| 警告她 | 原版语境下的明确提醒 | 需要知道假叔叔/赃物信息；警告后撤销相关陷阱状态 | 不能要求玩家盲猜未提示的隐藏开关 |
| 困境援助 | 原有零预算食品交易/赠予 | 物品真正转移才算帮助，不使用“点给食物却只扣钱”的替代 | 可以延后帮助；贫穷不是品德失败 |
| 拾荒调查款 | 多次按正常机制买她的货 | 参考原版 onItemSold 的实际 paid 累计到 800；金额、速度、是否压价影响回应 | 玩家少买时她继续自行攒款并延后，不凭空停掉所有进展 |
| 安保救援 | 复用可用的原生支付或交涉载体 | 逮捕状态→救援渠道→实际代价→释放确认 | 如果原版没有可用保释接口，允许一个上下文交涉选项，不能伪装成已存在的电话系统 |
| 证据保管 | 在熟悉的物品交付入口接收/移交；她保管也有对应状态 | 唯一证据状态、可用研究、保管人、是否已交付 | 若要把原版叙事数据盘实体化，先验证原生支持；不强加新 UI |
| 威胁处置 | 原生举报/捕获等可验证行为，或交付证据 | 成功结果才更新；根据保管人检查能否交盘 | 原版威胁者不可直接逮捕/射击；需要先验证改旗标后的完整流程，不能直接承诺所有武力选项 |
| 救母破局 | 前期保全研究、准备一个可信保护渠道、支付实际需要的成本 | 先确认母亲转移/安全，再泄露研究；每项准备都能回溯到玩家行为 | 证据不足可选择原版归还保命或延后准备，提前说明风险 |
| 感情与未来 | 明确双方同意，再用已存在的物品回赠/正常业务表达关系 | 感情确认与职业去向分别记录 | 不让一个无说明的“放吊坠”操作替代同意，也不因售出吊坠无补救地卡结局 |

价格判定应采用本次交易可获得的、与质量/状态相符的原生价值参考。初始可试用正常价区间、明显压价区间等内部规则，但比例必须根据游戏交易数据校准；不得拿 item.unitValue 直接当回收价，也不要求玩家记隐藏百分比。

每次相同交易只结算一次；拒绝/取消/失败不扣已承诺之外的款；赠予必须确实接受才生效。价格好感每次拜访设上限，防止拆分同一批货刷好感。对白自然反馈行为，不持续弹出“好感+2”。

## 六、剧情包与单周目体量预算

计数定义：一次完整路线中首次实际出现的角色对白和有内容的叙事句。选项标题、需求说明、名字、操作教程不计；互斥分支只计选中的一条；完全重复的周常不计；不通过把一句话拆成多个气泡凑量。可选纸书另计，不承担必经剧情的最低字句预算。

参考 MOD 本地中文文件实测 1,339 个有效唯一键，章节前缀 R01～R18。其入口以原版 Lou 成功后支线为定位，并含队列、回家、日常和存档处理。350～500+ 单周目是本项目采用的体验目标，本次没有跑完 Lou 的所有路线，不能把总键数转换成已经实测的单周目句数。

下表是**待写作的 420 句完整成功路线预算**，不是对当前文件的统计。每个包拆成 1～3 个短场景；同日补充对白尽量附着原有交易，不额外堆强制访客。

| 剧情包 | 关系/故事功能 | 主要载体 | 首次有效句预算 |
|---|---|---|---:|
| 1. 第一位挑剔常客 | 阶级反差、店主有边界 | 第 23 天食品交易及成交反应 | 28 |

## 七、结局结构与数值调整

把“母亲命运”“研究去向”“关系状态”“Eleanor 的工作去向”分开存储，避免一个 true_ending 布尔值承担所有含义。

| 路线 | 故事结果 | 恋爱处理 |
|---|---|---|
| 归还保命 | 参考原版谈判：母亲安全来到下层区，研究被交回 | 可发展成完整团聚恋爱结局；不因不是新最佳线就缺少感情内容 |
| 充分准备的救援 | 玩家帮助保全研究、落实保护/转移，再处理公开；母女在下层区团聚 | 推荐的新增成功线；双方共同赢得更好的结果 |
| 冒险公开 | 未完成保护就公开，保留母亲遇害及她加入革命的可能 | 先有风险提示；离别、牵挂或保持关系按已有信任写，不强制每周送钱 |
| 朋友/不恋爱 | 玩家可以救人而不谈恋爱 | 有完整感谢与后续交易，尊重玩家退出 |
| 出卖或放弃关系 | 有充分提示的出卖/利用可关闭浪漫线 | 短而完整的收束，不播放成功新闻 |

原作归还路线与新增救援路线都允许母女团聚。新增路线的额外价值在于研究得以保存、母亲保护更可靠、双方有共同承担的经历，不是把原版可达的团聚误写成新奇迹。

恋爱资格建议由若干关键事实组成：至少数次稳定的公平往来、一次实际风险协作、没有明确利用/背叛，以及双方明确意愿。内部好感可保留，但不把“12 分 + 2500 钱”当唯一依据。

20/40/60 声望只作为待平衡参数。先查正常周目在目标天数的可达性，再决定渠道门槛；任一合理渠道应能完成对应任务，但黑市不自动掌握安保和法官。高声望降低成本/风险或提供不同过程，不解锁全势力同时服从的全能叙事。革命渠道若没有完整因果和实现，首版不承诺。

她已攒 320、调查费 800 时，应写明差额 480，或说明为什么玩家支付整笔 800；不要让账目和求助文本冲突。恋爱常驻回礼优先使用有限的小物品/实际业务，金钱和声望奖励需一次性或有明确上限。

## 八、NPC、物品、美术和承载层预算

### NPC

- 核心只围绕 Eleanor、母亲、原版假叔叔/威胁者。原版两名施压角色同用 `maleBM5`，威胁者以“还记得我吗”开场，可利用这种延续，避免再造同职责反派。
- 维克多、莉迪亚、哈维的功能合并，首版最多保留 **1 位新增命名配角**。可以是上层区旧识或代办人，在两次来访中完成轻视、她表态和态度变化。
- 退婚、未婚夫塞拉斯不是此次核到的 Eleanor 原版线必需元素。建议首版删去其核心地位，以旧圈子的切割替代；若保留，应当作为新创设定单独铺垫，不能声称原作既有人设。
- 母亲是既有故事人物扩展出演，不算新造人物，但固定立绘与发言量仍计资源预算。没有合适原版立绘时先用可信的转述/便条，不将随机通用人像当成永久母亲形象。
- 档案员属于技术兼容提示，不参与恋爱剧情。优先改用已有 MOD 配置/原生提示载体；若暂时保留，一次性且不计剧情体量。
- 采购客继续使用普通上层区交易客户，无须新命名和新人物线。

### 物品

- 必复用：原版食品、日用品、拾荒货、陷阱箱及相关赃物行为。
- 新物品以 **2 种为首版上限建议**：一件纪念物，以及确需物理交付时的数据盘。先确认原版是否已有适用盘实体；能复用就不新增。
- 现有吊坠可以保留，但不作为不可替代的结局钥匙。研究笔记可并入数据盘内容或现有纸书载体，避免再增加一个必需库存道具。若保留笔记为独立物品，优先放弃新增实体盘或吊坠之一，不能悄悄突破预算。
- 伪造芯片首版移出正式流程；以后只有在真实检视、交换、消耗与后果均成立时再加入。

### 美术与 UI

- 首版新增角色立绘 0、新背景 0、物品图标 0～2；复用原版 Eleanor 状态立绘和已有纸书/新闻样式。
- 本次查看了吊坠小图，尚未完成与原版同类物品的并排画面验收，不能认定严格同风格。正式验收比较游戏内缩放下的尺寸、描边、色板、光向、透明边缘和物品轮廓；脱离游戏的大图相似不够。
- 自定义通讯中心、案卷 UI、新联系人系统、后间地图均移出首版。现有通讯前缀可暂作叙述，但必须说明是谁给玩家看到的，不能展示无来源的私人聊天。
- afterhours 后间仅在原生载体验证且确实改善体验后做可选更新。参考 Lou 的规模与节奏，不把它的所有系统作为本 MOD 必需功能。
- “留灯”“椅子”等细节可以作为明确的对白或简短叙述；不能将没有画面/站位支撑的双人动作写成已实现演出。空间站天气等描述需核对设定，谨慎使用“雨夜”等地面恋爱模板。

## 九、实现结构与存档计划

保留现有工程，按职责逐步拆分，不先做与目标无关的重构。

1. `StoryDirector`：只负责可达条件、队列、相对时间和事件优先级。事件有稳定 ID、前置、最早日、待执行/进行中/完成/跳过状态；入队不结算完成。
2. `RomanceState`：新增 schemaVersion，记录关系事实、母亲状态、研究状态和物品去向。对旧存档映射有依据的事实；不能把旧菜单点过“检查”直接迁移成已成功举报。
3. 行为适配层：监听实际交易、onItemSold、onItemAddedToCounters、onReportAction/onCaptureAction、离店等已确认接口。额外接口先核实，避免先设计不存在的报警/联系人功能。
4. 剧情段落：一个节点只决定说什么与接哪个结果，扣款/发物/解除威胁等统一走可返回成功与否的提交操作。失败时保持可恢复状态。
5. 世界结果适配：研究公开成功后仅一次解除种子限制和排新闻；归还线不误触；追加结局文本遵守原本游戏结局发生的事实。
6. 内容源：逐节点定义 speaker、条件、分支、行为回调与本地化 key，产出路线清单。旧生成器不得继续覆盖新版文本。移除废键前检查动态引用。

旧档默认继续原版，已开始 MOD 的存档按 schema 迁移。重置仅在用户明确选择时执行，并说明不会回滚已发生的全局世界效果；清理本 MOD 队列和状态时保护其他人物线。自动备份放在迁移/测试流程中，验证成功后再使用副本进入游戏。

“旧日回响”新开局移至最后验收，可先作为未发布实验功能。若保留，所有访客与场景统一按故事相对时间，取消初始 +20 直接跳过信任成长的做法，另写符合早期资源水平的条件。

## 十二、最终发布标准

- 至少一条普通成功恋爱路线实测达到 350～500+ 有效句，建议首条以约 420 句为目标；完整替代路线分别统计，早退路线明确排除。
- 七成以上关键状态变化由真实游戏行为触发；感情同意与高风险决定有明确表达机会。
- 母亲可获救并与 Eleanor 在下层区团聚；不要求玩家一定恢复上层区身份或扳倒全公司。
- Eleanor 保留傲气、判断力和行动力；至少两次主动回馈、一次主动维护玩家、一次恢复选择权后的自主选择。
- 正式版新增命名配角建议不超过 1，新增物品建议不超过 2；超出须有明确无法复用的内容理由。
- 新档、旧档、跨日、存读档及全部结局无阻塞错误；未验证部分明确列出，不用“构建成功”替代体验验收。
- README、攻略、台本、生成器和实际代码一致。旧稿归档并注明不代表当前可玩内容。

当前推荐的下一个具体动作：先落实阶段 A/B，并制作“原生箱子与举报→她的回应→母亲救援准备”的行为样板。这个样板通过后，再投入完整 420 句路线的扩写。
