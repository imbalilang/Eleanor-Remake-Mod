## 6. 阶段三：文本 AI 味专项治理

这是当前最重要的内容工作。目标不是让句子“更华丽”，而是让玩家感觉角色在当下说话、做事和应对，而不是作者在总结剧情或模型在解释人物。

### A0 先建立问题样本，不直接批量改写

从共同线、恋爱线、后宫线、侍从线和革命军线各抽取高可见场景，优先包括：入口、告白、争执、交易后回应、结局前一场和结局页。每条反馈登记：

- 具体版本、场景和语言；
- 原文行号或 block；
- 玩家认为“像 AI”的原句；
- 问题类型；
- 是否影响事实、角色声音、节奏或沉浸感；
- 修订后的对照句；
- 是否需要实机复核。

第一批样本至少覆盖 30 个中文 block 和 15 个英文 block。没有具体原句的“AI 味”只能记为待定位反馈，不能据此整段重写。

### A1 使用固定问题分类

每条候选只允许登记一个主问题，必要时追加一个次问题：

| 类型 | 识别信号 | 处理方法 |
|---|---|---|
| 总结腔 | “这让她明白……”“关系从此……”等直接总结变化 | 改成当场对白、动作或交易选择 |
| 解释腔 | 角色把自己的动机、阶段和主题讲完整 | 删除解释，保留角色此刻真正会说的一句 |
| 角色同声 | 埃莉诺、莉迪亚、索菲娅都用相同的稳重短句和结论句 | 按角色卡重写句长、回避方式、称呼和反应顺序 |
| 模板重复 | “你不用……”“我知道……”“这不是……而是……”跨场景反复出现 | 保留事实，换成不同的具体动作或物件反应 |
| 旁白过载 | 旁白替角色解释心理、关系或世界规则 | 优先改为角色可见的动作、对白、通告或交易结果 |
| 选择换皮 | 多个选项只改变同一句回应的语气 | 保证至少一个选项改变信息、态度或当场行动 |
| 系统词入戏 | “资格、门槛、奖励、路线、完成、阶段”等出现在角色嘴里 | 替换为角色会使用的生活语言 |
| 翻译 AI 味 | 英文逐字对应中文、长句堆从句、人物语气不分 | 英文按角色声音重新写，不做逐词翻译 |

### A2 先做 1:1 候选，再做结构修订

第一轮仍然优先 1:1 voice pass：保持 block、行数、speaker、选项 ID、事实、交易声明和状态条件不变。但候选正文必须由 NovelWorkFlow 主笔或 Super QA 重写者产生，Agent 不直接改写 Content 正文。

每个场景的修订流程：

1. Agent 读取当前场景前后各一场，列出角色此阶段的欲望、不能说的话和正在处理的具体物件。
2. Agent 标记所有总结句、抽象关系词、重复句式、同义反复和不可能由角色知道的信息，写入 Rewrite Brief。
3. NovelWorkFlow 使用正式三文件输入链生成主笔候选；需要已有文本的最小修订时，使用 Super QA 的 `minimal` 或 `voice-pass`，不使用 Agent 自写替代稿。
4. Agent 对 A/B/C 候选做事实、角色声音、节奏和格式对照；只做标签正规化、证据明确的机械修复和 patch 应用。
5. 中文候选和英文候选分别冷读，回看事实、角色语域和选项语义。
6. 用 `tools/super_qa/check_text_contract.py` 检查，记录 source hash、Brief、模型参数、patch manifest 和遗留问题。

### A3 第二轮只处理真正需要的结构问题

只有 NovelWorkFlow/Super QA 的 1:1 候选仍然出现“像旁白摘要”或“角色没有在当下行动”时，才提交结构修订。结构修订必须说明：

- 删除或合并哪一行；
- 为什么 1:1 修订不足；
- 对选择、交易、状态和旧档的影响；
- 中英文行号如何对应；
- 回退方式和实机测试用例。

没有 line map、key remap 和回退点的 merge/split 不进入生产。

### A4 采用盲读作为主要质量门槛

每个小批次至少准备 A/B 两份阅读稿：当前版和修订版，不标明哪份是新版。盲读者只回答以下问题：

1. 能否分辨埃莉诺、莉迪亚和索菲娅是谁在说话？
2. 是否能看出角色此刻想要什么，而不是听到作者总结？
3. 玩家选择是否像玩家在说话，而不是系统按钮？
4. 是否有一句读起来像“模型解释剧情”的句子？
5. 是否愿意继续读下一场？

若修订版只减少字数、没有提高角色可辨识度和继续阅读意愿，则回退，不把“更短”当成成功。

### A5 首批处理顺序

按玩家可见度和反馈价值排序：

1. 共同线 c01–c05：建立埃莉诺原作声音，避免入口就出现模板化总结。
2. `love_a2_01`、`love_a2_02`：验证索菲娅、埃莉诺和玩家的声音差异。
3. `dv08`–`dv13`：验证告白、欲望、道歉和三方确认的即时反应。
4. 侍从线公开演出与私下尾声：验证身份反差，不让角色都说成同一个稳重叙述者。
5. 革命军线归来段：保留疲惫、战术和责任者语气，去掉抽象英雄总结。
6. 结局前后文本和英文高可见段落。

每轮最多处理 5 个场景；通过后再扩大到下一批。首轮不处理旧档专用资源，除非修订会影响新旧共享 block。

本专项的生产命令只允许使用现有入口：

```powershell
# 先生成 Brief/候选；不要直接写 Content
python tools/super_qa/run_chapter.py --chapter c19 --source Content/story_v06.json --dry-run

# 使用测试输出中的候选做格式正规化和合同检查
python tools/super_qa/normalize_candidate.py `
  --script tools/NovelWorkFlow_Eleanor_Test/Test_Output/<candidate>.txt `
  --out tools/NovelWorkFlow_Eleanor_Test/Test_Output/<candidate>_normalized.txt `
  --source Content/story_v06.json --chapter c19
python tools/super_qa/check_text_contract.py `
  --script tools/NovelWorkFlow_Eleanor_Test/Test_Output/<candidate>_normalized.txt
```

如果是 NovelWorkFlow 的正式主笔试点，输入只能是 `writer_prompt_template.md`、`writer_system_prompt.md` 和选定的 `world_book*.json`；不要把 `tools/NovelWorkFlow_Eleanor_Test/` 中的实验模板当成生产入口。候选先留在测试输出目录，只有经过 A/B/C 记录和 patch manifest 才能申请接入。

### A6 AI 味专项的完成标准

一个场景只有同时满足以下条件，才能标为完成：

- 1:1 或经批准的结构修订通过；
- P0/P1 文本合同问题为零；
- 没有新增抽象关系总结、系统词入戏或未在场知识；
- 角色声音在盲读中可区分；
- 至少一处玩家选择承担了真实态度或行动；
- 中文、英文和阅读稿一致；
- 需要实机的气泡长度、表情和选项回显已验证或明确登记阻塞。

## 7. 阶段四：第一轮情感体验批次

这一阶段只有在 S0 的 P0 用例通过、S1-01 完成或明确回退，并且 AI 味专项至少完成首批样本后开始。每次只选择一条路线、1–2 个场景，保持 1:1 行数、现有选择结构和存档兼容。

### C1 恋爱线优先批次

**目标：** 让玩家在确认关系后更常亲口表达照顾、欲望、边界和主动选择。  
**首批范围：** `love_a2_01`、`love_a2_02` 或 `love_a3_02` 中选择两个，不同时改三幕。  
**具体要求：**

- 保留停水事件的现实压力和索菲娅的主动性。
- 增加 2–3 个短玩家回应，每个回应只改变即时反应，不新增好感门槛。
- 保留埃莉诺的工作、判断和嘴硬，不把她写成被动奖励。
- 亲密表达符合售卖亭窗口站位；不新增室内演出。
- 中文定稿后同步英文，英文按角色声音重写，不逐字硬译。

**完成证据：** 场景 brief、1:1 patch manifest、Super QA linter、中文/英文 diff、构建和路线检查日志、一次实机记录。

### C2 后宫线后续批次

在 C1 通过后，选择 `dv09`–`dv13` 中一个节点，重点加强莉迪亚“主动想要玩家”和三人当面沟通的即时反应。不得增加声望门槛、秘密关系状态或新的结局。

### C3 侍从线与革命军线

只在 C1/C2 通过后安排：

- 侍从线：强化公开身份与窗口私下称呼的反差。
- 革命军线：强化她完成任务后回到玩家处的回报感。

两条路线各只做一个场景试点；若试点不能在现有机制内自然表达，退回文本调整，不申请新机制。

## 8. 阶段五：英文与重复表达定点审校

每个段落只做事实、角色声音、重复口癖和英文自然度修订。不得把局部审校扩大成全量重写。使用 `tools/super_qa/check_text_contract.py` 和已有 registry 记录每一项变更。

## 9. 每个批次的固定验收闸门

任何正文或代码批次都必须按以下顺序完成：

1. 记录修改前 source hash 和目标场景。
2. 修改 `Content/*.json` 或对应代码源。
3. 运行 `python tools/build_content.py`。
4. 运行 `python tools/check_project.py`。
5. 运行 `python tools/check_route_map.py`；若路线、结局、目标日未变，也要记录“无路线变化”。
6. 使用内置 SDK Release 编译。
7. 运行 Super QA 或对应离线回归。
8. 阅读中文、英文和实际选项分支。
9. 完成必要的实机用例。
10. 保存 diff、日志、哈希、截图和回退点。

任何一步失败，批次状态只能是 `blocked` 或 `needs-fix`，不能标为 `done`、`shipped` 或“已验证”。

## 11. 暂停、回退和升级规则

### 立即暂停并回退

- 旧档路线被改变、结局重复触发或出现不可逆扣款。
- 交易物品、现金、奖励或排期出现重复结算。
- 立绘模式影响其他 MOD 的客户或导致表情闪烁。
- 新增文本引入未批准机制、未在场角色知识或错误空间关系。

### 可以继续但必须登记

- 英文个别句子需要母语审校，但中文和逻辑已稳定。
- 候选美术尚未完成实机抽检。
- 已知的源文连续 NPC 行仍存在，但没有被本批次新增。

### 需要作者决定

- 是否接受超出当前窗口机制的演出需求。
- 是否批准新的美术生成、外部 API 调用或明显增加素材成本。
- 任何改变路线、结局、目标日、关系条件或尺度上限的方案。
