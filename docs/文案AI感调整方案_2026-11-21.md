## 总原则

1. **先修结构和事故，不先润色句子。**
2. **不改剧情事实、选择、交易、空间、时间线、结局。**
3. **不做全量重写；只做可定位的局部修复和批量清洗。**
4. **不要求玩家逐句标注，不逐章人工投入。**
5. **任何批量修改先生成候选/diff，不直接改 Content。**
6. **社区 Lou 只作对照，不复制其文本。**

## 阶段 0：只读审计（不改 Content）

### 0.1 选项汇合审计

- 从 `src/MaidV2Story.cs`、`src/RevolutionV2Story.cs`、`src/LoveStory.cs`、`src/DualStory.cs` 提取：
  - 每个 choice 的主线/非主线选项；
  - 非主线 block 的最后 1–3 行；
  - 接回 continuation 的前 1–3 行；
  - 同一说话人、同一场景的重复分句。
- 输出：`dist/ai_feel_audit/choice_joins.json/md`。
- 重点验证报告 1 的侍从线告白汇合，以及其他路线是否有同类。

### 0.2 行内动作与裸舞台指令审计

- 从 `Content/*.json` 原始文本统计：
  - 每路线 `<i>...</i>` 行内动作数/占比；
  - 无标签但明显是舞台动作的台词（“走到窗口前……”“坐下去……”等）；
  - 游戏内实际渲染样式：斜体还是圆括号。
- 输出：`dist/ai_feel_audit/inline_actions.csv/md`。
- 分类：
  - A 类：纯微动作/无信息 → 可删或迁移到独立旁白/表情；
  - B 类：承载道具交接/关系信息 → 保留为独立动作行，或改写成台词；
  - C 类：裸舞台指令 → P0 修复。

### 0.3 语域漂移审计

- 建黑名单：`今儿/明儿/昨儿/娘俩/掰扯/摆活/营生/铺子/衣裳/余下/余后/便/成。` 等。
- 逐行判断：是角色声音，还是 voice-pass 副作用。
- 输出命中行与建议还原值。

### 0.4 规则复读与公式审计

- 统计“账/价签/不欠/别替我做主/按天记/分开记”等声明句，按路线/场景列密度。
- 统计“玩家嗯/行/成/去 → NPC 嫌字少”公式出现次数。
- 统计同一笑点/同一问答模板跨场景重复。
- 输出：`dist/ai_feel_audit/rule_recitation.csv`、`formula_repetition.csv`。

## 阶段 1：试点清洗（只出候选，不动 Content）

试点范围：

- 侍从线告白汇合（报告 1 的最小干预）；
- 默认 4 章：`love_a1_01`、`love_a3_04`、`dv01`、`dv06`；
- 6 处裸舞台指令；
- 选项提示提纲化（只列候选）。

### 1.1 侍从线告白汇合

- 不重写中文正文；
- 调整分支 block 的接回位置：让“说我也是”分支不再接回“嫌他说得少”的共享开头；
- 保留主线“两样都给”的追问；
- 检查三条选择路径的关系旗标、称呼、后续唱歌剧情、状态一致。

### 1.2 裸舞台指令修复

- 将 6 处无标签动作改成独立动作行/旁白，或并入可说的台词；
- 不改变剧情事实。

### 1.3 行内微动作清洗（分类）

- A 类：删除或移出气泡；
- B 类：保留必要信息，改为独立动作行；
- 不做“一刀切剥离 80%”；避免把道具交接、关系动作删没。

### 1.4 语域还原

- 对 89 行命中黑名单的台词，用低温单行修复：
  “仅把方言/旧白话/生造词还原为现代标准口语，允许保留原句正常词汇与语序”；
- 逐条检查是否破坏角色声线。

### 1.5 变体块同步

- `love_a3_02`（2 变体）、`love_a3_04`（4 变体）以顺句后的主块为母本，同步共同行；
- 只保留真实分支差异（研究交回/公开、是否请邻居等）。

### 1.6 规则复读与公式

- 侍从线 8 处账目复读：保留 1–2 处有戏剧作用的，其余替换为当章具体货品/动作；
- 恋爱线三场“数他字数”：至少删/换一处，打破公式，不改变关系节拍。

### 1.7 试点验收

- 裸舞台指令：0；
- 行内动作率：试点章节降至 ≤2%（或经作者确认的风格上限）；
- 方言/旧白话/生造词命中：0（或仅保留有意的角色声音）；
- 规则复读：试点章节降至 1–2 处，且落在具体场景；
- 选项汇合处不再出现“刚确认又重开”；
- 合同/canon/选择/交易/空间/时间线全部通过；
- 输出 `Clean-Batch-01` + 前后统计 + diff，不写 Content。

## 阶段 2：全路线分批

试点通过后，按路线分批：

1. 侍从线 v2（含告白汇合、账目复读）；
2. 后宫线 v2（括号动作最多）；
3. 革命军线 v2（汇合审计）；
4. 恋爱线（变体块、三场公式）；
5. 共同线（少量 P2 过度解释）。

每批：

- 生成 patch + manifest + 备份；
- 自动跑合同/构建/路线检查；
- 作者只审汇总和抽样；
- 通过后再进入下一批。

## 阶段 3：角色声音与呈现（P2）

- 用卡语言系统做 speaker-swap 审计；只重写被判可替换的行；
- 全员店主化：逐步拉开不同角色的句法/反应方式；
- 选项提示去提纲化；
- 实机截图/录屏确认行内动作的视觉形态。

## 明确不做

- 不再全量 voice pass；
- 不再换模型/预设重写整场；
- 不再做第三遍全局八股词扫描；
- 不要求玩家逐句标注；
- 不直接改 Content 后再验证。

## 建议立即开始

先做阶段 0 的 0.1 和 0.2：

1. 侍从线告白汇合路径复核；
2. 裸舞台指令/行内动作实机渲染确认。

这两项不需要改写文案，风险最低，且直接对应两份报告里证据最强的 P0。
