# 画像导出管线：按作者样图校准

2026-11-10。用户提供同一角色的正常大图与作者最终游戏画像，说明作者采用大图生成后再算法缩小的流程。本轮据此纠正此前“应主动简化五官、发束和色块再重绘”的方向，使用本MOD原有正常绘画母版重新导出两张美化画像。

## 从样图得到的依据

输入图1为1470×1070 RGB、洋红背景；图2为288×212 RGBA，透明度仅0／255，有效人物边界为`[81,62,208,212]`，可见颜色9033种。

以图1人物区域拟合图2人物边界，控制位置和尺寸，比较六种常见缩小方式。不做色板归并、额外锐化或额外模糊；颜色误差在图2透明边缘向内收缩两格的区域计算，避免抠图边界主导结果。

| 缩小方式 | 内部RGB平均绝对误差（0～255尺度，越低越接近） |
|---|---:|
| 面积平均 BOX | 3.38 |
| Hamming | 3.63 |
| Lanczos | 3.68 |
| Bicubic | 3.80 |
| Bilinear | 5.24 |
| 最近邻 | 7.29 |

在这组受控比较中，面积平均的内部误差比最近邻低约54%，人物轮廓重合度约99.47%；同尺度目视也更接近作者的头发、眼线、肤色过渡和金边。最近邻明显产生碎点和断裂细线。

**这支持选择面积缩小作为当前复现方案，不能证明作者使用了Pillow BOX或某个具体软件。** 原始源文件、缩放位置的精确小数、抠图参数或其他处理未知，不能声称已逐像素还原作者整套算法。

## 现行导出步骤

1. 继续使用原有正常绘画母版，保留人物、服装、神态与姿态。
2. 用Alpha≥128确定人物裁剪边界，维持已经核对过的脸部大小、位置和底部裁切。
3. 在预乘Alpha空间执行一次BOX面积缩小，避免透明区域隐藏RGB污染人物边缘。
4. 转回正常RGBA后将透明度定为0／255，清零完全透明像素的RGB。保留完整RGB颜色，不归并到48／64色，不抖动，不另加模糊或锐化。
5. 放入288×212画布，继续使用原生Point显示、无mipmap和原有Sprite比例。

面积缩小本身会将一个目标像素覆盖的源区域进行平均，作用与直接选取某个源像素的最近邻不同。最终仍是游戏原尺寸的像素图，正常的绘画过渡得以保留，无需把人物先改画成粗大色块。

## 验证与复现

- `python tools/export_eleanor_beauty.py`：两张正式美化资源按当前管线导出。
- `python tools/export_eleanor_beauty.py --output-dir <目录>`：只生成候选及其记录，不改正式资源。
- `python tools/audit_gala_asset.py`、`python tools/validate_maid_asset.py`：核对尺寸、透明度、边界、来源与SHA256。
- `tools/compare_portrait_resampling.py`：用用户提供的图1、图2复现六种缩放对照；完整结果见`dist/reference-pipeline-20261110/resampling/resampling-comparison.json`。

两张资源的重复导出哈希一致；原有母版与原版风女仆装哈希未变。项目资源检查通过。游戏镜头和柜台遮挡的最终表现仍需实机确认。
