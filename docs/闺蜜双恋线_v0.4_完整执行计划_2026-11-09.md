# 闺蜜双恋线 v0.4 完整执行计划

日期：2026-11-09。状态：待执行。当前代码基线：0.80。

## 1. 结论与交付目标

v0.4 可以直接作为完整开发计划的剧情基准，无需另写一版完整剧本。它已经覆盖正常流程、经营分支、拒绝、旧档、世界结果和日常。本计划将少量衔接问题转为明确的实施任务；不把它误认为无需转换便可导入的运行数据。

最终交付为一条可完整游玩的双恋扩展：普通恋爱前段接受莉迪亚撮合，母亲安全后领取荐店铭牌，通过真实经营体验推荐带来的收益；在不覆盖埃莉诺原有关系与世界结果的前提下，完成莉迪亚心动、三方讨论、分别约会及共同晚饭。

正常新档目标第67天完成，第68～75天作为队列挤占和短暂延迟余量。玩家主动长期拖延和更新过晚的旧档按实际进度继续，不保证强制赶在75天完成。主要铺垫在60天前，关系确认和约会收束在61～67天。

本轮执行范围：剧情、中英文、独立存档状态、调度、两笔真实业务、铭牌持续收益、已定美术接入、旧档迁移、调试入口、验证与可回滚发布包。不扩写其他三条路线，不新增女二、阵营制服、电话界面、餐厅场景或新恋爱数值界面。

## 3. 开始实施前落实的衔接修正

这些是本计划的实施决定，不要求用户再选择剧情方向。对白修补以最小必要改动为限，并记录原句与改句。

### 3.1 章节调序必须有独立进度

现有合作介绍买家在运行Chapter21，加载c20内容；完成时会推进22并立即排买家。v0.4将这段放到第58天，而运行22/23所对应的莉迪亚来访、工作场景要提前到第54/55天。只改TargetDay会卡住前置链或重复奖励。

处理：接受扩展后，由独立双恋调度接管救母后的对应场景；原主线进度保留在明确的接管边界，另记哪些原内容实际完成。完成收束时提交一次原核心完成。不能为解锁后章而伪造尚未发生的合作、工作、赠礼。未接受者继续原顺序。通用原流程与双恋流程必须共用事实提交方法，避免两套奖励逻辑分叉。

### 3.2 旧档的经营不能成为感情前置

v0.4旧档顺序中“入口与铭牌 → 首位营业客 → 个人咨询”只表示推荐阅读顺序。实际实现中首位营业客是并行可选任务；没领牌、没摆牌、缺货或未成交都不能阻止个人咨询、约饭和后续感情。

### 3.3 第二笔未成交的叙述与补做

第9章未成交版本说客户“在别处找到了”，不能之后又让同一人无限重复同一紧急需求。处理：已到访并结束该需求才使用这句；尚在预约队列中用“她还在等回话/还没来”的事实版本。需求已结束后，补做由另一位通用上层买家提出相同规格的新需求，使用短对白，沿用第二业务类型；不新增具名NPC。成功结算与第一业务分别记录。

### 3.4 时间指代随实际日差变化

第15章“昨天”、第16章“明天一起”、第18～19章前后约定不能依赖理想日程。记录前次场景实际日期；相邻日使用原句，延迟时用“上回/前些天/约好的时候”等替代。三方明确讨论期间第15章在首个安全剧情槽优先播放，不被普通日常挤到数日以后。不会为了兑现一句“明天”抢原版紧急事件。

### 3.5 拒绝当场与后续收束

第17章三人在场而选择退出时，先当场明确“不成立双恋”，随后才进入分别收束的安全来访。不能点击拒绝后无回应就散场，也不能继续播放吻或握手。第15章撤回提议同理。七天冷静期统一以对莉迪亚的明确收束实际播放日计算；私人来访和她本人的业务反馈暂停，已经排好的普通买家照常履约。

### 3.6 美术文字与实际版本一致

人物描述补充日常薄纱/原版不透明拼接；第18章原版使用披肩覆肩描述，美化版使用披肩搭上臂描述。美术清单“不透明面料”明确为裙身不透明，美化版允许上胸薄纱。沿用第一版约会像，不再追加绘图任务。

### 3.7 小型事实分支补齐

- 第2章“刚才瞥见一件”只在有适用品时出现；缺货版从入口就替换，避免先称有货再称无货。
- 第4章成交反馈中“看见橱窗里我的名字”需检查当前是否摆牌，已取下时改为中性成交反馈。
- 旧档入口不假定曾去莉迪亚介绍的餐厅；未播放过约饭时使用首次邀请版本。
- 终局“牌子在你那儿收着”区分已陈列但未成交、仓库持有、意外缺失三种事实。
- 双恋完成的工作尾声必须读取实际工作已提交状态；不能只凭恋爱结局补造上层工作。

## 6. 存档与事务规则

使用独立前缀（建议er.dual.）和自身schema，避免为新增路线直接提高RomanceState.Schema导致旧档整体阻断。

至少保存：

- 入口：未提供/接受/明确拒绝；普通恋爱资格仍读取原事实。
- 场景：已播放集合、当前待办、实际完成日、恢复阶段、下一最早日；原合作/工作/核心各自完成记录。
- 关系：未讨论、讨论中、确认、拒绝/撤回；最终结局另记，不与普通恋人字段合并。
- 物品：未领取/已赠予；实际存在与陈列每次检查，补领资格不只看一个布尔值。
- 业务：首笔/第二笔各自未预约、待来、未成交、已成交；待来访唯一ID、需求快照、成交去重ID、一次供货标志。
- 口碑：待反馈/已提交；记录实际成交事实，不用恋爱好感替代。
- 引荐：当日抽取结果与日期、上次额外买家日、队列保留状态；排队受阻不得当天再抽。
- 冷静期、日常上次日期、旧档迁移版本、历史拾荒资格来源。

提交原则：选择点击不等于关系成功；完整同意对白结束才提交双恋。赠礼、业务成交、奖励都只能提交一次。对话中断恢复到最近安全节点，已实际支付/转移的物品不再次交易。日抽取和待来访状态持久化，读取同一保存状态不重抽；不宣称能禁止玩家回到此前尚未保存的历史节点。

## 7. 经营实现与首轮参数

### 7.1 先做接口验证

在接完整剧情前验证：橱窗真实物品枚举、库存商品标签、便携净水器的实际目录ID和耐久字段、原生买卖预算及成交回调、保存后队列恢复。使用当前游戏程序集/目录实查，不能把此前研究中的函数名当作已存在稳定API。

完成一个最小场景：放牌、有货→出现买家→真实成交→保存重读只计一次。若最低耐久无法通过稳定接口准确验收，调整为原生可表达规格，并同步接单说明；不伪装已检查。

### 7.2 铭牌

- 注册唯一1×1物品，非奢侈品、不计作库存商品，不赋予许可证/司法保护属性。
- 使用项目既有重要物品保护方式；物品位置在受支持存储间移动不复制。
- 有效橱窗陈列才产生新引荐；仓库、背包无效。取下只停止新排队，已在路上者仍来。
- 受控补领先核查所有受支持存储；无法可靠核查时不猜测“遗失”，保留以后重试。

### 7.3 客流与订单

初始50%、口碑75%，作为可调整配置起点；买家到店后至少空出一个营业日，下次最早D+2。首位教学买家在摆牌且有适用品后保证排入下一可用普通位置，不走无限随机。第二笔预约在说明需求后最早次营业日，缺货也可正常结束。每日至多1名相关经营客，最多1名已承诺待来访客；第二预约与首位教学同时待排时保留任务，不覆盖已承诺来访。

第一业务按实际奢侈品/精品标签筛选；不把高价等同奢侈品，排除剧情物品、铭牌和不适用物品。第二业务优先便携净水器，预算与最低耐久在接单前明确显示。首轮数值以原生物价与现有预算为基线，通过实机收益记录确定，不能凭剧本文字保证盈利。

两种不同业务各成交一次才具备口碑反馈资格；同一交易即使满足两类条件也只能完成其所属任务。普通引荐客不无限计入升级。供货为一次有限普通卖家机会，正常采购价、不免费、不保证回购；不重复赠货。

剧情拒绝不撤销既成合作。为避免收集所有路线终局增益：基础铭牌效果保留；75%扩展口碑效果仅在双恋扩展仍有效或完成时启用，退出后保留事实但按基础效果运行。此为执行层收益分配，不新增惩罚剧情。其他路线的未来经营扩展不在本轮实现。

## 8. 旧档与其他路线兼容

| 存档情形 | 行为 |
|---|---|
| 新档、尚未救母 | 正常共同修订；不提前撮合或赠牌 |
| 救母后、未确认普通恋爱 | 按实际章节给新入口；不回放已经发生的原章 |
| 普通恋人已完成 | 旧档专用邀请；不重复告白/吊坠/香水；经营并行 |
| 朋友/已明确拒绝扩展 | 无莉迪亚暗恋与再次推销；已有业务按事实保留 |
| 侍从有效档 | 不开放双恋；只做共同人格和已授权美术更新 |
| 丙丁线 | 保留原世界与关系结果，取消不符合事实的新增待办 |
| 已处于部分双恋流程 | 按已提交场景恢复，不把未定义状态推断为确认 |
| 程序不识别的未来schema | 停用双恋写入并提示；不重置整个MOD |

母亲、研究公开/归还、撤案新闻、种子、已卖吊坠及香水各自保留。拾荒已激活事件自然结束；接受撮合时不立即剥夺收益，双恋正式确认时切换未来资格；退出则按真实普通恋爱条件恢复。不得把已有侍从投资、分红写进双恋收益。

## 9. 内容制作与美术接入

1. 逐段转录v0.4并保留来源章/分支；说明文字变为条件或玩家可见选项说明，不能全部塞进对白。
2. 同名发言使用既有说话人系统，三人场景仅轮换对白头像，不生成两个同时交易的顾客。
3. 旁白不能承诺未存在的餐厅画面；约饭与晚饭使用既有柜台场景和文字过渡。
4. 先完成中文结构校验，再人工核对英文语气、物品名、选项实际效果和关系用语；中文小修必须同步英文。
