本记录补充并修正此前0.81审查。依据当前运行代码与Content源，不将执行计划中的所有复杂机制视为必须补齐。此次为排查结果与修订边界，尚未修改运行逻辑。

以下不应按关键词直接删除：

- 侍从“先不公开，重新商量”：代码返回当前对话菜单，是取消危险行为，不跨天。改成“返回，重新选择处理办法”，保留退出不可逆操作的机会。
- 侍从“稍后再来领取”：奖励处理与剧情推进分离。见MaidStory.cs:454、465。可简化主动留待以后，但满仓等交付失败必须保留恢复方式，不能因此暂停剧情或丢奖励。
- “这回先不进货。说说上面的事”：明确拒绝当前交易并推进剧情，应保留。
- 王尔德项目筹资：这是玩家明确认可的经营准备时间，不属于含糊的感情暂缓。
- “先不提箱子的事”等隐瞒/策略选择，以及角色对白中的“让我想想”：不等同于待续剧情，按实际效果判断。

旧档已存在Romance=2时不能因为删除新入口而遗留死路。普通恋爱旧档按实际关系给一次明确收束，不转入后宫，也不再提供暂缓。

## 2. 为什么同一玩家可能遇到两套场景

这不是剧情需要，而是目前代码把改写稿作为追加内容接入了。

StoryDirector.cs先尝试DualDirector排队，再尝试原EleanorStory。DualDirector.SuppressMainChapter只屏蔽部分原章；DualStory又独立实现告白、工作和结尾，导致两个推进记录不完全对应。

具体例子：新告白dr05完成只设置恋爱成功，没有完成原告白章；原告白章又不在被屏蔽范围。因此改写稿存在，原告白也仍有排队入口。工作和结尾虽然压住了原场景，原场景负责的吊坠、回执等行为却没有全部接到替代场景。

正确目标：同一玩家每个节点只玩到一次当前版本场景。共同剧情只有一份；进入后宫后，dr05替换原告白、dr08替换原工作、dr11替换原核心收束，剧情与该节点的交易/奖励一并迁移。未进入后宫者继续普通恋爱的当前版本，不把历史文本当作另一条可游玩路线。旧普通恋人档继续其普通后续，不新增回补入口。

保留普通恋爱和后宫两个结果分支，不等于保留“新旧两条路线”；源代码能复用方法，但运行时不能重复播同一阶段。

## 3. 当前后宫线实际付出与收益

| 内容 | 玩家付出 | 获得 | 是否阻止后宫结局 |
|---|---|---|---|
| 共同恋爱资格 | 已有公平交易/让利累计至少3次，以及举报、救援或记录威胁等经历之一；母亲安全 | 原本就存在的恋爱资格 | 属于共同前置，非后宫新增挑战 |
| 后宫入口 | 不扣现金，不扣声望 | 新剧情 | 无新增经营条件 |
| 荐店铭牌 | 免费领取；启用占橱窗1格 | 符合条件时引来买家 | 不摆牌也不锁感情 |
| 第一笔业务 | 准备并卖出合适商品；承担取得商品成本，交出商品 | 买家预算500，实际议价收入及成交记录 | 可不完成 |
| 第二笔业务 | 准备便携净水器，真实耐久至少150；交出商品 | 买家预算600，实际议价收入及成交记录 | 可拒绝/未成交 |
| 两笔成交 | 两种商品的真实供货与交易 | 经营反馈；但当前实际概率未按成交升级 | 不要求完成 |
| 双恋确认 | 推进对白；无现金/声望/业务次数条件 | 关系确认，代码将引荐概率从50%改为75% | 不看两笔业务结果 |
| 埃莉诺上层工作 | 当前节点无玩家付款或交货 | 工作与去向发生变化 | 由剧情推进提交 |
| 核心礼物 | 当前分支无额外付费 | 原有香水；代码仍会授予符合条件的普通拾荒资格 | 并非后宫独有投资回报 |
| 分别约会、共同晚饭 | 无餐费、礼物购买或其他经营门槛 | 约会画像与后宫结局 | 对话推进即可 |

500/600是买家预算，不是赠款或保证利润。实际净收益需扣商品取得成本，也受议价和能否成交影响。50%/75%受摆牌、合适库存、冷却和队列条件约束，不是每天保证增加客人。

结论：后宫线当前是“共同前置完成后，恋爱剧情带来免费经营机会”，不是“完成后宫独有挑战后取得关系和经营成果”。零笔新增业务成交仍可确认后宫并获得更高引荐概率。它没有侍从线那样明确、必须承担的新增资源投入。

## 4. 建议的设计取舍（未作为已授权数值实施）

先兑现现有简单机制：去掉主动暂缓，业务一次性接受/拒绝/成交/失败后继续；人物好感和恋爱不等待补单。

若希望经营参与有价值，可让基础铭牌免费，实际完成两类业务才取得额外经营收益，未完成者仍可完成恋爱。这提供经营目标，但不能宣称是“获得后宫必须完成的挑战”。同时将真实成交反馈纳入人物评价，避免只在结尾弹收益通知。

若用户希望后宫结局本身也需要付出，则必须另行确定一种清楚、可预先准备的必要条件；当前代码没有。建议围绕店铺承接上层客人的能力设计一个固定目标，而不是照搬侍从的四期投资或添加反复补约。是否让该条件影响恋爱结局，属于设计决定，不能在修缺块时暗中加入。

当前优先级：统一玩家看到的场景版本 → 删除暂缓及补约承诺 → 修复缺失文本引用 → 再确定独有挑战和经营收益条件。沿用项目每日调度限制，不为这些修订扩建交互系统。
