# 项目制作过程与发展史

最后整理：2026-11-20。本文记录《上层区的富家千金爱上在下层区开当铺的我：埃莉诺剧情扩展》的制作过程、版本脉络、生产方式和文档体系演变，供后续 Agent 与作者追溯“为什么现在是这个样子”。现行规则与文档导航见 [INDEX.md](INDEX.md)，发布证据见 [archive/releases/](archive/releases/)。

## 1. 项目定位（不变）

《深空当铺：可能是偷的 / Probably Stolen》的 Eleanor 个人剧情扩展（Unity MOD）。玩家始终是下层区售卖亭的当铺店主，在亭内、来客在窗外；故事核心是上层区千金埃莉诺与店主在阶级反差中的恋爱与爽文式满足。项目是个人兴趣、无偿、自费的扩展，不是推倒原作的完全二创；作者是最终解释者，Agent 是编剧助理与舞台工作人员。原则见 [PROJECT_PRINCIPLES.md](PROJECT_PRINCIPLES.md)。

## 3. 关键决策与转折

1. **路线体系从“甲乙丙丁”改为四线**：早期文档明确“甲乙丙丁是世界事件结果，不宜直接改成四个恋爱菜单”，据此 0.81 建后宫线、0.90 建革命军线、1.04 完成四线重制。现行只有恋爱线/后宫线/侍从线/革命军线 + 共同线；甲乙丙丁、A/B/C/D 等旧称呼只保留在归档文档，不得用于新文案。
2. **无旁白修订（0.83）**：先从 32 块中删 48 条旁白，再由后续重制加回“作者保留的具体动作旁白”。现状是：旁白不做心理总结，只写玩家可见可听的动作与环境。
3. **E 编号合并（2026-11-15）**：E5–E8 并入 E1–E4，E10–E14 仅旧档保留；现行五结局 E1/E2/E3/E4/E9。营养果开源只是经营风味，不拆结局、不评完美。`完美集合 E1/E4/E3/E9` 成为历史词，路线图维护文档与 `check_route_map.py` 已禁止再用。
4. **立绘兼容策略反复**：0.86 内置美化包 → 0.87 回退 → 0.88 恢复 Lydia 独立形象 → 1.06 强制统一 → 1.08 逐帧守卫 → 1.09 合作式让位 + 私有 `cp_portrait_*` 键 → 1.11 三模式（Auto/Force/Other）。方向从“抢占”转为“让位 + 可配置”。
5. **版本门禁取消（1.13 follow-up / 1.14）**：游戏更新曾让精确版本白名单停用全部剧情；改为 `Application.version` 只写日志后，代价是 follow-up 未升版本、玩家端不会自动更新，随后补 1.14 并强化“每次上传必升 manifest 版本”的发布纪律。
6. **日韩本地化（1.20–1.21）**：1.20 新增 ja/ko 全量翻译；1.21 韩语改自然半语、埃莉诺统一译名“엘리너”；1.22 时 zh 5,977 / en 6,221 / ja 5,977 / ko 6,221 键。
7. **售卖亭空间规则（1.04 / 2026-11-15）**：玩家始终在亭内、常规对话与交易只通过窗口发生；卷帘没有把手/铰链/门闩/门绳；侧门不能承载完整对话。此后所有新场景都必须隔窗成立，居家与场外另设地点。
8. **文本去 AI 味的路线选择**：0.80 首轮 765 条重写 → 1.04 重制 → 1.10 按路线 1:1 voice pass → 11-16 五场主笔试点 → 11-17 定点修订计划 → 11-17 作者解除限制、改为 Agent 直接改稿并保留逐行证据。结论是“换模型/整场重生成”不能解决结构问题，场景体量与玩家侧才是主因。

## 4. 生产方式（当前）

### 4.1 文本

1. `Content/*.json` 是唯一正文真源（共同线、恋爱线三卷、后宫、侍从 v05/v2、革命军 v1/v2）。
2. **角色层是两级**：一级是三位角色的静态卡（`docs/埃利诺-角色设定.txt` 等），描述共同线状态下的基准人设；进入各路线后使用**路线二级人设**——各路线自己的阶段、处境、欲望、回避方式、禁止项和声音参考。二级人设的正式载体是各路线 world book / ActCard 的 stage、facts、voice、boundaries 字段（`tools/NovelWorkFlow_Eleanor/` 是本地目录，不入库）；仓库里 `docs/埃莉诺与莉迪亚_全局人设基准` 的路线/阶段表只是参考材料，不能替代正式二级人设，也不能把一级静态卡直接套到所有路线。
3. 改文本：改 Content 中文 + 对应英文 → `python tools/build_content.py` → `python tools/check_project.py` → Release 编译。
4. 本地化：en 为人工意译（`tools/en_v06_part*.json`、`tools/ui_text_en.json`）；ja 由覆盖层 + `apply_ja_translations.py` 生成；ko 直接维护 CSV。生成物 `.g.cs` 与 CSV 不手改。
5. 新剧情/选项/日期/结局：同一次改动更新 `route_map.html` + `ROUTE_MAP_MAINTENANCE.md`，跑 `check_route_map.py`。
6. 文风基准说明：作者的主要参照是游戏本体原文与官方中文本地化（`docs/原作Eleanor章节_对照稿`、`docs/原作非台词表现与MOD应用审计`）；`docs/文风与玩家台词基准` 是 Agent/流水线根据原作与预设整理的参考，不是作者提供的标准。

### 4.2 写作生产管线（历史实验）

`tools/NovelWorkFlow_Eleanor/` 曾用固定三文件链（`writer_prompt_template.md`、只读 `writer_system_prompt.md`、`world_book*.json`）+ 主笔/QA 脚本生成候选正文。它跑通过若干幕、产出过完整候选，但未接入游戏构建，且出现结构越权、事实漂移和 QA 失守；2026-11-17 起正式做法改为在 `Content` 上直接修订。该目录保留作历史与工具参考，调用时仍受 `CLAUDE.md` 的三文件规则约束。

### 4.3 美术与 CG

- 立绘/表情/服装走“作者 B/detail 采样”管线（高清母图 → 288×212 二值化采样），表情差分只改脸内眉/眼/嘴。
- CG 两轨：**P 像素**用于结局、新闻、文书、世界卡；**A 动漫**用于立绘、关系、日常/私密/外出 CG。每条 CG brief 必须标 P 或 A。
- 当前运行 8 张 CG：4 张事件 CG（A，1664×936）+ 4 张路线完成结局 CG（E1 高清、E3/E4/E9 像素 960×540）。计划为 4 路线 × 8 格 = 32 格，另有 36 格候选扩张池。
- 规则说明（不作为方向性原则）：四条路线完成结局 E1/E3/E4/E9 各配结局页 + 1 张 CG；E2 朋友结局用原生 GameOver，不配 MOD 页面/CG。

### 4.4 校验与发布

`check_project.py`（键、块、生成物一致性、场景图）、`check_route_map.py`（版本、结局、节点、指南链接）、`test_*.ps1`（离线内存回归）、`scan_package.ps1`（原生能力扫描，要求 0 反射/0 线程/0 弃用）是 Agent 能执行的检查。发布：升 `manifest.xml` 版本 → 同步 README/`DATA.version`/维护文档 → `package_release.ps1` → `publish_workshop.ps1` 上传并记录回执；`dist/` 保存证据但不入库。历史发布记录已归档到 [archive/releases/](archive/releases/)。

两条项目事实（Agent 必须知道）：

- **实机验收不由 Agent 负责**：本项目从未出现 Agent 主导的实机验收；历次尝试都未成功。Agent 只做离线检查、Release 编译、原生扫描、打包与证据记录；实机验证的范围和是否执行由作者决定。
- **Git 提交由作者明确指令**：本项目所有提交都是作者直接指令 Agent 执行的，从未有 Agent 自动提交；推送平台同理。Agent 不做自动提交、自动推送。

### 4.5 平台文案

Steam 工坊与 Nexus 的对外文案由作者在平台手动维护和同步；仓库内 `WORKSHOP_*`、`NEXUS_*` 只是 AI 记录或打包输入，不是权威发布稿，也不要求回填。
