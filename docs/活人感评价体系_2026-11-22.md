# 活人感评价体系（2026-11-22）

这份文档把此前“我按 8 分制读一遍”的评审方式，升级成**可执行、可复核、尽量不偏向本项目**的评价体系。

它不是发布门槛，也不声称“AI 感”可以被单一指标证明。它的用途是：

1. 区分“文本是否合格”和“读者是否觉得像人写的”；
2. 用盲评和成对比较替代单评委的绝对 8 分；
3. 把“同质化/跨场景重复”纳入评价，而不只看单场句子；
4. 让每次修复的收益可以被比较，而不是只凭印象。

## 0. 为什么升级

旧做法的问题是具体的：

- 评审者知道哪些段落刚改过，容易把“比上一版好”当成“已经够好”；
- 8 分没有锚点样例，换一个评委就会漂；
- “句子漂亮/情绪成立”与“读者觉得是人写的”被混成一个分数；
- 只看单场，不看同一角色在几十场里是不是同一个模子；
- 单评委、非盲，无法估计偏差。

文献侧的约束：

- AI 文本检测没有稳定通用解，检测器会被改写、采样和未见模型绕过（[RAID](https://arxiv.org/abs/2405.07940)、[Sadasivan et al.](https://arxiv.org/abs/2303.11156)）；
- 读者对“人味”的判断不是单一维度，且受“作者是 AI”标签影响（[Nature 2024](https://www.nature.com/articles/s41598-024-76900-1)、[Chu & Liu 2024](https://academic.oup.com/joc/article-abstract/74/5/347/7756907)）；
- AI 文本的同质化是分布问题，不只是单句问题（[Doshi & Hauser 2024](https://www.science.org/doi/10.1126/sciadv.adn5290)）；
- 可靠的做法是成对人类偏好，而不是绝对评分（[LitBench](https://arxiv.org/abs/2507.00769)）。

## 1. 三层结构

### 第一层：硬门槛（pass / fail）

不过门槛的文本不进入审美评分。检查项：

- 事实：原作事实、前情、人物关系、时间线；
- 空间：店铺窗口、卷帘、侧门、访客位置；
- POV：角色只能说此刻能感知/有来源的信息；
- 选项后果：每个选项的语义与后文一致，不能 2/3 分支漏答；
- 交付：`python tools/check_text_contract.py`、`python tools/check_ai_feel.py`、`python tools/check_project.py`。

输出：P0/P1/P2 数量 + 具体位置。P0 存在时，不给“活人感”总分。

### 第二层：盲评（主证据）

**目标**：回答“读者在不知道版本来源时，觉得哪一版更像人写的、更想继续读”。

**基本协议**：

- 每个样本是 2 个版本，随机左右/甲乙，隐藏来源；
- 至少 2 名读者，理想 3 名；读者之间不讨论；
- 每对先读同一段场景背景，再读两版；
- 每版评 5 个维度（1–7），最后强制选“更像人写”或“平局”；
- 主指标：偏好率、维度均分差、评委间一致性；
- 不统计“AI 检测器分数”。

五个维度（固定名称，避免每次换词）：

| 维度 | 问题 | 1 分 | 7 分 |
|---|---|---|---|
| 声音可识别性 | 遮住说话人名字，还能认出是谁吗？ | 谁都能说 | 只有这个人会说 |
| 私有议程 | 角色有没有不服务当前场景的欲望/秘密/拒绝？ | 只回应玩家 | 有自己的事、会不配合 |
| 对话自然度 | 有没有停顿、改口、打断、答偏、废话？ | 每句都精准接上一拍 | 像真人对话，有不齐整 |
| 场景因果 | 这场有没有改变什么？选择有没有后果？ | 纯信息交换 | 有事件、有代价、有后果 |
| 沉浸/继续读 | 读完想不想看下一段？ | 想跳过 | 想继续 |

**锚点建议**（每次盲评前先给评委看 4 个锚点，不告诉来源）：

- 1 分锚点：每句都在回答上一句，角色没有私心，结尾收得很齐；
- 3 分锚点：能读，但像“正确作文/短剧”，人物声音可替换；
- 5 分锚点：有具体动作和局部活口，但整体仍能看出设计；
- 7 分锚点：遮住名字仍认得出人，场景有意外，角色会不配合。

**样本量**：最小 12 对；本轮先做 12–16 对，不追求显著性，只用于校准“我的 8 分是否偏乐观”。

### 第三层：自动诊断（辅助证据，不是总分）

自动指标只回答“形态是否异常”，不回答“好不好”。

必看指标：

- 玩家提示 → NPC 回应率；
- NPC 回应比玩家提示更长的比例；
- 行内动作率；
- 句长分布（中位/P90/P95/≤8 字/≥25 字）；
- 短→长跳变率；
- 块尾发言人与块尾 ≤12 字比例；
- 角色声音可识别性（遮名分类准确率）；
- 跨场景/同路线相似度；
- 高频重复短语（口头禅/公式句）；
- 词面重复率/类型-形符比；
- **防御性澄清/预先消歧（H20 启发式）**：NPC 句中“我不是…/我没…/别误会/不是那个意思/我只是…”等先替读者消歧的比例。它是候选项，不直接当 AI 句；必须抽样复核，并用“删掉澄清后下一句是否仍成立”做 A/B。

这些指标要与**人类基线**（原作/卢前半）比较，而不是只与自己的上一版比较。

## 2. 评分与报告

不再用单一 8 分作为最终结论。报告使用：

- **硬门槛**：P0/P1/P2 数量；
- **盲评**：偏好率（含置信区间）、五维均分差、评委一致性；
- **自动指标**：与基线的差值；
- **同质化**：同角色跨场相似度、跨角色相似度；
- **结论句式**：“在 N 对盲评中，A 被选为更像人的比例是 X%；五维中 Y 显著；自动指标 Z 仍高于人类基线。”

只有同时满足以下条件，才可以说“这一批文本在读者层面接近过关”：

1. P0=0；
2. 盲评偏好率 ≥ 60%，且至少 2 名评委方向一致；
3. 五维中没有一项显著低于人类基线；
4. 同质化指标不高于人类基线。

否则只能说“可读/有局部改善”，不能说“AI 感已解决”。

## 3. 工具

### 自动指标

```bash
python tools/super_qa/eval_human_feel.py \
  --current docs/CURRENT_TEXT_READING.md \
  --baseline docs/原作Eleanor章节_对照稿_2026-11-10.md \
  --out dist/ai_feel_audit/HUMAN_FEEL_BASELINE_2026-11-22.md \
  --json dist/ai_feel_audit/HUMAN_FEEL_BASELINE_2026-11-22.json
```

`--baseline` 也接受 `speaker：text` 行的简格式（原作对照稿就是这种）；它没有块结构，因此只会参与句长/动作/提示回应的对比，不参与块形状与跨场景相似度。

### 盲评

```bash
# 1. 由 pairs.json 生成盲评页
python tools/super_qa/blind_eval.py build \
  --spec dist/blind_eval/pairs.json \
  --out-dir dist/blind_eval/run_2026-11-22

# 2. 读者打开 BLIND_TEST.html，完成后下载 responses.json
#    没有活人读者时，可把 build 生成的 READER_PACKET.md 交给 Agent 盲评；
#    responses 结构相同，但分析时必须标 --evidence-level ai_panel。

# 3. 分析一份或多份 response
python tools/super_qa/blind_eval.py analyze \
  --key dist/blind_eval/run_2026-11-22/blind_key.json \
  --responses dist/blind_eval/run_2026-11-22/responses_reader1.json \
  --evidence-level ai_panel \
  --out dist/blind_eval/run_2026-11-22/REPORT.md
```

`--evidence-level` 三档：

- `human_panel`：2–3 名活人读者，默认；唯一能写“读者偏好率”的证据。
- `author_single_blind`：作者一人盲评；比不盲好，但只算个案。
- `ai_panel`：Agent/AI 评审团；只能做 triage 和方向判断，不能写成“读者看不出 AI 味”。

`pairs.json` 格式（`left`/`right` 只是构建时的内部键，页面会随机变成甲/乙；`label` 用于事后汇总，跨对建议保持同一组名字）：

```json
{
  "title": "2026-11-22 场景对读",
  "pairs": [
    {
      "id": "love_a1_02",
      "title": "恋爱线《营养果》",
      "left":  {"label": "当前稿", "text": "……第一版全文……"},
      "right": {"label": "候选B", "text": "……第二版全文……"}
    }
  ]
}
```

至少 12 对；每对只放两个版本，不要三版混排。读者页不会显示 `label`，只显示甲/乙。

## 4. 每次评价的固定流程

1. 冻结版本：记录 `git diff`、Content 哈希、阅读版生成时间；
2. 跑硬门槛；
3. 跑自动指标，和人类基线并排；
4. 抽样 12–16 对，生成盲评页；
5. 至少 2 名读者完成；
6. 汇总偏好率、五维差、一致性、自动指标；
7. 结论只写“这一批文本”的，不外推全作；
8. 不因为一次盲评赢就发布，不因为一次输就全盘推翻。

## 5. 边界

- 盲评仍受读者经验、场景熟悉度、标签预期影响；
- 12–16 对只能校准方向，不能证明全作；
- 自动指标是形态诊断，不是“人味”证明；
- 人类基线（原作/卢前半）也有自己的时代和体裁限制；
- 本体系不替代作者判断，只把作者判断从“单评委绝对分”变成“可复核的证据”。

## 6. 与旧评分的关系

旧的 8 分制保留为**内部粗标**，用于快速排序修复工单，不再作为对外结论。  
如果旧分与新盲评冲突，以盲评为准，并记录冲突原因（例如旧分偏向句子质量、盲评偏向整体结构）。
