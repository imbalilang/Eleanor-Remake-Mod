# 文风批量重构前审查意见

审查日期：2026-11-10。
对象：文风与玩家台词基准、第一批试改v4，以及配套JSON、核对报告和相关运行代码。
结论：方向值得采用，但目前不宜把基准与v4作为无需人工复核的批量重写模板。先修正规则冲突、残留的无依据回应及机械应用边界，再扩大批次。

本次没有重新提取原作本地化包，因此不独立背书基准中2544条等原始统计；本次主要检验规则内部一致性、试稿语义和实际代码接入条件。未修改两份受审文件或运行文本。

## 一、必须修正的基准规则

### 1. 不让“玩家零台词”覆盖剧情事实与主动选择

减少访谈式提问是正确方向，但“没有登记理由，一律删除”应改成“未登记者标记待审，不自动删除”。应优先锁定：告白、拒绝、三方意愿、调查结论、玩家承诺、交易用途、关键解释及其触发来源。

若既有菜单已经表达同一信息，可以删掉重复回显；若菜单没有表达，不能为降低玩家占比而直接抹去，更不能转成NPC单方面断言“你答应了”。也不能未经授权新增菜单来逃避对白配额。

优先级应写明：既定剧情/玩法事实与玩家选择语义 > 因果可读性 > 角色阶段与声音 > 风格目标 > 数量指标。标准应称为“统一文风标准”，不是覆盖所有剧情设计的“唯一文本标准”。

15%可保留为常规审查阈值；关键表态使短分支超限时，提交例外，不补NPC废话扩大分母，也不删关键同意。共同与新路线都默认0，block“目标1句”改为“默认0；已批准例外通常1句、最多2句”。

### 2. 统一数量口径，消除互相矛盾的限制

- 斜体每章≤2%，意味着少于50行的章连1条都不允许。c02全分支26行已有1条，即3.85%；实际路径占比更高，不能同时称为合规示范。
- 建议：斜体每章默认0、确需最多1条，跨章同一路径整体目标≤2%；取消短章2%的硬限制。连续使用限制单列，避免用“每10句”规定不明确的取整方法。
- “每场保留一次无台词反应”改为“可保留必要反应，不强制每场安排”。否则模型会为达标编造玩家动作。
- B类隐含动作和文字效果按同一情绪点避免叠加；不要因本章有一次叹气，就否决另一处有依据的短反应。普通Idle浮动、当前服装画像不应算作额外演出配额。
- 主线角色TextAnimator需批准与莉迪亚表格“优先wave”不一致；本次廉价模型重写统一禁止新增动画标签，既有已验证标签保留清单化处理。
- 字数统计明确：可见文本，去除标签、不删标点的口径需固定；中文限制不直接套用英文字符数。总行数和实际路径行数分开报告。

### 3. 修正莉迪亚和后期埃莉诺的角色约束

基准9.4“莉迪亚保持调侃、轻佻、精明”不符合用户确认的大家闺秀气质与v0.4角色定位，容易把她重新写成职业交际人物。

建议替换为：爱漂亮、热心、嘴快、喜欢给朋友出主意，有一点小虚荣；对自己的感情反而迟疑。出身富裕，有生活见识，但不是职业经纪人；不以轻佻或老练情场口吻为默认声音。

“恢复埃莉诺的阶级偏见”须限于早期。后期可保留傲气、急躁和嘴硬，但不能把已经完成的成长倒退为重新羞辱下层人。每批输入必须提供当前阶段及已发生关系事实。

### 4. 区分真实物件与仅写在对白里的物件

不能把“用物件表达关系”理解为任意加送餐、赠礼、查看、闻香、受伤等行为。必须标记：实际物品交易、既定剧情事实、纯口头提及三者之一。

查看物品不能自动证明玩家闻过、识别出处、解释折旧或坚持赠送。动作与知识必须分开审查。修辞性反问也不等于无依据回应；关键是是否要求一个尚未发生的前因，而不是是否出现“你”“对吧”或问号。

### 5. 删行前查运行调用，不能仅保持block ID

StoryEngine.BuildSkipFirst会从索引1开始构造对白。EleanorStory中c14、c19、c22的部分分支使用它，以跳过重复菜单的首句玩家台词。若批量删除首句而不处理调用，新首句NPC台词会被静默跳过。

批量改写须附“保护行/调用方式”清单。文本阶段遇到保护行不自动删除，登记为需要代码配套调整。m23_b006等共享块应列全部调用路线和触发条件；中文改动同步检查英文、动态模板、条件追加及按行生成的键。

允许调整lines数量不等于允许直接覆盖所有lines。还应保护格式占位符、标签闭合、选项键、任务金额、期限、物品ID及外部直接引用的行键。

## 二、v4中需要先纠正的具体示例

| 位置 | 问题 | 修正方向 |
|---|---|---|
| c01.b004“既然你坚持” | 让利或赠予证明给了优惠，不证明双方经历了推辞后坚持 | 改为直接接受，如“……那我收下。这笔我记着。” |
| c02.b002“你盯着这瓶…认得？”后接“正牌货就够”“我还以为你只认得废铁” | 删除识货回答后，NPC仍默认玩家鉴定成功；去掉“对吧”没有补上因果 | 改成她自行介绍来源/要求；需保留店主识货卖点则登记真实依据或必要短回应 |
| c03.b002“按我的姓算？” | 对应玩家提问已删除，仍像回答不存在的提议 | 自足陈述：“最近听到我的姓，连出价的人都没了。”具体语气可再润色 |
| c03.b003“每一样都说清楚了” | 公平价格只证明结算，不证明玩家逐件解释 | 直接评价价格或接受结果，不编造说明过程 |
| c03.b004“你刚才说的折旧呢？” | 玩家未说折旧，真实议价也不能自动补出完整说辞 | 改成她从价格观察到的让利：“这价钱，比这些旧东西该卖的多。” |
| c02.b004“灯我收下了” | 运行买的是HOUSEHOLD_GOOD，实际让利不保证买了灯 | 改“东西我收下了”，或已有按物品条件版本才能写灯 |
| c23.b003“你答应过的” | 必须查所有进入恋人结局的路径是否有此承诺，包括旧档 | 有确定前置则登记；无前置改为她当前直接提出的要求 |

还有比措辞更重要的运行时序：c02.b002在mainDialogue里无条件链入，玩家尚未进行这次交易时就播放；“看货时”的scene文字并不产生真实验货事件。c03.b001的“轻点”也在实际卖货前播放，若保留可视为她请求小心的指令，不应声称已观察到拿瓶动作。两条B类登记的依据需要重新核对，而不是仅凭scene名称认定有效。

不必把所有口语反问都禁掉。“价签？”可理解为自己看到价签后的反应；需要检查柜台情境，并可改得更自足，不宜与明确引用不存在的“你刚才说的折旧”同等处理。

## 三、试改配套JSON还有两处示范问题

- er_line_scav_assist把“哪块废料松了要塌，我也替你盯着”缩成“塌了我也替你盯着”，从事先警戒变成事后看着，改变了行为意义。可改为“哪儿快塌了，我替你盯着”。
- er_line_core_end改成“她有了工作、母亲，和一堆日常……”，仍是基准要求删除的抽象总结，且“有了母亲”不准确。先确认这个结束节点承载的系统作用，节点可以保留但文字改为具体状态；不直接删除完成提示。

因此核对JSON的PASS只可理解为其已检查的结构条件通过，不能当成“语义无误”“C类清零”或“可直接上线”。文档应分开列结构检查、人工因果检查和运行检查，未完成项标待核查。

## 四、廉价模型每批必须收到的输入

1. 本批准确版本、源文件与block清单；修改前摘要或哈希，避免覆盖并行修改。
2. 角色当前阶段、路线、关系、母亲/研究/工作事实。
3. 每block的真实触发时点：交易前/成交后/离店/某选择之后；前后相邻内容。
4. 每场不可删除的信息：新事实、玩家主动表态、伏笔、承诺、交易要求、情绪转折与结尾作用。
5. 实际可见路径与互斥分支，不只提供chapter内所有块的顺序排列。
6. 保护清单：选择语义、数值、占位符、共享块、跳过首句、直接行键引用、已验证标签。
7. 仅提供修正后的短执行规则和合格示例；历史v2/v3诊断、实验动画表和大量坏例子留给审查阶段，降低模型混用风险。

## 五、每批输出与放行标准

每批建议按2～4个完整场景，遇共享块或关键结局单独处理。应交付：候选JSON、完整路径阅读稿、删改摘要、信息保全表、例外与阻塞清单、中英待同步清单。

信息保全表至少包含：源信息/原位置/改后位置/删除原因/触发证据。不能用“无玩家台词”作为完成判定。

程序检查：ID、schema、角色、占位符、分支集合、空块、保护行、实际路径计数。人工检查：蒙住被删台词后因果是否成立、角色阶段是否倒退、关键行动是否仍由玩家决定、交易结果是否被伪造。最后才检查句长、密度和重复句式。

禁止靠拆碎NPC台词降低玩家占比，禁止把玩家台词搬进旁白或NPC引用来刷零台词，禁止为每章“硬话收尾”制造反复金句。原作统计是节奏参照，不是要求复制翻译腔和粗口；亲密、告白与三方讨论可有更高必要表达密度。

批量重构保留场景信息量和体验体量。减少对白框不等于缩减剧情；各路线统计实际路径的关键事件和阅读量，明显缩水时回查是否误删情感进展，不为凑句数加填充文本。

建议先修本批明确反例，再用一组包含告白、拒绝与共享块的短批验证规则，最后扩展到全稿。无需推翻现有方向，但目前v4不适合作为廉价模型的唯一正面范例。
