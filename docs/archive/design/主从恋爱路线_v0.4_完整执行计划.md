# 大小姐侍从恋爱线 v0.4：完整执行计划

日期：2026-11-07。状态：剧本与执行设计，尚未实现运行时代码、制作立绘或发布更新。

配套全文：`全流程攻略_纯阅读版_大小姐侍从恋爱线_设计稿_v0.4.txt`。本计划取代 v0.2 的执行规则，保留历史稿供比较。新状态名、事件间隔与费用均为拟议设计；第2节是前轮本地核查记录，不代表本轮完成了游戏运行验证。

## 1. 目标、边界与本版取舍

原有平等恋爱保留；800节点新增侍从恋爱分支。玩家提供资金、经营判断和有限的人脉，她付出工作、承担交付责任，以自己的名字重返上层区，最终自愿延续主从恋爱。上层区的认可与下层区主人的贡献要同时成立。

“比过去耀眼”表现为从依赖家庭地位到凭业务获得认可，不宣称小额投入买回整个农场。她接受引见，拒绝没有实际职责的照顾性职位；保留挑剔、傲气与救母决心。恋爱在第20章确认，第23章完成基础阶段，第28章才结束约定并作出自由后的选择。

沿用柜台对白、普通交易、王尔德升级、新闻与立绘。无新地图、雇员面板、命令系统、公司经营、自动分红或日常服务费。挑战由玩家自愿承担，不改变原版经营规则，不以新增付款拖延救母。允许准备到本局结束，但不承诺跨周目保存进度或无限延长原版周目。

相对 v0.3 的必要修订：

- P1结果可在第23章以后补播，堵住P2前置条件的死锁。
- 实付800与旧档豁免使用不同对白；旧档不虚构支付，也不静默补扣。
- 女仆装来自她的短工结余和旧裙改制，不另收费，不挪用调查款或母亲生活费。
- 莉迪亚介绍、玩家人脉与她靠能力立足不再互相否定；声望只代表具体合作关系。
- 乙线受理、计时、正式撤案独立于P1～P4；母亲出席与尾声读取实际结果。
- 第20章买家反馈后置于真实交易；第22章修正来问称呼的人；第26章明确“绕过她成交”；第28章三个回答均成功。

核对范围为当前工作区、本地 `dist/workshop-0.61` 至 `dist/workshop-0.66` 中的 `EleanorRomance.dll` 和安装游戏的 `Probably Stolen_Data/Managed/Assembly-CSharp.dll`。0.66核对了完整相关回调，0.61～0.65比较了调查款回调与调度入口。采用源码及只读 IL 检查，未启动游戏验证 UI，也未读取或修改玩家存档。不能据此宣称已经覆盖所有线上历史包。

本地包比较不是“整个线上所有版本”的证明。发布前必须按线上实际包清单和真实存档补齐迁移样本。

所有开放条件还要求侍从路线有效、甲或乙母亲安全、未退出。P1可在恋爱未确认时购买，其余需基础主从恋爱已完成。新入线800直接现金支付，不套用升级折扣；她自筹的调查800独立保留。

基准预算（倍率1、无折扣、无wildFavor抵付）：新档纯现金17800；全部人脉方案9800＋上层20／下层20。旧档豁免入线，分别17000和9000＋同样声望。混合购买逐项相加。声望门槛是支付前门槛，扣后低于门槛不撤销项目。

付款前说明：支持可延期、无利息、无催缴、无失败倒计时；已完成的准备不退款、不返声望，转换关系后不再购买后续项目。挑战只决定进阶，不取消已有恋爱。

## 5. 王尔德界面、交易与恢复

通过现有升级注册机制添加七个定义，读档后使用AddMissingAfterLoad补齐，注册须幂等。列表与当铺升级并列；不满足开放条件时隐藏或禁用并显示前置条件，不添加自制付款面板。使用现有确认/说明能力显示资源明细，玩家看得到缺口和两种方案。

仅拦截本MOD的 `er_maid_` ID。覆盖WildUIManager.OnUnlockClicked与WildNetworkUI.OnUseClicked两个入口。原版在回调前扣钱和写解锁，不能只在onUnlock里检查声望。自定义购买由一个服务统一执行，拦截后不得再让原购买路径扣第二次。

执行顺序：

1. 检查升级归属、项目开放状态、关系、未付款、替代方案未成功及重入锁。
2. 获取并记录当前实际报价、wildFavor抵付、现金余额及两区声望。界面提示与点击时校验均使用同一计算方式。
3. 一次校验全部资源，任一不足就提示具体缺口并保持所有值与解锁状态不变。
4. 记录购买事务ID和变更前快照，在同一同步提交中通过原生接口扣抵付、现金、声望并写项目Paid、SelectedPlan、实际支出、ResultPending。P4不得先扣一边再检查另一边。
5. 标记当前购买成功、关闭另一方案、刷新列表和反馈。场景回调只负责排队，不再收钱。
6. 失败恢复到事务开始前状态，释放重入锁；读档遇到未完成事务按日志确定完成或回滚，不能猜测余额后再扣一次。测试保存边界；若引擎不支持可靠回滚，需先解决提交与保存时序，不能带风险发布。

只保存本MOD事务需要的数据，不回滚其他升级或整局经营。双击、重复回调、UI切换与同帧重入都只能成功一次。已付但未看结果是合法状态，加载时恢复ResultPending，不再扣款。

转普通／朋友前明确提示后续挑战关闭、既付支持保留。P1等待反馈继续用无称呼版本交付。若未来在P2～P4加入中途退出入口，需先补完对应无恋爱结果文本，不能让已扣款项目静默消失；当前不新增这些额外退出菜单。

P1的ResultPending不得依赖第18～23章正在运行。第23章后无合适访客，就排独立结果来访；其优先级高于等待短聊，不重播第18章。转普通／朋友也保留交付机会。项目长期未买时仅低频短聊，拟定至少间隔5个游戏日，每段首次播放后轮换，不替代主线结果、不反复催款。

基础奖励第23章发一次；完成进阶不再发香水或增加拾荒协助。原版结局可提前发生，尾声读取实际阶段。未完成24～28不把玩家写成失败，也不冒领归来成果。

## 7. 乙线撤案作为独立世界事件

只对进入本次新分支或从该分支转出的乙线适用，原有未入新线存档不自动追加世界改写。保护转移与研究交付是前置，归来项目无关。

流程：Eligible → ReceiptPending → Submitted → NewsPending → Acquitted。回执演出成功提交时设置SubmittedDay，DueDay=SubmittedDay+7。每日检查DueDay并生成新闻任务；只有成功提交新闻才写Acquitted，避免新闻未出现却提前宣告母亲自由。重复加载不重设DueDay，不能因日期经过就跳过回执。错过目标日照常保留待播。

若提交前已正常退出、不再安排人物来访，使用同一既有新闻通道显示“相关调查材料已正式受理，将继续复核”，作为回执替代并记录日期，不强迫她回来。研究未交付则不凭空生成受理。已提交后转关系或退出不取消客观证据；不再来访时仅播结果新闻，省略私人邀约。

第22、24章按已撤案／待复核换句；第27章同样换母亲出席版本，亮相本身不等撤案。第28章和所有尾声也分别判断。新闻迟于27时补晚到短聊，不重演现场或假称她出席过。

提交后除非新增剧情明确破坏证据，不增加失败骰子或隐藏门槛。现有破坏研究的背叛发生在成功提交前时直接排除；若编码发现存在提交后破坏链，必须写出确定的失败事件与文本再接入，不能停在没有生产者的Pending。具体新闻API与保存字段仍需实现阶段核查。

## 8. 旧停线档承接

本次只自然续接已核对形状的旧800停线，不全局解锁恋爱。候选条件须联合满足：

- 已初始化、受支持版本、全局Schema=2，非OldBlocked。
- Chapter=13、PendingChapter=0、Romance=4、Route=0、BetrayalKind=0、DriveState=0。
- MotherState=0、Savings=800、MotherVisited=false、EpilogueDone=false。
- 无正在进行的保释／拘捕、核心完成或其他终止记录，无新路线状态或迁移标志。

这组字段来自已核对控制流，不是可靠的“曾点击800”专用标志。必须用真实匿名化旧档和对应发布包验证；PendingChapter=13、已排数据盘访客、0.61～0.65已继续推进等情况单列规则，不倒回、不猜测、不清整条访客队列。未知Schema、保留原版、丙丁、背叛与已处置数据盘的档不自动迁移。

迁移步骤：InitializeForSave完成后、任何RomanceLocked早退之前，保存相关原字段快照与候选来源；写Legacy800ResumeState=Pending；仅解除命中档的旧通用锁定；保持原主章13，专门排承接序章。完成序章选择后才写方向及完成标记，下一安全日期接数据盘。中途存读档仍恢复序章，不代选、不跳章。

主从选择写EntryPaymentKind=LegacyWaived、EntryPaidCash=0；普通选择照常恢复原有关系发展。本地旧包未扣800，不能补扣、返款或假记实付；母亲17、莉迪亚21、悲剧与退出段用豁免文本。SavedCash、Savings、声望、物品、吊坠、世界进度与既有奖励均不重置。若以后发现真实扣款旧包，须凭证据另设VerifiedLegacyPaid迁移，不套本豁免规则。

同档反复加载只恢复待办，不再次迁移或重设日期。未命中且疑似停线的档记录诊断原因，待补精确规则；发布说明不保证未知第三方改档全部兼容。
