# 0.77：对白显示与记录的发言归属

2026-11-09。实施对象是已发布0.76后发现的发言归属问题；发布确认见 `RELEASE_0.77.md`。先前假叔叔个案的原因保留在 `ARREST_DIALOGUE_SPEAKERS.md`。

## 查到的问题

原版只把 `PLAYER` 与 `SEC` 识别为特殊发言通道，其他title一律由当前顾客显示并记录，忽略填写的显示姓名。因此仅在数据里写“旁白”“来宾”仍会被算成埃莉诺的台词。

实际通过149种访客/分支组合的构造与原生记录器核对，发现69条不同文本键不符合指定身份：59条旁白，5条晚会来宾/管事对白，3条新闻，2条治安部通知。组合覆盖普通线、侍从线、甲乙路线、丙丁后果、归来、日常、经营和实际晚会；不是全部世界状态的笛卡尔积，也不以静态全文数冒充实际播放数。

| 场景 | 原问题 |
|---|---|
| 假叔叔举报、箱子陷害拘捕 | 治安员的局部显示名不被识别，进入当前顾客通道 |
| 晚会 | 来宾2句、采购行管事3句被记为埃莉诺 |
| 普通线保护手续及救母团聚 | 通知2句、新闻2句进入埃莉诺记录 |
| 普通丙线的母亲遇害报道 | 新闻1句进入埃莉诺记录 |
| 侍从入线、旧伤、工作、称呼、告白、归来、终约及晚会等 | 旁白或动作描述挂在当前人物名下 |

玩家台词本身已使用 `PLAYER`。母亲、莉迪亚、采购商作为独立顾客来访时，他们自己的台词与当前身份匹配；这些场景内的旁白仍需统一处理。只用作报纸正文、结局说明和未引用旧稿的内容不计入上述69条。

## 修复方式

- 治安员使用原版 `SEC`，玩家保留 `PLAYER`。普通对白沿用原有气泡，不新增场景、人物切换或动画。
- MOD的通用对白工厂标记自己创建的节点。显示这类节点时，用节点指定姓名同步更新现有姓名栏和当次历史记录，涵盖旁白、来宾、管事、母亲、莉迪亚、通知和新闻等角色。
- 顾客的 `displayName`、身份、交易和事件对象全程不修改；这既避免其他系统读到错误身份，也避免来宾说完后遗留错误姓名。
- 记录改写仅限当前同步显示调用中、内容完全一致的原生记录。上下文按调用保存/恢复，嵌套外部对白和无关通知不继承角色。原生异常原样继续传递；单独姓名栏更新失败不会打断剧情，且会清理上下文。
- 标记使用弱引用，不阻止旧对白释放。已恢复的历史图仅在顾客来源确认为本MOD、且姓名是本MOD已知角色时提供兼容；其他原版/第三方顾客和任意未知title保持原行为。
- 停用MOD后显示适配不生效，重新启用可处理已有标记。现有历史记录为已存字符串，不猜测重写过去记录；新对白按正确身份入库。

实现：`src/DialogueSpeakers.cs`，接入 `StoryEngine` 通用工厂和少量直接构造节点。界面访问使用游戏自带 `Unity.TextMeshPro`、`UnityEngine.UI` 引用，均不随包复制，不申请新权限。没有改变付款、分红、救母、关系路线、排期或存档schema。

## 验证

- 66组离线回归通过，包括原62组与新增4组，执行原版 `DisplayLine`、姓名记录拼接、去标签、入库，运行实际生产适配。只替换Unity气泡/打字机及姓名栏赋值边界，不手写一个“假原版分发”代替测试。
- 核对中文/英文姓名、实际晚会全段、保护手续、团聚通知和丙线新闻；核对非本MOD隔离、启停、已恢复图、嵌套调用、异常恢复和姓名栏故障兜底。
- 重查149种构造组合，之前69条不同文本键全部按指定身份记录，剩余不符0。
- Release编译0警告0错误；中英各2294键不变；原生扫描无拒绝、错误、额外权限、硬性标记或发现项。

复现工具：`tools/audit_dialogue_speakers.ps1`（可用 `-Managed`、`-ModDll` 指定原版程序集和待验包）。它先运行完整离线回归，再生成 `dist/report-speakers/runtime-audit.json`，列出访客、文本键、期望身份、实际历史与逐条结果。

真实姓名栏布局、气泡位置、完整语言环境和磁盘存读档由用户实机验证。本轮不操作真实游戏界面或玩家存档。
