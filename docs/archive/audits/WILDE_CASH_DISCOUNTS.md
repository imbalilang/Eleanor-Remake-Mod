# 王尔德筹备：单一现金方案与声望优惠

初版实现于2026-11-08；2026-11-09已与垃圾填埋场事件及互动补强一同随0.75发布，见 `RELEASE_0.75.md`。下述分项验证保留当时记录，正式包已通过54组回归。

## 玩家规则

四个项目现在只有四张卡片，每项只显示一个现金购买入口。项目仍按原有剧情节点开放，不提前显示后续内容。

| 项目 | 基准原价 | 自动优惠条件 | 基准优惠价 |
|---|---:|---|---:|
| 安顿 | 1000 | 保持原规则，无额外优惠 | — |
| 通行与正装 | 3000 | 下城区声望≥30 | 1500 |
| 第一单 | 5000 | 上层区声望≥40 | 2500 |
| 自己的事业 | 8000 | 上层区声望≥50，且下城区声望≥50 | 4000 |

后三项把原人脉方案的门槛和半价金额合并进现金方案，取消原来每项10点、两区各10点的声望支出。声望是优惠条件，不是购买条件；未达标时仍可原价付款，不需要选择另一张卡片。只有被指定的派系参与优惠判断，不受无关派系负声望影响。

说明保留一段用途，加入对应声望条件、经当前原版价格修正后的原价→优惠价，以及“当前已享受声望优惠”或“未达标也可按原价办理”。P3/P4保留原有分红说明。难度、原版派系价格特性、开局特性及取整照常适用；王尔德恩惠沿用原版抵付规则。

## 实现与存档

- 新注册只包含四个原 `*_cash` ID。标题直接使用项目名，删除现金／人脉后缀。
- `NetworkUpgrade.GetCost` 的局部前缀只为这四个 ID 选取原价或优惠基准，随后继续执行原版报价。界面和实际付款调用同一入口，每次查询重新核对声望，优惠不会因此前显示过而黏住。
- 付款记录新增 `pN.discount`，保存实际付款时是否享受声望优惠。后续结果对白据此承接人脉帮助，不受之后声望变化影响；未优惠仍接原价筹备对白。声望不会扣除，资源事务、存档延迟和重复扣款保护继续使用原有服务。
- 历史 `*_favor` ID 仅作为兼容数据识别，禁止新购买，不注册定义，保存中的旧行隐藏。已付款改在同项目的现金行显示“已结清”，保留原方案 ID、现金／恩惠／声望支出、付款日期、待交付结果和对白分支，不退款、不重新收费、不重置剧情。
- 全局 schema 仍为2。旧未完成付款事务继续恢复；0.68异常原版解锁修复也覆盖退休的人脉ID，按其旧基准报价处理。
- 筹备期缺钱事件按当前现金报价判断，不再因为玩家声望不达优惠门槛而跳过经营日常。等待短聊改为同一方案的原价／优惠语义，中英文同步。
