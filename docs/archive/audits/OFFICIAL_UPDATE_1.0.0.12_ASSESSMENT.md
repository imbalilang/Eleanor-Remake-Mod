# 官方 1.0.0.12 更新适配评估

核对日期：2026-11-07（北京时间）。以下保留当时的评估与改动建议，0.66 的实施结果见文末。

## 核对依据与范围

- 官方更新：Cumulative Update - 1.0.0.12。Steam News API 时间戳为 1794005714，即北京时间 2026-11-07 06:55:14。
- [Steam 官方公告](https://steamcommunity.com/app/4348910/announcements/detail/1839676055895202)；[Steam 官方新闻 API](https://api.steampowered.com/ISteamNews/GetNewsForApp/v2/?appid=4348910&count=5&maxlength=0&format=json)，对应新闻 gid：1848664643347661。
- 本机安装为 `open_beta` 分支，Steam build 26496118；游戏启动日志中的内部版本仍为 `0.46D`。
- 本机 `Assembly-CSharp.dll` SHA-256：`D9ABC029F6B390619C31175DF5735901AEC6DC071C35C50CE5B3FDF92E3EDE46`。
- 下述具体奖励数值来自本机游戏程序集；公告本身只描述奖励变丰厚。正式分支与本机测试分支的完整一致性尚未验证。
- MOD 当前发布版本：0.65。

## 结论

优先同步谢礼增强、50 信用点援助和保释基准，保留重制版的路线、人物关系和后续章节。保释需要同时修正条件、时序及旧档迁移。

`src/Patches.cs` 在本 MOD 接管后屏蔽原版的三个 Eleanor 调度方法。官方新增的援助、谢礼和保释逻辑不会自动出现在重制剧情中，需要接入本 MOD 的状态机。应继续保留调度隔离，避免原版与重制版重复来访或重复结算。

## 第一批：建议立即适配

### 1. 举报谢礼增强

本机原版 `StoreClientUniqueList` 的 `EleanorWarned` 奖励回调：

| 奖励 | MOD 0.65 | 本机新版原版 | 建议 |
| --- | --- | --- | --- |
| 便携净水器 | 当前耐久 75 | 当前耐久 175 | 举报路径同步为 175 |
| 信息素香水 | 可用 3 次 | 可用 5 次 | 举报路径同步为 5 |

代码位置：`src/EleanorStory.cs`，`CreateWarningChapter`、`GiveWarningGift`。

继续使用已修复的 `GiveToPlayer` 发放及 `WarningGiftGiven` 防重机制。未举报而提醒她的延伸分支可以保留原来的 75/3，清楚区分举报奖励与 MOD 延伸谢礼；本次不改此前决定忽略的“知情”判定问题。

不建议直接修改所有现存净水器或香水：这些是通用物品，无法可靠区分商购物品、已消耗的谢礼和其他来源。新数值优先应用于尚未领取的奖励。

### 2. 困境章节新增 50 信用点援助

官方新增以 50 信用点代替食物的选择。MOD `CreateHardshipChapter` 目前只有交易食物的援助判定，没有现金援助入口。

建议：

- 增加“给她 50 信用点买食物”的选择，与原来的食物援助并存。
- 实际扣款成功后计为同一次援助，获得相同的后续剧情资格与好感反馈。
- 现金援助后直接进入相应收尾，避免没有交易食物却被按“未帮助”结算。
- 保存援助领取状态，防止中断、读档或重试重复扣钱、重复加好感。
- 与原版动态选项条件配合：取出现金后立即恢复可选，不够钱时保持禁用。

### 3. 重整保释条件与时间

| 项目 | MOD 0.65 | 官方新增规则 | 建议 |
| --- | --- | --- | --- |
| 保释通知 | 被捕次日进入救援章 | 被捕 2 天后警官来访 | 按真实被捕日 +2 调度 |
| 普通支付 | 120、300、400、1200 等并行路径 | 支付 500 | 普通保释统一为 500 |
| 声望担保 | 治安部声望 30，仍支付 300 | 治安部声望至少 40，免费担保 | 同步 40/免费 |
| 释放时机 | 当前救援对话直接包含获救衔接 | 本机原版付款后，次日释放回访 | 区分保释已办与释放回访 |
| 旧被捕存档 | 缺独立被捕日期和保释等待状态 | 有旧被捕状态迁移 | 补默认状态，保留剧情进度 |

代码位置：`src/EleanorStory.cs` 的 `CreateRescueChapter`、`AddTrapWatcher`；`src/RomanceState.cs`；`src/StoryDirector.cs`；中英文 UI 文本。

当前无需声望、无需举报记录的 120 信用点普通程序会压倒其他付费路径；增加 500 选项而保留这个选项无法实现官方的新平衡。建议清理重复付费分支，保留“筹钱后再来”。举报证据、黑市关系如要保留，应赋予明确的额外剧情意义。

建议记录被捕日、保释是否已办理及办理日；释放后恢复 `TrapResumeChapter`。等待时长按真实被捕日计算，`旧日回想` 的 11 天提前只影响主线起点，不缩短被捕后的两天。

旧档处理必须区分：

- 已被 MOD 接管且处于被捕状态：补填缺失日期和保释状态，保留章节、好感、库存与母亲/研究状态。可参考原版 `MigrateEleanorBail` 对未知日期的锚定办法，确保不会永远等不到来访。
- 原版已被捕、尚未接管的存档：继续尊重现有“保留原版 / 重置接管”选择。保留原版时允许官方保释继续工作，不能为适配而强制重置。
- 新增字段应有旧档默认值；不需要仅为这些字段提升整体 Schema，导致所有兼容旧档暂停。

## 第二批：设计同步与兼容检查

### 剧情人物可被射杀

官方现已允许射杀大部分剧情人物并终止其剧情。本机原版 Eleanor 设置 `forceShootable`、收枪恢复对话及 `onShotDead` 回调。

MOD 的 Eleanor、母亲、Lydia 等当前统一 `nonShootable = true`。这是设计差异，可以作为后续独立改动。开放射杀时需一并处理 MOD 的死亡/终止状态、已排队访客、后日谈和拾荒协助；只改可射击标志或只写原版 `isEleanorDead`，无法阻止 MOD 次日再次生成角色。母亲或 Lydia 死亡对主线的影响也需明确设计。

### 关键物品防盗

本机原版自补充香水自带 `IMPORTANT_TAG`，MOD 使用其原生工厂，已经继承该保护。

自定义吊坠目前只有 `ER_KEEPSAKE` 标签，建议按重要纪念物补入原生保护并迁移已有吊坠。注意原生 `IMPORTANT_TAG` 同时影响夜盗和抵债回收。上层手工镯是普通可交易商品，不需要一律免盗。数据盘当前通过剧情状态表示，并非实际库存物品，没有同类丢失风险。

### 原生 UI 与购买设置

- 对话点击推进、气泡 50%—150% 缩放：MOD 使用原生 `Dialogue` 和选项接口，优先回归验证，无需另写推进或缩放逻辑。
- 提现后支付选项立即解锁：现有选项已使用动态 `Enabled` 回调，验证救援/援助选择即时刷新即可。
- “购买后移入库存”：交易仍走原版 `MoveDealItemToInventory`，本机实现已检查新设置。验证单件和批发各自遵循开关；礼物仍可维持柜台优先的发放规则。
- `旧日回想` 已提供 `iconKey`，应受益于官方天赋图标修复；核对日历和思维重编程器的图标，无需重新改为独立开局。
- 官方新增剧情的旧档补排机制不要求重写我们的全部日程：MOD 用“到期后可入队”而非严格日期相等判断，已有迟到补排能力。保释日期迁移仍须单独处理。

### 版本与权限

官方发布号 `1.0.0.12` 与本机内部 `Application.version = 0.46D` 是不同标识。当前本机运行不会被 `VersionGate` 拦截，不应仅把允许字符串替换成公告中的版本号。建议在正式分支验证后补齐文档中的发布号、内部版本和已验证 build，继续保留实际接口/流程回归。

官方安全更新说明现有 MOD 不受影响；本轮适配没有新增反射、文件或网络权限的功能需求。

## 建议验收范围

1. 举报/未举报路径、新谢礼数值、满仓重试、读档不重复领取。
2. 食物/50 信用点两种援助、资金不足、对话中提现、援助中断后重试。
3. 被捕日 D、D+2 警官、D+3 释放衔接；普通/提前特性两类周目。
4. 500 支付、40 声望免费担保、暂缓后重来；原版旧被捕档与 MOD 旧被捕档分开验证。
5. 单件/批发、库存移动开关、手动/点击推进、气泡最小/最大尺寸、三类天赋图标入口。
6. 未验证射杀终止状态前，第一批版本维持当前人物射击设置。

建议下一适配版先完成前三项、旧档迁移及原生交互回归，再单独决定射杀分支。

## 0.66 实施结果

- `VanillaEleanorBridge` 在 MOD 被捕期间放行原版 `CheckStoryLineEleanor`；原版生成警官、判断 500/40 条件、扣款并安排次日释放回访。桥接层隔离其他原版 Eleanor 访客，避免两套章节混排。
- 释放回访的原生记账动作与重制章节衔接在对话末尾共同执行。中断时仍可重试，完成后恢复 `TrapResumeChapter`。
- 老 MOD 被捕档调用原版 `MigrateEleanorBail`；原版保留档不改，Schema 仍为 2。
- 50 信用点援助直接复用 `Eleanor4` 的支付动作、资金条件和回应；MOD 保存援助状态，统一后续好感结算，并提供现金援助的收尾台词。
- 谢礼调用 `EleanorWarned` 的原版奖励动作；仅将这次动作的放置交给现有安全发放接口，保留满仓重试。所有现有谢礼分支共享原版奖励定义，不再单独维护耐久/次数。
- 吊坠补原生 `IMPORTANT_TAG`，包含已有物品读档迁移；原版香水保护和普通手镯规则保留。
- 移除了旧的自定义保释实现及 15 个过时 UI 键。角色射击保护维持现状，未引入尚未设计的死亡分支。
- 离线检查调用真实的原版调度、付款条件、奖励动作和旧档迁移，覆盖原/提前周目、支付与免费担保、暂缓/拒绝、重复调度、释放中断、现金不足与提现、满仓和防重；渲染等边界在内存中替换，未修改游戏文件或存档。
- 实机点击、气泡缩放和完整周目仍需验收；正式分支与本机 open_beta 的完整一致性未单独验证。
