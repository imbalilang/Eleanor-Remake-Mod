# NovelWorkFlow 主笔对照与五场试点报告

日期：2026-11-16  
范围：c17、c19、love_a2_01、dv08、v2_r1c1  ；只保存候选，不写入 `Content/`

## 结论

本轮不切换生产默认主笔。`google/gemini-4-argon` 已确认可调用，且在 C19 和 DV08 的同输入候选中更短、输出更稳定；但它没有解决 C19 的 11 句连续，也没有解决革命军第一张单子的 16 句连续。Opus 在 C17 的事实保留较完整，在 DV08 的动作与告白回扣较完整，但更容易扩展结构和分支。现有证据支持“场景输入和结构预算优先于换模型”，不足以支持把 Gemini 设为全局默认。

本轮采用规则：所有实质性改字先留在候选；Super QA 只做最小、可追溯、逐行校验的候选；未生成可应用 patch，不改正文、不改世界书正式文件、不改正式模板、不改路线与结局。

## 运行与凭据记录

- OpenRouter `/models` 返回了 `anthropic/claude-opus-5.5`、`google/gemini-4-argon` 以及各自的 `:batch` 条目；实际试点使用非 batch ID。
- 两个模型使用相同的正式 `writer_system_prompt.md`、正式 `writer_prompt_template.md` 的内容，以及各场隔离 world book/ActCard 副本。差异只在模型 ID和模型响应。
- Responses API：`max_output_tokens=64000`，不发送 `temperature`；每次最多一个请求，不自动重试或 fallback。
- 十次主笔请求均 `completed`。请求体序列化大小为 104,434–119,007 bytes，均低于 20,000,000 bytes；本轮没有接近上限的请求。
- Super QA 采用 DeepSeek `deepseek-v4-pro` 的 JSON 1:1 候选；五次首轮请求及一次 C19 重试均低于 20MB，无自动重试。
- 费用元数据、token、耗时和 response hash 见 `tools/NovelWorkFlow_Eleanor_Test/Test_Output/PILOT_2026-11-16/run_summary.json`；本轮主笔调用记录成本合计约 1.34212（按服务返回的 cost 字段）。报告不保存凭据。

## 事实与结构审读

### c17

两版都保留了索菲娅的看护登记、复核、研究公开、农场工人/班次、八百信用点拾荒来源、日用品 BUY 和四种交易结果。Gemini 增加三项 C1 选择，Opus 只有两项；当前代码和现行场景契约没有授权新增选择，因此两版都只能作观察材料。当前 A 已有足够具体的瓶盖、营养果、报价动作，不进入改写队列。

### c19

两版都保留吊坠、母亲在家、价格历史、拾荒卖货、不是还账、接受/朋友两方向、次日来访和店外等待。两版都没有恢复旧测试中的“慢一点”选项，也没有写入电子元件回扣。Gemini 缩短约六行，但仍出现 11 句连续，说明是场景承担过多回扣的问题。Opus 的 `交易：无` 是合法“无交易”说明的位置错误，应排除；没有产生 Content 补丁。

Super QA 对两处镜像 `c19.b101:13` / `c19.b101_return:13` 提出“就这些。等你回答。”，但模型两次都擅自给其中一处复制 `neutral` 表情；1:1 合同拒绝。最终 C19 保留 A，不采用 B/C。

### love_a2_01

正式代码 `src/LoveStory.cs` 的 `CreateAct2FirstTrade` 使用 `HOUSEHOLD_GOOD`、预算 150，交易后接 `la2_s1_common`。Opus 把预算写成“按代码配置”，Gemini 写成 200，均不能进入候选。Opus 把共同冲突段放进正文，Gemini 放到每个交易结果后；两者都改变了原有客户端边界表达，保留 A。

### dv08

两版均保留莉迪亚因家宴缺席、伤口/搬货、旧衣、挡在前面、母亲、告白、亲吻、离开和三个回应。没有接触 `dv12/dv13`，没有提前三方确认。Gemini 更短，但仍把动作集中在同一段；Opus 更像完整候选但超过 A。Super QA 未发现有证据的最小句子问题，保留 A。

### v2_r1c1

两版均保留母亲死亡并认尸、研究公开、入革命军、采购单、旧衣由埃莉诺决定、SELL TOOL、C1 三选项和 T1 四结果；都把最长 NPC 连续留在 16。主笔没有能力单独解决此问题；需要下一轮只研究“认尸事实是否拆到上一场/把货物对单分成两个来访”，并输出 line map/key remap，不能现在接入。

## 当前主笔判断

| 维度 | Opus | Gemini 4 Argon |
|---|---|---|
| 模型可用性 | 已验证 | 已验证 |
| 事实保留 | C17、DV08 较完整；会扩展说明 | C19 较紧；偶有预算/边界误读 |
| 体量控制 | 更易接近 35–55 行，但常扩展分支和思考 | 倾向更短，C19/DV08 更接近目标 |
| 选择/结构服从 | 会新增选择或结构提案，需严格拒绝 | 也会新增/重排尾部，需严格拒绝 |
| 长连续 | C19=11，革命=16 | C19=11，革命=16 |
| 可作为全局默认 | 暂不变 | 暂不切换；可作关系峰值候选对照 |

决定：继续以 Opus 为生产默认，Gemini 作为高风险关系场景的平行候选模型；下一轮先改复制的 ActCard/场景预算，再做单场调用。任何模型都不能自行决定交易预算、分支数量、状态、路线或结构拆分。

## 下一阶段建议

1. **先改场景输入，不切默认模型。** 复制的 ActCard 应取消“每章必须 35–55 行/总字数 2,000–4,000”的冲突要求，以场景类型预算为准；普通交易 6–11 气泡，关系峰值 8–14，超过时输出拆场提案，不把拆场直接写进正文。
2. **给 v2_r1c1 做一次结构研究。** 只允许提出两个候选：保留认尸在本场但把对单前移；或把认尸事实放上一场、第一张单子只写补给接触。两者都要带 line map、key remap、路线图影响，暂不接入。
3. **C19 维持 A，若要修只用人工批准的 1:1 patch。** “就这些。你看着办。”属于作者已确认的告白节点，不因模型偏好自动替换；如果将来修改，必须同步 b101/b101_return 并锁表情字段。
4. **把交易参数外置为代码事实。** Prompt 只注入已解析的交易声明；模型禁止填写“按代码配置”或猜预算。love_a2_01 的预算必须是 150，且共同尾段只作为现行接口事实，不让模型重新安排客户。
5. **继续保留 Super QA，但将模型输出当材料。** 零改候选就保留 A；出现未授权表情、预算、选择或标签时直接拒绝，不为减少 P2 继续消耗调用。
6. **五场试点后再提交正式模板改造。** 目前已足够证明模板存在长度冲突，但还不足以证明某一模型优于另一模型。正式模板仍不改，待作者确认“ActCard预算优先”的具体方案后再提交 patch。
