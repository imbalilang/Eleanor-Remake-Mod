# 晚会终章：关门邀请与次日留白

2026-11-10。本地0.81开发内容；按用户要求调整侍从线最后一章。本轮只更新项目、编译和离线验证，未部署到游戏、未上传工坊或推送，未读写真实玩家存档。

## 玩家实际流程

1. 归来28完成至少3天后，邀请可用。白天不安排晚会来客，也不显示在顾客队列中。
2. 最后一位客人离开、队列为空，玩家点击关门按钮，埃莉诺才出现。如果最后一位客人的离场动画仍未结束，会先等他走完；无需再点一次关门。
3. 保留她穿礼服来接玩家、拿出请柬、想一起跳舞的邀请对白。答应后只留下填写名字、伸手和“走吧。今晚的时间，归我了。”三句门口收束。
4. 立即进入收店过渡，跳过夜间自由行动，使用游戏原生黑屏和睡眠结算进入次日清晨。没有晚会门厅、来宾、舞池或散场的现场叙述，没有新赴宴费或数值奖励。
5. 次日由原有报纸侧写晚会，后续安全来访仍可有一次读报短回应。原生重要新闻、威胁新闻和母亲复核新闻优先，必要时顺延刊登。
6. 拒绝则她独自赴宴，正常收店，保留夜间自由行动；关系和分红不受影响，不再主动邀请。

现有恋爱／母亲安全资格、归来28的完成要求、3天间隔和E1～E14结局编号保持。晚会不创建额外顾客来强行清空其他客户。

## 实现与存档

- `src/GalaClosing.cs`接管空店时的关门入口，直接呈现邀请；正常营业、仍有顾客、当前来客未结束、外出或原生关门锁等情况下不抢占。只有旧的本MOD晚会916排队项被移除，其他客户保留。
- 答应选择立即持久化已接受状态；门口收束后调用原生`EndAndClose`。等待原生收店回调结束，再调用`EndOfDayUIManager.InitUI`及`OnEndDayButtonClick`，由游戏处理服务费用、库存周期、健康、事件、日期、自动存档和晨间界面，不直接增加日历。
- 旧延期／第二邀请／已预约继续在空店关门时处理；旧已答应状态接门口离开，不再执行旧晚会图。旧完整晚会文本与不用的延期菜单从现行文本源删除。
- 邀请中途读档保留已读行；释放本段自己的关门锁，丢弃旧呈现，下一次关门继续。已答应但未收店续接离开，已收店但未跨夜恢复睡眠，已进入次日不再次跳天。
- 中英文本由Content JSON生成；全剧情TXT／Markdown／HTML、覆盖核对、路线图与维护规则均同步。
