# 文风、玩家台词与非台词表现基准（Probably Stolen 本体）

日期：2026-11-10。修订：批量重构执行版 v3；2026-11-11 追加 v3.1，新增第14节（去AI味执行细则），未改动前文优先级和量化目标。
用途：指导整章文风重构、玩家台词密度、非台词表现和去AI味检查。本次只修订基准，不修改台本、Content、Localization、src 或游戏文件。

## 0. 执行摘要与优先级

目标是贴近原作的短促口语、NPC主动表达与玩家行动反馈，减少访谈式问答和反复解释；不是把扩展剧情削成原作的长度，也不是让玩家失去主动表态。

发生冲突时按以下顺序处理：

1. 用户已确定的剧情目标、世界事实、路线与玩家选择语义。
2. 因果、信息完整性、角色当前成长阶段和实际运行条件。
3. 原作的说话节奏、各角色声音和场景情绪。
4. 玩家台词密度、句长、标签频率等数量目标。

**默认玩家寡言，优先用已有行动与选择表态；删重复解释，不删必需信息。** 超出常规阈值时登记例外，不能靠补NPC废话、机械拆框或抹去承诺来达标。需要改菜单、结构或代码的部分单列待审，不在纯文本批次里擅自处理。

本文是统一文风标准，不覆盖已经确认的路线设计与人设。写作模型先读第3～5、9、11、14节；第14节是从「夏瑾 天琴座 Beta 2.42」预设吸收的去AI味执行细则，与既有规则冲突时按第0节优先级处理。历史统计和表现技术资料用于复核，不作为凑数模板。

- 原作有直接感谢、脆弱求助、半截话和温和告别。“照顾好自己”与“我需要一件武器”都可作结，不强制每场一句硬话。

## 3. 原作文风：七条执行原则

### 3.1 一框一个表达重点

普通对白优先短句。自然的跨框停顿和短复句均可；不为了句长阈值把一个词组切碎，也不为了降低玩家占比增加无意义框数。原作长句可作必要说明，不能把统计分位当成逐句硬禁令。

### 3.2 对话服务当下行动

能由已有交易、价格、还盘、保释或菜单表达的，不再让玩家发问复述。只有实际存在的菜单/行为能承担信息；不能新写一个方括号选项，就假定游戏具备该动作。

### 3.3 删重复复盘，保留必要动机

保留新事实、人物转折、风险说明和决定依据。优先删除已经由场景说明、又被同义总结一次的内容。人物可以说“我必须振作起来”，不必禁止“我意识到”“我想过”；判断其是否推进当前场景，不做词语黑名单。第14.3节的套话清单沿用同一原则：命中只触发审查，不自动判错。

### 3.4 用具体内容承载关系，不凭空造物

原作可由食物、信用点、旧物、数据盘、回礼和武器承载关系；MOD的杯子、饭盒、铭牌等按已确认台本使用。每个具体行为必须区分：真实交易/物品转移、已确定的叙事事实、仅口头提及。不能为显得具体而新增送礼、扣款、查看伤口或同居事实。

### 3.5 结束在合适的位置

交易、请求、留白、道谢、硬话或温和告别都能收尾。删除每场必有的作者总结，不删除完成提示、后续安排或关键结局事实。少用成套的“这笔账”“我记着”“别指望我……”替换所有句子。

### 3.6 自然口语，不刻意制造翻译腔

原文引用保留重复和直译感。新写MOD中文以自然、清楚、符合人物为准；允许停顿、半截话和必要重复，不主动添加病句、粗口或故作生涩。不是越粗糙就越像原作。

### 3.7 角色与成长阶段先于主题

早期偏见、后期感激、嘴硬与脆弱都应有位置。不能让所有人都成了情感顾问，也不能为消除咨询腔把所有人写成冷淡、刻薄或只会报货价。

以上七条是内容原则；生成层面的去AI味检查（两遍法、套话清单、认知边界、结尾反升华）见第14节。

## 4. 角色声音与路线阶段

完整全局人设（含莉迪亚、各路线阶段和视觉阶段）见《埃莉诺与莉迪亚_全局人设基准_2026-11-11.md》；本节保留文风执行口径。

### 4.1 埃莉诺

| 阶段 | 应保留 | 不应倒退或抹去 |
|---|---|---|
| 刚落难 | 高傲、急躁、迁怒、自怜、直接的阶级偏见 | 不强行温柔或提前自省 |
| 开始自立 | 实际筹款、求助、难堪、直接感谢，仍可嘴硬 | 不要求每次道谢都绕成“记账” |
| 接受新生活 | 感谢更直接，能肯定下层社区，自己作决定 | 不重新恢复已克服的阶级羞辱 |
| 恋爱/侍从/双恋 | 各路线已确定的亲密、称呼、占有欲和主动选择 | 不用统一冷淡口吻抹掉路线差异 |
| 母亲死亡/危机 | 悲伤、行动目标、克制或失控依情境成立 | 不为口语化加玩笑，不删关键代价 |

多用具体陈述、请求、反问和短祈使句；少重复抽象关系分析。但“喜欢”“愿意”“不愿意”“我答应”等明确表态在关键节点应保留，不用身体动作含混替代。

### 4.2 莉迪亚

以已确认v0.4和用户偏好的大家闺秀气质为准：爱漂亮、热心、嘴快、喜欢浪漫故事和替朋友出主意，有一点小虚荣；自己的感情反而拿不定主意。懂上层生活，不等于职业经纪人；有推荐分量，不等于能包办司法或工作。

可以调侃、嘴硬、热心过头；不以“轻佻、精明、情场老练”为默认声音。普通友情与双恋心动按真实关系分支区别，不能全局添加暗恋。

### 4.3 玩家与配角

玩家寡言、务实，可有冷幽默；不当访谈者，也不成为没有意愿、由NPC替他作决定的人。

母亲温和但有脾气；其他人物按已确认身份和阶段。原作乔治奥的第三人称自夸、伦警官的公务转生活琐事、塞尔皮科的认真天真、卢的危险调侃是声音差异参照，不应互相套用。没有依据不新增口音或固定口头禅。

## 5. 玩家台词与隐含回应

### 5.1 原作与扩展的关系

对照稿没有玩家自由对白，但有行动提示、菜单、交易和既定交往。沉默的是自由接话，不是玩家的选择和贡献。扩展新增恋爱、侍从及三方讨论，允许必要的主动表态，不要求照搬原作0条的绝对结果。

### 5.2 计数口径

玩家台词密度 = 同一实际路径上玩家对白行数 ÷ 全部角色对白行数。旁白、系统提示不计分母；菜单与行动提示不计玩家自由对白，但必须另列数量和含义。多角色同场计全部实际发言；互斥分支不相加。

一行按数据中一个对白节点计，不按标点拆句。路径必须包含该次来访的共同块、所选分支和条件追加。改写前后均报告角色行数、可见字数及关键事件；不能只报告密度。

### 5.3 常规目标与审查阈值

| 项目 | 常规目标/上限 | 超出时处理 |
|---|---|---|
| 共同/普通章 | 默认0句，通常不超过3句玩家对白 | 登记剧情必要性 |
| 新路线章 | 目标0%～8%，通常不超过5句 | 关键表态例外单列 |
| 实际路径密度 | 常规不超过15% | 不自动删稿；先审信息与短路径因素 |
| 普通block | 默认0，必要例外通常1句、最多2句 | 不每块补一句，避免对称问答 |
| 玩家问句 | 共同/普通≤1句，新路线≤2句/章 | 删除纯粹接力式访谈；必要问题登记 |
| 连续玩家发言 | 不超过2行 | 先查能否自然合并，不破坏语义 |
| 玩家单行长度 | 目标≤10字，常规≤20字 | 选择承诺等必要长句可登记 |

这些上限是批量审查阈值，不是删除关键剧情的授权。超过时保留候选并标待审，不在未批准情况下自行应用。严禁扩写NPC、拆碎NPC框或把玩家发言搬进旁白/NPC引用来刷低占比。

### 5.4 例外登记与信息保全

每条必要玩家对白记录：block/位置、作用、是否被既有菜单完整表达、删除后的信息损失、路径总数与密度。典型必要作用包括主动告白、拒绝、三方承诺、关键调查结论和影响NPC判断的实质说明。

没有登记理由的玩家行先标待审；不得一律删除。菜单完整表达的重复回显可删，但先查代码是否跳首句。新增菜单、修改选项实际含义或新增行为都属于结构/机制改动，另列申请。

### 5.5 隐含回应分类

**A：有明确依据。** 已完成交易、真实菜单/行动提示、确实播放过的承诺或事实。注明触发源。原作“你说得对”接在交盘/公开选择后可用，“你提醒了我”接在警告行动后可用。

请求、指令、自发判断、修辞反问不自动算隐含回应。例如“轻点。那瓶盖子松”可以是事前提醒，而非宣称玩家已经拿瓶。“价签？”可为她自己看见价签的反应；若当前场景无法支持，改成自足陈述。

**B：低风险的概括性交往或弱触发反应。** 如原作“我们上次交谈之后”，可由既有会面支撑，而不必捏造逐字玩家对白。弱动作须符合当前UI/上下文，不承担鉴定结论、承诺或关键选择。

- 默认0；单章最多1条，大场景最多2条须单列批准。
- 共同/普通线累计审查阈值5条，每条新路线8条；按实际路径统计，超出标待审。
- 登记block/位置、支持事实、为何保留及本章次数。不能只因scene写“检视时”就认定程序已经发生检视。
- 同一情绪点不叠加隐含动作、斜体和动画；不同位置不因本章有一次叹气就彼此禁用。默认肖像和Idle浮动不算额外表现。

**C：缺乏前因的具体引用、事实或读心。** 必须改写或标阻塞，不得宣称已通过：

- 玩家未解释过，却说“你刚才说的折旧呢”“你每一样都说清楚了”。
- 只是公平交易，却推断玩家坚持赠送、鉴定真伪或逐件说明。
- 只有查看UI，却说玩家闻过香水、认出出处；查看≠闻香≠识货。
- 没有相应状态却说“你答应过”“这盏灯我收下了”。

删去“对吧”“我知道”不会自动把C变A。检查整段：NPC的新判断是从哪来的？本路径是否真的提供过？源台词删了以后，后续是否还依赖它？

## 7. 中文、句长与统计规则

普通NPC对白参考：平均15～19字，90%不超过26字；常规单框≤40字，必要信息/情绪高潮可到55字，超过40字每章通常不超过2框。属于审查目标，不凌驾于完整表达。

原作每框句数约1.18，作为节奏参照；一框一个表达重点，自然的短复句与跨框半句都允许。不得用强拆降低平均句长。

新统计统一用去除富文本标签后的可见字符数：计标点、数字及正文星号，不计换行和空格；占位符按原token计数，并说明它不代表实际替换后的宽度。旧统计没有相同口径证明时不得直接比较。英文单独检查语义与实际气泡排版，不套中文20字符上限。

中文与英文源同时列出；只产中文候选时明确标“英文待同步”，不能称完成。保留占位符的索引/类型/数量、转义、标签闭合和运行时专有名词。台词里的金额、剩余天数、人物去向、母亲状态不能为了简短改义。

## 8. 场景功能与信息量

每场先列：人物带着什么目的来、玩家实际能做什么、产生什么新事实/情绪转折、离场后留下什么后果。可减少重复问答，不减少这些必需作用。

每项信息记录来源、改后位置、触发依据及删改原因。关键情感推进同样是信息，不能只保留数值和任务。剧情体量按实际路径统计，明确共同复用、新增、互斥和可选日常；不要拿所有分支总行数宣称单周目体量，也不为保持句数补废话。

没有台词的反应是可选手段，不是每场必填一项。已有动作提示有信息功能时先找承载位置；不能把所有动作机械改成NPC自述“我正在……”或一律删除。

## 9. 整章改写与运行保护

### 9.1 可改范围

以完整场景和实际路径为单位，可以增删对白、调整措辞和自然分框；block ID、scene、label、分支、选项、数值效果与已定事件顺序保持不变。改结构、菜单或玩法时单列待审方案。批量模型只产候选，不写入运行目录。

### 9.2 必须先查的调用约束

- `StoryEngine.BuildSkipFirst`从索引1开始播放；当前c14、c19、c22部分分支在使用。删除旧首句后，新的NPC首句可能被继续跳过。标记保护行；需要配套代码调整时列阻塞，不直接覆盖。
- 检查其他按行号、直接文本键、BuildFrom或动态拼接的调用，不假设只有上述几个块。
- 共享块列全部调用路线与条件，尤其m23_b006；按每条调用路径检查事实与语气。
- 选项回显与菜单含义一致，不能删掉拒绝、代价或同意的一方，也不能让NPC提前认定成交。
- 来访前、交易中、成交后、离店时分别标记；scene/label是元数据，不必然生成对应行为。
- 生成键、中文、英文及相关检查按稳定来源一并更新；不得手改单个生成文件掩盖源数据差异。

### 9.3 不能伪造的事实

价格公平≠已解释估价；看过物品≠鉴定过；给优惠≠坚持赠送；有过来访≠说过某句承诺；出现纸/食物的对白≠自动产生物品；恋爱确认≠业务成功；普通共同收束≠所有世界状态都相同。

## 13. 体量、留白与删章

### 13.1 当前体量判断

当前 MOD 全部故事为 **38,611 汉字 / 2,391 行**（全分支），原作全作为 **30,199 汉字 / 2,544 行**；MOD 核心 `story_v06` 为 **12,607 汉字**。这不是“3.8 万个人线对 3 万全作”，但体量已经足够大，后续不应再按当前密度自然膨胀。

分路线参考：共同+普通 10,187；侍从 15,933；双恋/后宫 8,861；革命军 1,269；丙/丁/尾声/互动合计约 2,361 汉字（详见 [`文本体量统计_2026-11-10.md`](文本体量统计_2026-11-10.md)）。

### 13.2 写作方向：少字、留白

1. **用少量文字表达信息。** 一句能说清就不铺陈；删同义反复、重复解释和总结句。
2. **适当留白。** 不必回应每一句，不必解释每个动作，不必每场都落到关系结论；允许停在硬话、交易结果或沉默上。
3. **短不等于碎。** 不机械拆句；自然的短复句、跨框半句都允许。目标是有信息密度的短，不是形式上的碎片。
4. **留白不等于偷信息。** 关键事实、选择、承诺、伏笔、物品、数值和关系阶段必须保全；删的是重复表达，不是必要信息。
5. 不为凑效果加斜体、动画或动作；默认纯台词。

### 13.3 体量预算

- 全 MOD 全分支目标：**50k–55k 汉字**左右封顶；当前 38.6k，两条未完成线按 **6k–8k/线**预留。
- 单周目目标：**12k–18k 汉字**；需按实际路径统计后再定，不能拿全分支总数冒充单周目。
- 现有文本优先做 **10%–15% 的重复/解释压缩**，不是砍路线。
- 革命军线当前仅 1.3k，若属于未完成线，应优先补足，不要从别处砍掉它的预算。

### 13.4 纯过渡章的删章规则

文风修改中发现某章只是纯过渡，且**同时满足**以下条件时，可以考虑直接删除：

1. 没有独特的体验：没有新的关系推进、角色声音、氛围或情绪转折；只是把已知信息再说一遍。
2. 没有关键信息：没有必须保留的事实、伏笔、回收、物品、数值、状态、选择、路线或结局条件。
3. 没有唯一分支后果：删掉后不影响任何选项、路线、结局、菜单、共享块或旧档兼容。
4. 必要信息已在相邻章节存在，或能用更少的文字并入前后场景。

操作要求：

- 在修订稿中标记“**删除候选**”，写明章节/block、删除理由、必要信息的去向、受影响的引用和替代方案。
- **优先合并，其次删除。** 能并入相邻场景并减少文字量时，不单独保留新章。
- 删除前检查路线图、E1–E14 编号、选项引用、共享块、跳首句、旧档兼容和双画风；需要同步更新路线图与维护文档。
- 试改稿阶段可直接不写该章；正式写入 `Content/*.json` 前仍需作为结构性改动确认，不能悄悄删掉引用或结局编号。
- 安静不等于无效：如果“安静/留白”本身是这一章的唯一体验，不要因为对话少就删。

**结论：后续修改优先“少字、准确、留白”，其次才是新增路线；纯过渡章可以删，但必须保全信息并留出结构恢复依据。**

## 14. 去AI味执行细则（吸收自「夏瑾 天琴座 Beta 2.42」预设）

前几轮修订主要在删长度、重复解释和玩家台词。仍被反馈“AI味”，剩下的问题多半不在信息量，而在生成痕迹：模型第一遍写出的最顺版本被直接采用；所有角色都像知道全部前因；动作写完后再补一句解释；情绪靠现成意象和生理套话；每场都收束成一句意义总结。预设的有效之处，是把这些问题拆成可检查的负约束，再用“先模拟、再改写”把第一版套话丢掉。

预设本身是酒馆角色扮演/小说生成配置，不能整包套用到分支游戏台本。下面只收可迁移的写法；与既有规则冲突时，按第0节优先级处理。

### 14.1 预设的机制拆解

预设分三层工作：

| 层 | 预设里的做法 | 作用 |
|---|---|---|
| 常驻规则 | 角色分工（模型是协作者，不是角色）、有限视角、角色认知边界、白描、对白分离、结尾落在可见行动、反机械重复 | 定住“谁在写、谁不知道什么、情绪怎么落地” |
| 开关规则 | 禁词表、反八股、活人感对白、白描基调、文风重置、抗升华、抗机器人 | 按题材和模型加硬约束；本案主要吸收这一层的负约束和两遍法 |
| 正则后处理 | 直接删除“突然/忽然/一丝/一抹/弧度/指节发白/语气像……”等；中文破折号改逗号；删除元标签和摘要 | 把提示词管不住的残留套话做确定性清理 |

可直接迁移的结论有六条：

1. **先写最顺的版本，再按人物和场景重写。** 第一遍只用来暴露套话和找方向，不进入候选稿。
2. **角色只知道他能知道的事。** 反应必须能追到本路径的所见、所闻或被告知；不写全知解说。
3. **用动作、物件、价格、流程承载情绪。** 动作之后不再补“这个动作说明……”。
4. **台词要像这个人在这个阶段会说的话。** 允许语塞、岔开、说反话、说一半；不追求每句完整礼貌。
5. **套话用清单查，不靠“写得更文学”。** 命中后先判断有没有具体信息，没有就换成场景里的具体物。
6. **结尾停在具体处。** 动作、交易结果、一句硬话或沉默；不写主题总结和情感升华。

预设里的 NSFW、舒适向、字数模板、破限和角色扮演承诺不进入本基线，理由见14.7。

### 14.2 两遍法：先模拟，再改写

预设的“活人感对白”要求先写一段“模拟对白”，再改写成更有日常感和背景感的正文；“反八股”要求先写带套话的“模拟描写”，再换掉意象。这个机制可以离线使用：

**对白两遍法**

1. 第一遍写“最符合人物和场景”的完整台词，允许书面、完整、信息饱和。
2. 第二遍只保留语义和目的，换成这个人物在此时会说的说法：可能短、可能岔开、可能答非所问、可能把真话藏在反话里。
3. 删掉书面连接词（然而、因此、与此同时）、总结对方感受的句子、每句都工整的排比。
4. 检查：这句换给莉迪亚或母亲是否也成立？成立就重写，直到只有当前角色、当前阶段会说。
5. 区分人物优先用称呼、自称、断句和回避的词；口癖只能来自已确认人设（与14.3补充口径一致）。
6. 留出潜台词：角色说出口的话可以回避、否认或绕开真正想要的东西；不用旁白替他说破。

**描写两遍法**

1. 第一遍可以故意写出最容易出现的套话，例如“她眼底闪过一丝复杂的情绪，指尖微微发白”。
2. 第二遍把情绪落到具体动作、物件、价格、流程或环境反应上。例：她把价签翻过去，又翻回来；杯底在柜台上磕了一声；她把那袋营养果推回去半寸。
3. 第一遍的套话不留在正文，也不要作为“润色前”的参考反复回看，避免被它锚定。

示例只用于说明方法，不是已批准台本。

### 14.3 高风险AI套话清单

下表是审查触发词，不是全局禁词。与3.3一致：先看它有没有承载不可替代的具体信息；有具体语境可以保留，只是默认装饰就改写。

| 类别 | 常见形态 | 改写方向 |
|---|---|---|
| 身体/生理套话 | 喉结滚动、锁骨、肩胛骨、指节发白、指尖泛白、睫毛轻颤、眼底闪过、嘴角勾起弧度、扯出一个笑、身体一僵、后退半步、深吸一口气、攥紧拳头 | 换成这个人物在这个场景里实际会做的动作；优先与货物、钱、门、杯子、衣服、账本等场景物件互动 |
| 空转修饰 | 突然、忽然、微微、缓缓、轻轻、淡淡、一丝、一抹、一缕、一阵、一种、不容置疑、不易察觉、微不可查、几不可闻 | 先删掉再读；多数不损失信息。需要程度时用具体动作或可核对的量，不用形容词堆 |
| 解释性同位与后释 | 这个动作、这个反应、这个认知、这个笑容；她这么做，是因为……；这句话像……；语气里带着…… | 删掉解释，保留动作和台词；让前后文自己说明 |
| 伪深刻句式 | 不是X，是Y；与其说X，不如说Y；不是不X，只是Y；有些X，一旦Y，就Z；仿佛/像是…… | 叙述中默认改写；只有角色真的在纠正一个具体误解时才保留 |
| 比喻滥用 | 石子入湖/涟漪、拉满的弓/弓弦、闪电击中、潮水、藤蔓、刀割、蜜糖、光与影 | 少用比喻；要用就用本场景独有、与人物经验相关的喻体；不用解释性比喻 |
| 对白腔 | “你是说……”式复述、总结对方感受、每句都完整礼貌、金句收尾、大量“……”开头、然而/因此/与此同时、精确数值和学术术语 | 让台词有目的、有遮掩、有停顿；允许不完整；日常对话不堆数值和术语 |
| 动作/转场套话 | 空气安静了一瞬、时间仿佛静止、不知过了多久、与此同时、另一边 | 用具体时间、地点、动作转场；没有过程就不转场 |
| 结尾升华 | 这一刻她终于明白；也许这就是……；未来还很长；某种东西改变了 | 停在动作、交易结果、一句硬话或沉默上 |

补充口径：

- 原作已有并有效的表达（省略号、傲娇反问、账本比喻等）不因本节一律清除；按3.3和既有审读结论，放在有效位置，避免每场重复。
- 口癖和口头禅只能来自已确认的人设或原作依据；不为“活人感”临时发明。
- 语塞、答非所问、说反话是人物策略，不是语法错误；不为了去AI味故意写病句、粗口或碎裂句。
- 中文破折号可以用，但不要用“——”来制造停顿和转折；预设的正则会把它直接改成逗号。连续使用破折号是常见AI腔。

### 14.4 NPC认知边界与信息差

本节与5.5的C类检查配合使用。

1. 写NPC反应前，先列三件事：本路径中他亲眼看到什么、亲耳听到什么、被谁告知什么。反应只能建立在这三类信息上。
2. 玩家没有说过的承诺、没有做过的动作、没有发生的交易，不能进入NPC的判断。需要时改成自足陈述，或补一个可信的信息传递动作（看见、听见、别人转告）。
3. 允许角色不知道、误解、试探、隐瞒。信息差是对话动力；不要让所有角色都变成全知解说员。
4. 不写元词汇、不剧透、不打破第四面墙；旁白只做短动作和场景提示（与10.1一致）。
5. 一场有实质对白的场景至少有一次信息、态度或关系的变化；没有变化的往返问答删掉一轮。

### 14.5 节奏、结尾与留白

- 关系与情节按阶段保守推进：不擅自转场、不引入未设定的新角色或新冲突、不让主要角色无理由离场；转场要有过程，关系升级要有代价和铺垫。
- 结尾优先落在可见动作、交易结果、一句台词或沉默上；内心独白结尾只在它是本章真实落点时使用，不能用来总结主题。
- 不写“这一刻她终于明白”“也许这就是……”“未来还很长”式升华；不把场景意义提炼成金句。
- 情绪要有张弛：紧张之后可以落到具体事务或日常，温馨之后可以出现小裂缝；转折由人物选择或实际事件推动，不靠作者宣布。
- 短句必须有信息或情绪功能；连续的“嗯/哦/好”不是留白，是空转。留白是删掉可推断的解释，不是删掉信息。

### 14.6 重复与风格漂移

- 每章动笔前登记已用意象、动作、句式、称呼变化和收束方式。强意象只给关键节点，不用在普通段落。
- 同一章内不连续使用同一动作、比喻或句式；相邻章不重复同一个金句结构。
- 每批改写从本基准和原作对照稿出发，不把上一版AI稿当风格样本。预设的“重置文风”原则适用：前文风格错误不继承。
- 完稿后朗读一遍，检查句首重复、段落节奏，以及每段是否都在解释同一件事。

### 14.7 不吸收的内容

| 预设内容 | 不吸收的原因 |
|---|---|
| NSFW/舒适向规则：“角色总是享受”“不谈负面感受”“避免绝望/极端”等 | 与本作的阶级冲突、丧亲、危险和失败可能冲突；不能为了“好读”抹掉代价 |
| 硬正则删除“而是/突然/一抹”等 | 可能删掉必要语义和正确否定；本项目只做人工审查触发 |
| 字数/段落模板：“每回复不少于1000字”“长对白”“每段至少20字” | 与第7、13节的短句、留白和体量预算冲突 |
| 格式/人称：“对白省略发言人”“必须第三人称” | 受游戏引擎、现有文本格式和POV约束；不改变运行格式 |
| 自由间接引语式大段内心戏 | 本作旁白只承担短动作/场景提示；内心信息改由台词、动作和既有选择表达 |
| 角色扮演承诺：“用户欲望必须被满足”“主要角色不得离开” | 本作有离场、死亡、逮捕和拒绝；不采用 |
| 精确数字禁令 | 游戏事实中的价格、天数、金额必须准确；只避免在散文里堆砌无意义的精确数字 |

### 14.8 提交前自检

1. 删掉解释动作含义的句子，场景是否仍然成立？
2. 每句台词是否只有这个角色、这个阶段、这个关系下才会说？换给莉迪亚或母亲是否也成立？
3. 本章命中的高频套话是否都有具体语境支撑？
4. 结尾是否停在动作、结果、台词或留白，而不是主题总结？
5. NPC的反应是否有本路径的触发依据？有没有把玩家没说过的话安到他头上？
6. 同一意象、动作或句式是否在本章或相邻章重复？
7. 遮住说话人，能否分辨是谁在说？
8. 是否为了去AI味故意加病句、粗口或碎裂句？（不应）
9. 朗读一遍，是否像人在说话，而不是在写作文？
