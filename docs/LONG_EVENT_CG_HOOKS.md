# 长对白事件与中场 CG 挂点清单

> 用途：找出在当前主线中“连续对白过长、缺少视觉断点”的场景，并给出可用的中场 CG 方案。
>
> 本文件只做设计盘点，不改变正文、路线、对话或资源；具体实现要另行确认。
>
> **地点、站位、服装与投放类别以[地点与投放规划](CG_LOCATION_AND_PLACEMENT_PLAN.md)为准。** 人物、背景画法与验收以[非结局 CG 美术规范](../Art/SCENE_CG_STYLE.md)为准。本文件只负责“哪些长场景需要视觉断点”和“插在哪里”。

## 统计口径

- 数据来自 `Content/*.json` 的主文块；分支块和选项后续未逐条重复计入。
- “连续对白”按单个块的行数估算；行数包含对白和旁白，但按玩家一次看到的连续文本计算。
- 经验阈值：
  - **高**：单块 ≥ 30 行，或 ≥ 45 行且几乎没有选择/动作断点。
  - **中**：单块 20–29 行，或总行数高但中间有交易/选择。
  - 低：短场景或已有 CG/明显动作断点。

## 场景层级与镜头多样性

窗口是主舞台，但不应该是唯一的 CG 镜头。所有 CG 都做成“玩家从柜台后向外看”会让构图重复，也无法表现全身、坐卧和更近的亲密。

### 四层空间

1. **窗口／柜台（默认）**：正常交易和来访。玩家在内，来访者在外；卷帘、柜台、秤、价签、灯是前景。
2. **店铺周边（仍属营业／店务）**：窗外街面、门楣、台阶、卷帘、展示柜、柜台外沿。可以用第三人称、侧后方、低角度、从街上看店内等镜头，展示她坐着、蹲下、倚靠、整理货物和全身衣物。她仍然在窗外，玩家仍然在窗内。
3. **打烊后的店铺生活区／后间（或游戏已有的 home / after-hours 场景）**：关门、灯暗、时间跳过后，用于拥抱、接吻、坐卧、躺姿、换下湿衣、包扎、休息等更私密的时刻。它属于 off-screen daily life / home scene，不是新的可探索空间，也不是普通顾客来访。
4. **少量场外特殊事件**：晚会、澡堂、上层区活动、节日、后宫“买下的一天”等。由剧情一次性触发，有明确转场和理由；不做每晚可选的约会菜单。

### 镜头

- 不必永远使用玩家 POV。可以用第三人称、从窗外看店内、侧后方、低角度、俯视、展示柜反光等，让她和玩家同时入镜。
- 正常营业来访仍必须遵守站位：她在外、玩家在内。不要为了构图把她放进柜台内侧、玩家身后或店内。
- 打烊后／后间是另一类场景，要有明确转场（关门、灯暗、时间跳过）；不能伪装成一次普通交易。
- 性吸引力可以来自全身构图、坐姿、蹲姿、腰臀线和衣料，但姿态要有角色动机和表情，不把她摆成无意识的展示品。

### 可用的 CG 类型

- **窗口全身／姿态 CG**：她坐在窗沿外、蹲下整理货物、趴在柜沿、侧后方看柜台；展示腿、腰、服装和距离。
- **打烊后插入 CG**：后间/住处的坐姿、卧姿、躺姿、包扎、换下湿衣、拥抱、接吻；用 `ShowStoryScene` 或短过场，2–5 行文字，不新增系统。
- **场外特殊 CG**：晚会、澡堂、上层区房间等；每路线少量，一次性的剧情事件，不是约会菜单。
- **已有 CG**：停水《夜路》、晚会、革命军拥抱、后宫约会、结局 CG 继续保留，不重复加。

## 落地方式：四种容器，不要硬塞进日常层

### 1. CG 插入（主线，少量）

把 CG 当成**插入式演出**，不是完整场景：

- 主线仍然在窗口里进行；对白到某一刻，她可以说“你出来一下”。
- 这时调用 `EndingPageUI.ShowStoryScene(titleKey, cgKey, textKey, onContinue)`：全屏 CG + 1–3 行短文字，镜头可以短暂离开窗口。
- 继续后只加一句过渡：“等你回到窗口，她已经把价签摆正了”，或者直接结束这次来访，进入关门/次日。
- 不需要新建室外场景、不需要室外对白树、不需要玩家自由移动；等于视觉小说里的 CG 插入。
- 主线只放少量高价值 CG（袭击、求婚、手镯、合同、第一张单子）；一次来访最多一张。

**示例**：窗口对话中埃莉诺说“你出来一下。” → 《墙外》CG：她把玩家按在当铺外墙亲吻 → 继续后：“你回到窗口时，她正低头把袋口重新折好。” 主线的下一句仍然可以在窗口发生。

### 2. 日常事件层（只放当铺周边，不放私密/场外）

日常层不能承担水族馆、摩天轮、内衣/睡裙/泳衣和闭店后的室内 CG。它天生有两个限制：后面可能还有客人；白天仍在营业。硬塞会破坏“我是当铺老板”的前提。

日常层只承载当铺周边内容：

- 由路线状态和日期触发，不是玩家每天从菜单里选“去约会”。
- 复用现有日常来访流程（如 `DualDaily`、`MaidReturnStory`、革命军日常的同类结构），每次 4–10 行、0–1 个选择、最多一张 CG。
- 只能是窗口来访、窗外小过场、营业时间内的店外动作；不进入后间私密场景，不离开当铺。
- 用来承载服装、窗沿坐姿、蹲姿、营业中的互动；不放泳装、睡裙、内衣、躺姿和接吻。

### 3. 闭店私密插入（夜间行动之后、睡眠之前）

用于当铺外或已成立住处的私密 CG：

- **默认放在玩家完成当晚自由行动之后、睡眠结算之前**：先去拾荒/补给站，回到当铺，再触发私密事件。这样不会删掉夜间收益，也不会出现“从埃莉诺家回来再去拾荒”的倒错。
- **空间现实**：当铺是售卖亭，没有里间、床、沙发、书桌或浴室；玩家只有柜台旁的地铺。不要把“后间”当成既有空间。
- 现有空间能承载的私密 CG 只有：
  - 当铺外墙面、窗沿、台阶、巷口（玩家打烊后可以离店，但仍在店外）；
  - 室内私密场景用**埃莉诺的房间**（配给站对面的小房间）或剧情已建立的场外地点。家具按该地点已有依据使用。
- 因此有两种自洽写法：
  - **A. 她来当铺（默认）**：她敲窗或在窗外等。相拥等动作放在玩家从当铺出来之后，两人都在窗沿、外墙面、台阶或巷口。她离开后，玩家回柜台旁的地铺。
  - **B. 去她家（过夜变体）**：夜间行动后她邀请 → 短离开/黑屏 → CG → 次日先播一句“开门前你从埃莉诺那边回到当铺”或短暂回店过渡，再进入当铺日常。只用于少数过夜章节，不能默认让玩家去她家后又在当铺醒来而不交代。
- 如果确实想在当铺内部获得床/沙发/浴室空间，那是**明确的空间/经营升级设定**，需要单独授权，不能由 Agent 假设一个里间。
- 由路线里程碑或当天事件触发，不是每晚固定活动；不出现“今晚去不去约会”的菜单。
- 4–8 行短场景 + 一张 CG；不新增可探索空间，不新增 UI。
- 承载睡裙、内衣、躺姿、坐卧、拥抱、接吻、包扎、休息等私密内容。
- 用现有 `EndAndClose`/黑幕/睡眠流程；这是“打烊后的最后一段”，不是新的日常系统。
- 实现上优先用现有 `ModHook.OnGoingSleepEarly` / `OnGoingSleepLate`：夜间拾荒、补给和结算都完成后，睡眠前触发；不需要新 UI。
- **不要放在夜间行动之前**，否则玩家为了收菜/拾荒必须在私密事件后离店，逻辑和节奏都会别扭。

### 4. 店休外出章节（Galgame 式约会，少量）

水族馆、摩天轮、澡堂、上层区夜晚这类场景，必须承认它们不能塞进当铺日常：

- 做成**一次性的店休章节**：门口挂“今日店休”，玩家和埃莉诺外出；当天没有营业，也就没有“其他客人”的问题。
- 线性短章节，2–4 个场景 + CG；可以有一个或两个选择，不做自由移动、地图或约会菜单。
- 由路线阶段/里程碑触发；每条路线 1–2 次，不要变成每天可选的约会系统。
- **白天/傍晚外出，晚上回到当铺**，夜间拾荒和补给仍然可做；不要默认让店休章节吞掉夜间行动收益。店休/回店分别接现有 `BeginDay`、`EndAndClose` 或睡眠流程，不新建日程系统。
- 只有明确写成“过夜/留宿”的章节才跳过当晚行动；这种过夜事件每路线最多一次，并要作为阶段高潮，不是常规日程。
- 场景背景和 CG 可以独立制作；玩法仍是原生对话/选择，不新增核心系统。
- 这是对当铺主循环的**例外**，不是替代；店休结束后回到当铺。

### 选择标准

| 需求 | 用哪种 |
|---|---|
| 主线拐点、必须和当前事件因果绑定 | CG 插入（1–2 句过渡，不改写整场） |
| 营业中的服装、窗沿坐姿、蹲姿、日常回访 | 日常事件层（短事件 + 一张 CG） |
| 睡裙、内衣、躺姿、接吻、闭店后的室内场景 | 闭店私密插入（当日最后一场） |
| 水族馆、摩天轮、澡堂、泳装、场外约会 | 店休外出章节（一次性、线性、少量） |
| 长对白只是节奏拖沓 | 先加动作/交易断点；必要时才用 CG 插入 |

### 内容预算

- 日常层：数量最多，成本最低，只做当铺周边。
- 闭店私密：每条路线每个阶段 1 次左右，用于高价值私密 CG。
- 店休外出：每条路线 1–2 次，作为阶段高潮；需要独立背景和 CG，成本最高。
- 不要把大量私密/场外 CG 全塞进日常层；这不是文案问题，是容器不匹配。

## 姿态 CG 的场景示例

| 想要的画面 | 场景 | 镜头 | 触发 |
|---|---|---|---|
| 腿部、腰臀线、坐姿 | 《窗沿》：她坐在窗外窗沿上，腿垂在街面一侧 | 从店内/侧后方/低角度，第三人称 | 一次普通来访结束后，她不肯马上走 |
| 蹲姿、整理货物 | 《拣货》：她在窗外蹲下分拣纸箱和旧货 | 从店内俯看或侧看 | 正常交易中的动作断点 |
| 拥抱、接吻 | 《卷帘半下》：打烊后她停在窗口，玩家把卷帘放下一半 | 侧面/窗外看两人，近景 | 打烊后，剧情里程碑 |
| 卧姿、躺姿、休息 | 《她的房间》：埃莉诺的住处，床/椅子/小桌 | 第三人称全身/中景，非露骨 | 过夜变体，次日回店过渡 |
| 坐姿、换下湿衣 | 《雨留》：在她的房间避雨，衣物和家具按场景核对 | 中景/侧后方 | 天气事件后，按已安排的住处过渡 |
| 晚会后的礼服 | 《晚会后》：她从上层区活动回来，礼服还没换 | 店外窗沿或台阶，第三人称 | 晚会/上层区特殊事件之后 |
| 泳装、澡堂 | 《水日》：她顺路去澡堂/配给站，白色泳装外披外套 | 店外短过场或窗口 | 一次性场外特殊事件，不是日常菜单 |

窗沿与店外沿用已有当铺结构；住处和场外地点以一次性剧情转场交代。

### CG 插入规则

1. **中场 CG 要落在转折点**：袭击开始、旧物被认出、求婚说出口、合同落笔、单子摊开、包扎开始；不要随机插在普通问答中间。
2. **CG 之前先给一个动作断点**：搬货、扫玻璃、递怀表、翻账本、摊单子；让 CG 是动作的自然停顿，而不是硬切。
3. **同一路线同一幕最多一张事件 CG**：优先把预算给高情绪、长对白、无现有图的场景。
4. **实现方式**：沿用 `EndingPageUI.ShowStoryScene(titleKey, cgKey, textKey, onContinue)`；在目标行前/后挂 `startAction` 或拆块，不新增 UI 系统。
5. **文本与 CG 分工**：关键事实仍由对白/交易承载；CG 只负责停顿、情绪和吸引力强化。
6. **亲密镜头不越过当前上限**：不上本垒、不直接裸露性器官；用姿态、距离、衣料、光线和她自己的反应表现吸引力。

## 文本平台期的处理顺序

连续对白过长时，先按这个顺序处理：

1. 拆出动作/交易断点（搬货、找零、包东西、翻账本、包扎）。
2. 换表情/立绘/光线，或让旁白只写可见动作。
3. 仍然过长，再插入中场 CG。

不要用一张 CG 替代场景结构问题；CG 是节奏工具，不是 AI 文风的解药。
