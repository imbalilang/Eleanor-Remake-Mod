# 现行文本体检与 NovelWorkFlow 改造建议

**日期：** 2026-11-16  
**适用基线：** MOD 1.12 现行 `Content/*.json`、`tools/NovelWorkFlow_Eleanor/`、`tools/super_qa/`  
**目的：** 在不让 Agent 直接充当正文作者的前提下，判断当前文本的真实问题，并提出基于现有主笔流水线和超级 QA 的改造方向。

## 1. 先固定生产历史和权限

本项目的文案生产已经经历三层：

1. **Agent 直接写正文：约 3 分。** 这条路径已经证明不适合作为默认生产方式。
2. **NovelWorkFlow_Eleanor + 主笔模型重生成：约 5 分。** 主笔负责小说正文，Agent 负责准备世界书、调用、整理和接入。
3. **NovelWorkFlow 初稿 + Super QA：约 6 分。** 主笔负责创作，Super QA 负责事实、空间、术语、格式和局部文风修订。

因此后续必须使用下面的权限划分：

| 角色 | 可以做 | 不可以做 |
|---|---|---|
| 作者 | 确定 canon、路线、尺度、取舍和最终否决 | 不需要逐行替 Agent 写正文 |
| Opus/NovelWorkFlow 主笔 | 在 world book、ActCard 和现有格式内生成小说候选 | 不决定游戏状态、路线、道具和结局 canon |
| Super QA 重写者 | 按 Brief 对已有候选做最小修订或 voice pass | 不从零替代整幕，不新增事实和结构 |
| Agent | 取证、写 Brief、准备 world book、调用流水线、A/B/C 对照、正规化、应用有 manifest 的候选补丁 | 默认不直接创作或润色 Content 正文 |
| 校验器/转换器 | 检查标签、行数、事实、分支、键、术语和包完整性 | 不替角色决定台词，不自行补剧情 |

Agent 可以直接改格式、标签、键映射和有明确证据的机械术语；任何实质性台词变化都必须来自 NovelWorkFlow 或 Super QA 候选，并保留 source hash、Brief、模型参数、候选对照和 patch manifest。

## 2. 当前文本的真实质量

### 2.1 原作的参照尺度

现有原作文本快照显示：

- 平均对白约 14.1 个汉字；
- 普通来访通常 6–11 个气泡，少数峰值达到 14 个；
- 独立旁白为 0；
- 带行内动作约 1.7%；
- 选择通常 0–1 个，每次 2 个选项；
- 角色靠自己的称呼、节奏和具体欲望区分，而不是靠共享口头禅。

这不是要求 MOD 永远复制原作数字，而是说明玩家熟悉的基本节奏：短来访、一个具体事件、一个小转折，然后离店。

### 2.2 现行 MOD 的优点

当前文本已经不是早期 3 分稿，局部具备可保留的质量：

- 共同线 c01、c02、c05 有明确的埃莉诺处境、骄傲和现实让步。c05 的“不是来讨饭”“账记着”“今天的事不许说出去”比抽象心理总结有效。
- 共同线 c17 的母亲来访有具体的货物、工作和埃莉诺传话，现有版本比测试版更完整，不应为了追求短而整体替换。
- 恋爱线 `love_a2_01`、`love_a2_02` 把停水、价格、提水和索菲娅对玩家的观察放在具体行动里，是目前较好的生活事件写法。
- 后宫线 `dv08`–`dv13` 有明确的欲望、拒绝、道歉和三人确认；作者已经手改的终章不应被通用“去 AI 味”流程重写。
- 侍从线和革命军线已经通过 voice pass 形成阶段语气；它们的问题主要是场景体量和长连续，而不是所有句子都需要换写。
- C19 的现行文本有吊坠、母亲、元件、拾荒和价格历史等长期回扣，连续性强；它的问题集中在告白公式和单次来访塞入过多内容。

### 2.3 AI 味的主要集中区

现有 Super QA 清单、Inventory、原作对照和测试稿共同指向以下问题：

1. **单次来访过长。** 当前 MOD 平均约 45.6 行/场；`c10` 为 116 行；革命军多个场景出现 14–16 句同一 NPC 连续；侍从后期有 13 句连续。一个来访承载太多事件时，角色只能靠解释、回顾和总结把场景撑满。
2. **长情绪场景套公式。** 典型结构是“我喜欢你—说完了—你看着办”，或把关系协商写成第一、第二、第三条款。C19 的当前版本完整，但“说完了”“你看着办”等公式集中出现。
3. **共享口头禅跨角色扩散。** 已有清单记录“算了”39 次、“行吧”27 次、“你倒是”25 次、“别以为”20 次、“我记着”14 次、“说完了”11 次。单句未必错误，跨角色和跨路线复用后会产生同一作者的声音。
4. **抽象总结替代当场反应。** “关系确认”“从此以后”“你让我明白了”一类句子把读者已经看见的变化再解释一遍。Super QA 能识别其中一部分，但目前没有把它作为主笔阶段的场景设计问题处理。
5. **动作和表情出现补偿性过量。** C19 的一次测试曾生成几乎每句一个表情、四条独立旁白；当前部分侍从/革命军场景又有动作说明书倾向。模型在努力“表现”时，反而暴露格式服从感。
6. **玩家台词不是太多，而是太同质。** 现有清单统计玩家行平均较短，很多是“嗯/好/行”。不能简单删掉玩家台词；应把其中一部分变成有明确态度的选择或动作，保留店主寡言和玩家主动性。
7. **角色卡容易退化成口癖清单。** 如果提示词只告诉模型“某人常说什么、下一步做什么”，模型会把共享模板分配给所有角色。角色需要的是情境行为：她什么时候回避、什么时候抢话、什么时候用工作话遮住情绪。

## 3. 继续使用流水线时的总体判断

**建议继续使用 NovelWorkFlow_Eleanor，但先改生产用法，再考虑改全局模板。** 目前最可靠的证据不是“再加一条禁止 AI 味”，而是已有 C17/C19 测试：

- 普通交易场景的原作式短气泡可以写得自然，C17 测试接近原作节奏；
- C19 的单场告白即使逐句改顺，仍会因承载过多内容而变成长独白；拆成两个短来访后，节奏和角色声音明显改善；
- prose-first 候选适合做欲望、动作和场景转折的实验室，不适合作为游戏正文；它需要一个确定性转换层才能进入气泡脚本；
- Super QA 对事实、术语、空间和局部口癖有效，但不能替代主笔重新设计场景，也不能让 Agent 手工把所有句子改成“更像人”。

所以第一优先级应是**场景架构和主笔输入**，第二优先级才是句子级修订，第三优先级才是模板重构。

## 4. 第一阶段：只改 world book/ActCard，不改生产模板

`writer_prompt_template.md` 当前是正式入口，修改它需要作者明确批准。第一轮不直接改它，先通过复制的 active world book 和 ActCard 做低成本试点。

### 4.1 为每个场景增加场景类型和体量预算

在 ActCard 中明确以下字段：

```text
【场景类型】普通交易 / 生活观察 / 关系推进 / 告白 / 冲突善后 / 路线高潮 / 结局收束
【本场只发生一件事】……
【角色当下欲望】……
【阻碍】……
【具体物件或业务动作】……
【本场转折】……
【离店时留下的事实】……
【气泡预算】普通 6–11；关系 8–14；高潮超过 14 必须拆场候选
【选择预算】普通 0–1；关系 1；不做连续微选择
```

这些是写作输入，不是事后用来硬砍字数的 KPI。普通交易可以接近原作体量；告白和高潮如果自然超过预算，优先拆成两个来访，而不是把解释压回同一场。

### 4.2 重写角色卡的组织方式

不再以“常用词 + 三段式动作公式”为主，改为四类情境规则：

- **她想要什么时怎么开口；**
- **她不愿承认时怎么绕开；**
- **被玩家看穿时怎样反击或转回业务；**
- **她真正动摇时留下什么具体动作或物件。**

每名角色保留 10–20 条非露骨、按阶段分组的正面语料；共享口头禅只作禁止重复检查，不能写成所有角色都要使用的范式。

### 4.3 把“反 AI”从创作要求改成场景事实约束

world book 应要求主笔提供：

- 一个角色能看见或触碰的具体物件；
- 一个正在进行的业务或生活动作；
- 一个角色没有说出口的欲望；
- 一个玩家能用选择或短动作回应的节点。

不再要求“每句话都新颖”“绝不重复任何结构”。跨场景重复由 Super QA 的审查和 Registry 处理；主笔阶段只需避免同一场把主题解释两遍。

## 5. 第二阶段：NovelWorkFlow 主笔试点

首轮只选五个场景，不重新生成整条路线：

1. c17：普通交易/母亲观察，作为低风险对照；
2. c19：告白峰值，验证是否拆场；
3. `love_a2_01`：生活事件和交易；
4. `dv08`：后宫个人告白；
5. `v2_r1c1`：革命军第一张单子，验证疲惫/战术声音。

每个场景使用当前正式的三文件输入链：`writer_prompt_template.md`、`writer_system_prompt.md` 和指定 `world_book*.json`。修改只写入 world book 副本或测试输出，不直接覆盖 Content。

每个场景保留三份：

- A：当前运行文本；
- B：NovelWorkFlow 主笔候选；
- C：Super QA 最小候选。

比较时不只看“更顺”，还要看：场景长度、最长同一角色连续、具体动作数量、玩家回应质量、角色可辨识度、事实差异、分支完整性和继续阅读意愿。

## 6. 第三阶段：确定是否需要转换层

已有测试说明两条路线都值得保留，但用途不同：

### 6.1 普通场景：直接生成游戏气泡

C17 类型的普通交易优先使用短气泡格式。主笔直接输出生产标签，减少中间层，避免转换器再次压缩或添加模型味。

### 6.2 情绪峰值：先做行为候选，再转换为气泡

C19 类型的告白、后宫谈判、革命军归来可以先让主笔明确“欲望—阻碍—转折—离店事实”，再输出气泡候选。若 prose/idiom 候选持续比 line-first 更自然，再开发一个**确定性转换器**：

- 只负责拆段、合并可合并的对白、把短动作附到对应气泡、生成合法标签；
- 不决定剧情、不补角色台词、不新增道具和状态；
- 生成后交给 `check_text_contract.py` 和 Super QA；
- 没有明确行号映射时不得写回 Content。

转换器不是新的主笔，也不能用它把 1,600 字小说自动“压成合格剧本”。如果转换结果损失了玩家选择、角色声音或事实，保留 A。

## 7. 第四阶段：Super QA 的职责调整

Super QA 继续保留，但从“泛化去 AI 味”改成定点修复：

1. 先由 Agent 做 Inventory、原作对照、概念考古和 Rewrite Brief；此阶段不改正文。
2. 由重写者按 Brief 生成 minimal 或 voice-pass 候选；Agent 不手写替代台词。
3. 用 A/B/C 对照选择骨架；A/B/C 任何实质性文字差异都保留来源和模型记录。
4. Agent 只做标签正规化、表情配额、分支挂接、事实机械修复和 patch 应用；不能为了“更自然”直接重写一行。
5. 高风险章节默认保守：如果候选更顺但失去原有回扣、角色边界或作者手改内容，退回 A。

Super QA 的优先级应是：P0 事实/空间/路线 → P1 结构/重复公式/角色同声 → P2 动作和表达偏好。不能用 P2 个人口味阻塞整批。

## 8. 第五阶段：再决定是否改 writer_prompt_template

只有五场试点证明 world book/ActCard 调整仍不足时，才提交模板修改方案。模板修改方向应是：

1. 删除或改写全局“每章 35–55 行”要求，使 ActCard 的场景预算成为唯一体量依据。
2. 将格式、交易、演出契约压缩为短的硬约束，把详细负面例子移到确定性 QA 文档。
3. 将“避免一切重复”改成“避免同一场重复解释同一事实”；共享口头禅和跨场景重复交给检查器。
4. 增加“本场只有一个转折、一个具体物件、一个离店事实”的输入字段。
5. 明确普通交易、关系推进、高潮和结局的不同预算；超过高潮预算时输出拆场候选，不在一场内填充。
6. 保留现有交易声明、分支附录和表现契约，不让主笔决定游戏状态。

这一步需要作者批准后才编辑 `writer_prompt_template.md`；在批准前只使用 world book 副本完成试点。

## 9. 不应采取的方案

- 不做全量 86k 重写。
- 不让 Agent 直接逐句“润色到像人”。
- 不把所有场景强行压到 6–10 行；普通场、告白和结局的体量不同。
- 不全局禁止所有重复词、所有旁白或所有 `<i>` 动作；原作也有角色自己的重复和碎片句。
- 不让 Super QA 重写作者已经确认的后宫终章。
- 不把 prose-first 原稿直接当游戏正文。
- 不以“AI 检测率”作为质量结论；使用原作对照、A/B 盲读、角色辨识度和继续阅读意愿。

## 10. 推荐的第一批执行顺序

1. 保存当前 1.12 文本、world book 和测试输出的哈希。
2. 复用已有 C17/C19 测试材料，避免重复调用模型。
3. 只修改 `world_book.json`、对应 ActCard 和测试输出目录，先跑 c17/c19。
4. 由 Opus/NovelWorkFlow 生成主笔候选；不直接写 Content。
5. 用现有 Super QA 做 Brief、minimal/voice-pass 候选和 A/B/C 记录。
6. 对 C17 保留当前版与测试版对照；对 C19 重点验证“两次短来访”是否值得结构变更。
7. 只有试点在盲读和离线闸门中胜出，才生成 patch 并考虑接入。
8. 接入后运行 `build_content.py`、`check_project.py`、`check_route_map.py` 和必要的实机验收。

## 11. 成功标准

第一轮不追求把全项目从 6 分变成统一的“满分”，而是验证生产链能稳定得到更好的候选：

- 普通交易场景保持具体、短促、可区分，不被过度润色；
- 情绪峰值不再用一场长独白承载所有转折；
- 角色声音来自情境行为，不依赖跨角色共享口癖；
- Super QA 能修事实和局部表达，但不会把作者文本抹平成同一种风格；
- Agent 全程可追溯、可回退，不直接成为正文作者；
- 至少一个试点场景在 A/B 盲读中比当前版更愿意继续读，且没有事实、结构、路线和旧档回归。
