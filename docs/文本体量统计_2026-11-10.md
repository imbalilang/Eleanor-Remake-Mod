# 文本体量统计（原作 vs MOD）

日期：2026-11-10
用途：统一“多少字、多少行、多少句”的口径，避免把不同范围直接对比。

## 0. 结论先说

**38,611 这个数字本身没有错，但它不是“Eleanor 个人剧情扩展”的字数。** 它是当前 MOD **全部故事 JSON、全部分支**的汉字数：

- 原作全作对话：**30,199 汉字** / 35,486 可见字符 / 2,544 行 / 3,046 句。
- MOD 全部故事：**38,611 汉字** / 44,919 可见字符 / 2,391 行 / 3,775 句。

所以“3.0 万 vs 3.8 万”是：

> 原作全作对话（所有角色、所有剧情） vs MOD 全部故事（所有路线、所有分支）

不是：

> 原作 Eleanor 线 vs MOD Eleanor 个人扩展

原作 Eleanor 线本身只有 **2,064 汉字 / 2,389 可见字符 / 144 个文本节点 / 199 句**。MOD 的核心故事 `story_v06.json` 是 **12,607 汉字 / 14,575 可见字符 / 871 行**，约为原作 Eleanor 线的 **6.1 倍**（汉字数）；MOD 全部路线合计才是 3.86 万。

## 1. 统计口径

- **行**：一个对白节点/一条 `lines[]` 条目。不是阅读稿里的视觉行。
- **可见字符**：去掉 `<...>` 标签和空白后的全部字符，含标点、数字、拉丁字母。
- **汉字**：只统计 `\u4e00-\u9fff`，不含标点、数字、拉丁字母。
- **句**：按 `。！？!?；;` 和连续省略号切分，非严格语言学句数。
- 只统计中文；英文分卷与 UI 菜单不计入故事体量。
- MOD 统计包含**所有互斥分支**，不是单周目实际阅读量；原作 `Dialogue` 表同样包含所有分支/变体。
- 玩家行动/选项提示是游戏节点，计入“行”；不计入“玩家自由对白”。

## 4. 正确的对比

### 4.1 MOD 全部故事 vs 原作全作

| 指标 | 原作全作 | MOD 全部故事 | 倍数 |
|---|---:|---:|---:|
| 行 | 2,544 | 2,391 | 0.94× |
| 可见字符 | 35,486 | 44,919 | 1.27× |
| 汉字 | 30,199 | 38,611 | 1.28× |
| 句 | 3,046 | 3,775 | 1.24× |

结论：MOD 全部路线的汉字总量约为原作全作的 **1.28 倍**；行数反而略少（0.94×），因为 MOD 单行更长（18.8 可见字/行 vs 原作 13.9 可见字/行）。这更像“用更少的行写了更长的句子”，不是“3.8 万 vs 3 万”的 1.27 倍个人扩写。

### 4.2 MOD 核心故事 vs 原作 Eleanor 线

| 指标 | 原作 Eleanor 线 | MOD `story_v06` | 倍数 |
|---|---:|---:|---:|
| 行 | 144 | 871 | 6.05× |
| 可见字符 | 2,389 | 14,575 | 6.10× |
| 汉字 | 2,064 | 12,607 | 6.11× |
| 句 | 199 | 1,295 | 6.51× |

结论：如果比较“Eleanor 相关核心文本”，MOD 核心故事约为原作 Eleanor 线的 **6 倍**，不是 1.28 倍，也不是 18 倍；3.86 万是加上侍从、双恋、互动等全部路线后的总数。

### 4.3 其他比例

- MOD 全部故事中，`story_v06` 占 36.4% 的行、32.7% 的汉字。
- 原作 Eleanor 线只占原作全作的 5.7% 行、6.8% 汉字。
- 原作全作平均 13.9 可见字/行；MOD 全部 18.8，MOD 核心 16.7。MOD 即使总量接近，句子仍偏长。

## 5. 需要保留的提醒

1. 3.86 万是 **汉字数**；按可见字符是 4.49 万。3.02 万是原作汉字数；按可见字符是 3.55 万。两套数字不要混用。
2. 当前统计是**全分支资源量**。单周目实际阅读量会更低，尤其是侍从/后宫/双恋/丙丁互斥路线；后续如需“单路径字数”，要按实际分支重新统计。
3. 3.86 万包含共同前段、普通、侍从、双恋、后宫、丙丁、旧档修复和互动，不只是 Eleanor 的“个人线”。
4. 原作 3.02 万也不只是 Eleanor，而是全游戏所有角色的 `Dialogue` 表。

## 6. 口径矩阵：哪些能比，哪些不能比

| 问题 | 应使用的对比 | 说明 |
|---|---|---|
| 这个 MOD 总共写了多少？ | MOD 全部故事 vs 原作全作 | 全分支对全分支；当前为 1.28× 汉字 |
| Eleanor 核心扩写了多少？ | `story_v06` vs 原作 Eleanor 线 | 当前为 6.1× 汉字；`story_v06` 含普通/丙/丁/尾声分支，仍不是单周目 |
| 玩家单周目实际读多少？ | 按实际路径统计 | **尚未统计**；当前所有数字都是全分支资源量 |
| MOD 核心 vs 原作全作 | **不建议** | 这是“子集 vs 全集”，只能说明核心部分占原作全作的约 42% 汉字、34% 行，不能当成 MOD 总规模或扩写倍数 |
| MOD 全部故事 vs 原作 Eleanor 线 | **仅作极端参照** | 18.7× 只表示“所有 MOD 路线合计”相当于“原作一条个人线的多少倍”，不是个人扩写倍数 |

`story_v06.json` 包含 c01–c23（共同/普通）、rc 丙线、rd 丁线和 ep/end 尾声；不含侍从 `maid_v05`、双恋 `dual_romance_v04`、关系修复 `relationship_choices_v1` 和互动 `interaction_v1`。因此它既不是“全 MOD”，也不能直接对应“原作全作”。

如果要做严格的单周目对比，需要先按实际分支路径取一组 block/line，再分别统计原文与 MOD；本轮没有做这一步，不能把全分支数字当作单周目长度。

## 7. 体量结论与预算建议

当前 MOD 全部故事为 **38,611 汉字**（全分支），不是单周目；单周目实际阅读量尚未统计。分路线大致为：

| 路线/来源 | 汉字（全分支） |
|---|---:|
| 共同 + 普通 c01–c23 | 10,187 |
| 丙线 `rc` | 1,269 |
| 丁线 `rd` | 332 |
| 尾声 `ep/end` | 819 |
| 侍从 `maid_v05` | 15,933 |
| 双恋/后宫 `dual_romance_v04` | 8,861 |
| 关系修复 + 互动 | 1,210 |

判断：

1. **不能仅凭 38,611 这个全分支总数就砍剧情。** 它只比原作全作多 28%，而且玩家单周目不会读完全部分支/路线。真正要量的是单周目，而不是资源总量。
2. **真正需要控制的是“每条线的预算”和“重复表达”**：当前侍从线 15.9k、共同/普通 10.2k，已经偏大；革命军线只有 1.3k，明显偏薄。如果两条未完成线包含革命军线，它更需要补，而不是从别处砍掉剧情。
3. **建议预算（待确认，不是既定规则）：**
   - 全 MOD 全分支：**50k–55k 汉字**封顶；当前 38.6k，给两条未完成线约 **6k–8k/线**。
   - 单周目：目标 **12k–18k 汉字**，需要按实际路径统计后再定。
   - 现有文本先做 **10%–15% 的表达/重复压缩**（不是砍剧情），把长解释、重复分支和长旁白收紧，为新增路线留预算。
4. **不要让两条线按当前侍从线的密度自然膨胀。** 侍从线 15.9k 已经是最重的一条；若两条线各写 12k–15k，全 MOD 会到 60k 以上，翻译、校对、QA 和阅读节奏都会变重。
5. **优先级**：先补两条未完成线中明显偏薄的革命军线；同时用 V5 的因果/声音标准写，不追求字数对齐。剧情可以保留，砍的是重复、解释和无效日常，不是砍路线。

> 执行规则见《文风与玩家台词基准》第 13 节：少字、留白、纯过渡章可删、全分支 50k–55k 预算与两条未完成线的余量。
