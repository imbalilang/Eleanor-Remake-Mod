# 路线图与结局预览维护规范

查看页面：`docs/route_map.html`（浏览器直接打开，无需服务器）。

## 强制规则

任何会改变以下内容的改动，必须在**同一个提交/改动**中同步更新 `docs/route_map.html`，否则视为未完成：

- 剧情章节、场景顺序、目标日期、提前开局日期；
- 任何会改变路线、关系、世界事实或结局的选项；
- 四条主路线的起点、核心分支或完美/非完美判定；
- 结局编号、入口条件、前置条件；
- 侍从/双恋/普通恋爱/朋友之间的关系规则。

## 四条主路线与完美结局

当前页面按**关系主路线**分类，不再把甲/乙/丙/丁当作主路线；甲/乙/丙/丁只作为世界结果或失败分支出现。

| 主路线 | 完美结局 | 非完美结局/分支 |
|---|---|---|
| 常规恋爱线 | **E1** 甲·普通恋人 | E2 甲·朋友、E5 乙·普通恋人、E6 乙·朋友 |
| 后宫线 | **E4** 甲·双恋 | E8 乙·双恋；拒绝/暂缓/朋友 → E1/E2/E5/E6 |
| 侍从线 | **E3** 甲·侍从恋人（契约完成/续约） | E7 乙·侍从恋人；E3 未完成/部分状态；重大背叛 → E11-E14 |
| 革命军线 | **E9** 丙·恋人/牵挂 | E10 丙·朋友/无恋爱；擅自公开/退出 → E13/E14 |
| 共同失败分支 | 无 | E11 交盘、E12 卖盘、E13 擅自公开、E14 退出调查 |

完美集合固定为 **E1 / E4 / E3 / E9**；其他 E1～E14 全部是非完美结局。当前以甲线（研究归还、母亲安全）作为各关系主路线的完美世界结果；乙线同关系但世界结果不同，列为非完美变体。若产品决定改变完美判定，必须同时修改本表、页面 `DATA.endings.perfect`、`CHART` 中 `cls:"perfect"` 的节点和 `tools/check_route_map.py`。

## 编号规则

- 现有编号 **E1～E14 永久稳定**，不得重排、复用或改号。
- 新增结局追加 **E15、E16……**，并在 `DATA.endings` 中填写 `mainRoute` 与 `perfect`；`CHART` 中新增对应终端节点。
- 删除的结局保留编号，在页面标注“已废弃”，不要删除编号。
- 死亡/被捕/离站是结局后缀（如 `E1-死亡`），不是新编号。

## 页面数据

`route_map.html` 是固定布局的 SVG 流程图，使用两个 JSON 数据块：

- `DATA`：`version`、`days`、`routes`、`endings`；结局索引和检查器使用。
  - 每个 ending 必须包含 `mainRoute`（`regular`/`harem`/`maid`/`rev`/`failure`）和 `perfect`（布尔）。
- `CHART`：SVG 的 `nodes`、`edges`、`lanes` 与 `axis`。
  - `axis`：`x`、`top`/`bottom`（当前 20/70 普通天）、`yTop`/`yBottom`（当前 40/2240）、`step`（5 天一个刻度）、`earlyOffset`（11）和标题。**纵轴是普通天**，提前开局 = 普通天 − 11。
  - 每个节点必须写 `day`（普通天，可为小数），`y` 必须由发生日换算：`y = yTop + (day - top) * (yBottom - yTop) / (bottom - top)`，当前为 `40 + (day - 20) × 44`。同一天的节点必须在同一水平线上；不要为了避让而随意改日期。`tools/check_route_map.py` 会校验每个节点的 `day` 与 `y` 是否一致。
  - 节点字段：`id/day/x/y/w/h/lines/cls`；`cls` 为 `common`、`decision`、`regular`、`harem`、`maid`、`rev`、`bad`、`perfect`。
  - 泳道是纵向列：共同失败分支 260 宽（x=180），共同部分 260 宽（x=460），四条主路线各 540 宽（x=760/1320/1880/2440）；画布 3020×2300。
  - **每条主泳道左侧是金色完美路径，右侧是红色非完美路径**，避免完美连线穿过非完美节点；共同失败分支放在最左侧独立泳道。
  - 四条主路线起点节点文字含“路线起点”；核心分支节点文字含“核心分支”；非完美分支节点含“非完美分支”；共同失败终点放在最左侧泳道。
  - 完美结局节点 `cls:"perfect"`，按路线终局窗口摆放：E1/E9 在第 59 天（主线第 24 章），E4/E8 在第 67 天（dr20），E3/E7 放在第 67 天终局窗口（侍从契约无固定期限）；不再有底部完美线。其他结局是非完美终端，不能有出边。
  - 共同失败分支按触发日错开：E14 第 41 天，E11/E12 第 43 天，E13 第 44 天。
  - 后宫线包含 dr07/dr11/dr14/dr15 里程碑节点（第 54/59/61/62 天），与 dr05、dr17 一起显示真实时间轴。
  - 长距离跨泳道连线可用 `edge.labelT`（0～1）把文字放到目标附近；不填时默认 0.5。
  - 新增/移动节点时先按日期计算 `y`，再调整 `x` 和宽度，避免重叠、文字溢出和长线穿过节点。

## 修改流程

1. 改 `Content/*.json`、`src/*.cs`、`Localization/*.csv`；
2. 改 `docs/route_map.html` 的 `CHART.nodes` / `CHART.edges`：先按 `CHART.axis` 把每个事件换算成发生日的 `y`，再调整起终点、核心分支、非完美分支和完美结局节点；
3. 改 `DATA.endings`（`mainRoute`、`perfect`、条件）和 `DATA.days`/`DATA.version`；
4. 改 `docs/ROUTE_MAP_MAINTENANCE.md`（如规则或完美集合变化）；
5. 改 `docs/RELEASE_*.md`、README、工坊说明（如果该版本要发布）。

## 发布前检查

1. 运行 `python tools/check_route_map.py`，确认 manifest 版本、E1～E14、完美集合 E1/E4/E3/E9、`mainRoute`、终端节点、`CHART.axis`、节点 `day` 与 `y` 对齐、已移除的重复退出项都正常。
2. 用浏览器打开 `docs/route_map.html`，确认：
   - 纵轴天数刻度与节点 `y` 对齐，同一天的节点在同一水平线上；
   - 顶部共同部分、四条主路线起点、核心分支、非完美分支点都可见且无重叠；
   - 四条泳道相互分开，完美路径在左、非完美路径在右，长连线尽量不穿过节点；
   - 完美节点只有 E1/E4/E3/E9，都位于各自路线的结束日，且都是终端节点；
   - E11～E14 位于共同失败分支，并按第 41/43/43/44 天排列；
   - 结局索引表的“主路线/判定”与流程图一致；
   - 维护说明的版本和最后更新日期已更新。
3. 对照 `StoryDirector.TargetDay`、`MaidStory`、`DualStory`、`Content/dual_romance_v04.json` 检查日期和选项。
4. 对照 `docs/RELEASE_*.md` 检查已发布/未发布状态。
