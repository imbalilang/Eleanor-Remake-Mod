## 1. 本阶段先固定的判断

五场试点没有证明更换模型能够解决 AI 味。Opus 继续作为生产默认主笔，Gemini 4 Argon 只在高风险关系场景作为平行候选。下一轮的主要变量必须是场景输入、事实契约和场景结构，不能同时更换主笔、改全局模板和重写正文。

五场的处理决定如下：

| 场景 | 当前决定 | 下一步 |
|---|---|---|
| `c17` | 保留 A；当前交易已经具体 | 不再生成候选，只作为普通交易基准样本 |
| `c19` | 保留 A；告白节点和两处镜像必须锁定 | 暂不重跑、不拆场；以后有明确问题再立项 |
| `love_a2_01` | A 暂不替换；候选出现预算和尾段事实错误 | 修正交易事实注入后，做一次定向复跑 |
| `dv08` | 保留 A；两版候选没有形成净收益 | 不再生成候选，保留为关系场景对照样本 |
| `v2_r1c1` | A 暂不替换；两模型都复现 16 句连续 | 先做两种结构研究，再决定是否生成候选 |

本阶段不得：

- 修改 `Content/*.json`、正式 `world_book*.json` 或正式 `writer_prompt_template.md` 作为试验手段；
- 把 Agent 直接写的台词当作正文候选；
- 把 `c19` 的“就这些。你看着办。”自动替换成模型偏好的表达；
- 让模型决定交易预算、客户、交易类型、状态、路线、结局或拆场结果；
- 因为 P2 口味问题反复调用模型，忽略已有事实和结构风险；
- 把“零修改”当作文风质量已经证明，只能把它记录为“本轮没有发现有证据的最小修订”。

## 2. 阶段目标与完成定义

本阶段只验证三件事：

1. ActCard 能否清晰规定本场目标、允许调整的结构和可解释的体量预算，避免互相冲突的要求。
2. 交易事实能否以机器可核对的方式注入，阻止主笔猜预算、客户和尾段接法。
3. 对超长场景，先拆分结构是否比换模型更能减少长独白和同一 NPC 连续。

阶段完成必须留下：

- 修正版试点输入、输入哈希和变更说明；
- `love_a2_01` 的定向 A/B 候选及合同结果；
- `v2_r1c1` 两种结构方案的可行性、事实映射、路线影响说明；可行方案才生成正文候选；
- 路径一致的 A/B/C 阅读包、评审记录、采用/保留决定和成本记录；没有实际读者时不声称已完成盲读；
- 明确的模板决定：继续不改，或提交需要作者批准的最小模板变更提案。

本轮保持生产默认和正式正文不变。正式模板只有在第 9 节的具体提案获批后才可修改，并重新记录输入基线。

## 4. P1：修正场景输入，而不是先改全局模板

### P1-01 让 ActCard 的场景预算可执行

在下一轮 world book 副本中增加明确的优先级声明：

```text
【任务模式】现有场景修订 / 结构研究；明确二选一。
【本场目标】一个具体事件、角色当下想得到的东西、玩家能回应的节点。
【长度】分别填写单条可达路径总气泡、关键段气泡、最长 NPC 连续的预期。
【参考】普通交易 6–11、关系片段 8–14；不是所有已有完整场景的硬上限。
【超预算处理】指出具体信息负担与可分离段；不擅自拆客户端或删除事实。
【冻结项】现有选择数量、分支效果、交易参数、入口出口、作者锁定台词。
```

只在预算试验的世界书副本中清理旧的冲突要求，并检查实际展开后的 prompt。正式模板仍有独立的长度/断章要求，不能声称改副本就已彻底消除冲突。模板修改提案与离线准备同时完成；第 9 节给出具体范围。

预算是结构判断工具，不是事后硬砍字数的 KPI。统一统计单条可达路径，互斥分支不相加，表情标签不算气泡；旁白单列，并同时记录可见字数和空泛玩家回应。不得靠合并超长气泡、插入“嗯/好”或换成旁白来降低连续数。第一轮停水复跑只检验交易事实，保持原体量目标；结构预算只在革命军研究中测试，避免一次改变所有变量。

### P1-02 把交易事实外置成硬契约

每个交易场景的 ActCard 必须单独列出以下字段：

```text
交易锚点：T1
意图：BUY / SELL
类型：HOUSEHOLD_GOOD / TOOL / …
预算：明确数值；没有固定预算时写“原生议价”，不能写“按代码配置”
客户：明确角色
可接尾段：明确 block 或入口
禁止事项：不得新增客户、物品、价格、赠品或第二笔交易
```

`love_a2_01` 的修正版输入必须明确为：`BUY + HOUSEHOLD_GOOD + 预算150 + 客户索菲娅`。`src/LoveStory.cs:128–160` 的运行顺序是交易前/选择 → 原生交易 → 当前结果反应 → `la2_s1_common` → 现有闭店回调。四个结果均接同一共同段且只执行一次；当前复制到各结果块的文本不算正确映射。模型接收解析后的值及引用，不承担阅读源码推算接口的责任。

`c17` 继续锁定现行 `HOUSEHOLD_GOOD`、预算 220、四个交易结果；`v2_r1c1` 继续锁定 `SELL TOOL` 和原生议价，采购留在既有后场。交易声明只允许描述代码已存在的事实，不能由主笔创造新的游戏机制。

### P1-03 将阶段行为写入 ActCard，保留静态角色卡

依照项目规则，`characters.*.writing_notes` 保持全局静态角色卡原文。上轮适配器曾删改并追加阶段材料，下一轮须纠正；下列规则和阶段语料只进入 ActCard/state，不改静态卡：

- 她想要什么时如何开口；
- 她不愿承认时如何绕开；
- 被玩家看穿时如何反击或转回业务；
- 真正动摇时留下什么可见动作或物件。

共享口头禅只作为重复检查线索，不作为必须使用或一律删除的词。语料使用已存在文本并记录来源，不让 Agent 编写新台词示范。停水两模型使用同一份修正后的静态卡和 ActCard；与上轮差异必须列明，因此该复跑用于验证契约，不宣称它严格隔离了全部文风变量。

## 5. P2：先完成革命军首场结构研究

`v2_r1c1` 是本阶段唯一允许进行结构重设计研究的场景。研究只输出候选，不改正文、不改路线图、不改章节键。

先查明真实前场。当前 `src/EleanorStory.cs` 的立即公开分支设置 `Route=3`、`MotherState=2`、`RevVersion=2`，随后进入 `RevolutionV2Story.ChR01`（280）。这只能证明运行入口，不能证明角色在前场已经完成认尸。两方案必须核对选择发生、母亲死亡、认尸、研究公开与入队的叙事先后，不得把前移当作已经可行。

### 方案 R1：认尸保留在本场，检查对单内容是否可以前移

- 保留母亲死亡、认尸、研究公开和加入革命军的事实；
- 当前开场已经有采购单和卖货说明；只把相同动作再放一次不算结构改善；
- 明确可前移的信息、实际承接节点及角色当时是否已经入队。前场无法承接时，记录此方案不可行；
- 若只能在本场重排，明确标为“同场重排候选”，说明如何让业务动作承接信息，并保持来访、交易和状态数量；
- 目标是让丧母事实成为本场压力，而不是连续 16 句说明。

### 方案 R2：认尸事实前移，本场只写补给接触

- 先证明真实上一场能承接认尸事实，再讨论如何移入；只有写入且玩家能实际读到，才可把它作为本场已知背景；
- 本场只保留革命军身份、第一张单子、旧衣决定权、SELL TOOL 和现有 C1 三选项；
- 若认尸在时间上只能发生于分流后，或前移会污染母亲存活的其他分支，标为不可行；不得默认 c18/c19 是革命军的前场；
- 目标是让第一次补给接触成为一个能在窗口内完成的单次来访。

两个方案先由 Agent 输出结构说明与映射，不创作台词。结构可行且没有未决事实后才交主笔；每份研究必须包含：

1. 原 block/index 到目标场景/段落的事实映射；候选生成后补齐实际 block/index 的 `line_map`，生成前不伪造最终行号；
2. 原选择、交易结果、表情和状态的 `key_remap`；
3. 每个事实的保留/前移理由；只可删重复表达，关键事实必须有承接位置；
4. 对 `route_map.html`、路线入口、目标日、旧档和结局的影响说明；
5. 预计气泡数、最长 NPC 连续和玩家有效回应数。

Agent 负责结构判断和推荐，主笔负责依据已确定结构生成正文。若两方案都无法在既有前后场承接，保留 A，提交具体取舍：接受当前体量，或批准新增一个来访并承担相应排期/旧档成本；本轮不自行创建第三种运行结构。

**验收产物：** `structure/R1.md`、`structure/R2.md`、`fact_map.json`、`route_impact.md`。需写出唯一推荐或不可行结论，不能只列两套空白方案。只在确实涉及事实前移、拆场或存档兼容取舍时提交作者决定。

## 6. P3：定向生成与 Super QA

### P3-01 只生成两类候选

第一类是 `love_a2_01` 的事实纠正复跑（流水线验证样本，不预设要替换现稿）：

- Opus 作为主候选；
- Gemini 作为平行对照；
- 固定当前选择、四结果、共同尾段和体量；列明交易事实补全及静态角色卡恢复，两个模型接收相同输入；
- 不再重跑已决定保留 A 的 `c17`、`c19`、`dv08`。

第二类是 `v2_r1c1` 的 R1/R2 结构候选：

- 两个结构方案分别使用隔离 world book 副本，只有可行方案才生成；
- 默认各用 Opus 一次，最多两次；不因两次失败自动追加 Gemini，应先辨认输入冲突或方案不可行；
- 未获采用的结构只留在研究目录。正式三段输出协议外的结构说明由 Agent 保存为报告，不要求主笔偷偷新增 `<结构提案>` 标签绕过模板。

**调用上限建议：** 本轮主笔最多 4 次（停水 2 次，可行结构最多 2 次），Super QA 最多 2 次且只用于有明确修订目标的合格候选。串行调用，无自动重试或换模型兜底；失败后先离线定位问题。运行前按当时价格和输入长度登记估算上限，历史 cost≈1.34212 仅作历史记录，不当作本轮报价。超过既有成本授权的部分先提交完整调用清单，不逐次询问。

所有 POST 预检完整序列化大小，小于 20,000,000 bytes，目标不超过 16,000,000；留存模型 ID、请求/响应哈希、结束状态、token、成本和输入来源。上轮验证的模型可用性不视为永久保证。

### P3-02 Super QA 改为“有目标才改”

本轮明确 A=当前运行稿、B=主笔候选、C=对选定 B 的最小修订；若审的是 A，记为 `C_from_A`。不得把 A 的零改记录当作 B 已完成 QA。

先审核 B 的事实、路径和结构，失败者直接退回，不让 QA 修补错预算或新选择。选定合格骨架后生成稳定 block/index，再制作 Brief。空允许列表只做离线记录，不调用模型返回整份原文。Super QA 的 1:1 是相对本次选定输入，不是用 A 的行数禁止已授权结构研究。输出必须逐字段复刻：

- block、index、speaker、expr、顺序、行数；
- 未授权行的 text 完全相同；
- 镜像块的表达和表情分别验证，不自动复制 `neutral`；
- 若没有证据支持的 P0/P1 改动，返回原文并标记 `zero_changes`。

`c19.b101:13` / `c19.b101_return:13` 的同文关系继续锁定；各行 expr 与各自源字段一致，不能要求两个镜像块的全部表情互相相同。C19 本轮不送审，未来修改作者锁定句须先有明确决定。

### P3-03 修正验证器和记录

在正式候选接入前，验证器必须单独报告：

- 未授权文字变化；
- expr 变化；
- block/index/speaker 变化；
- 新增或删除行；
- 新增选择、交易声明、预算、客户、道具、状态；
- 分支和镜像不一致。

补充运行契约检查，而不是只依赖通用文本 linter。至少用上轮已存在的失败作离线回归样本：停水预算 200/“按代码配置”、共同段重复、C17 新增选择、C19 expr 漂移；合格基线和合法交易结束标签仍须通过。对白中提到其他历史价格不等于预算变化，检查应针对交易声明和映射。

验证器失败时保留候选用于审计，标为拒绝并保留 A；不通过放宽检查器“消化”错误。结构候选按已声明的研究范围验收，不把批准范围内的键变化误报为越权。格式提取错误可以确定性重提取，但保留原始响应、提取版本与差异，不能静默修写正文。

## 7. P4：A/B/C 盲读与采用闸门

先统一 A/B/C 的可达路径。停水覆盖 3 个回应 × 4 个交易结果共 12 条组合；革命军覆盖现有 3 × 4 组合，并单独计算关键段的连续。A 的运行过滤不能漏掉，B 的互斥附录不能累加成一条假路径。

候选不以“更像小说”或“更短”单项决定。先做下表审读，再将同一路径排成随机编号阅读包，隐藏版本名和模型名；映射单独保存。只由已看过来源的 Agent 阅读时，结果叫冷读预审，不声称完成独立盲读。

| 维度 | 通过条件 |
|---|---|
| 事实/机制 | P0=0；预算、客户、物品、状态、交易尾段全部正确 |
| 结构 | 清楚指出事件和转折；超参考体量有解释，不把 14 气泡当统一否决线 |
| 声音 | 玩家、埃莉诺、索菲娅/莉迪亚能靠行为和措辞区分，不靠统一口癖 |
| 具体性 | 物件、动作确实推动当前关系或交易；不为满足清单强塞动作、不重复解释事实 |
| 玩家与回报 | 现有回应承担明确态度；恋爱吸引力、角色主动选择与玩家被需要的体验不因缩短而减弱 |
| 演出 | 窗口内外位置、主客户、backup、表情和旁白符合现有实现 |
| 格式 | 合同、标签、选项、交易声明和 line map 全部通过 |
| 阅读意愿 | 实际读者标出最想跳过/最有吸引力的具体段落；允许平票或现稿胜出，不替读者规定理由 |

执行者先完成有逐行证据的自审；作者只需看一份筛选后的完成候选或少量真正影响方向的取舍，不承担逐章写大纲的工作。有授权且愿意参与的读者才安排盲读，本计划不自行联系玩家。尚无读者时标记 `awaiting_read_review`，绝不补写反馈。小样本用于决定是否采用该场，不宣称项目已从 6 分升到某个分数。

采用结果只能是：

- `retain_A`：候选没有净收益，或任一 P0/P1/事实合同失败；
- `adopt_B`：主笔候选整体胜出且可生成逐行 patch；
- `adopt_C`：Super QA 对明确 Brief 做了最小有效修订；
- `split_proposal`：结构问题得到证据，但需作者批准章节/键/路线影响。

合同通过且自审有净收益的候选可生成未应用的 patch 草案供审阅；阅读验收和必要结构决定完成后才进入正式接入。无胜出稿时输出失败原因与保留决定，不强行生成补丁。

## 8. P5：只有候选胜出后才允许入库

后续执行获得采用结论，且具备该候选接入授权后，才执行以下顺序；当前“生成计划”的请求不触发这些动作：

1. 保存目标 Content 文件的 source hash；
2. 生成逐行 `patch_manifest.json`，记录旧 block/index、旧文本、新文本、来源候选、Brief hash、模型和时间；
3. 通过既有翻译流程完成英文候选并对齐键/事实；只应用有来源记录的变化，机械正规化由 Agent 完成，不让 Agent 自行润色中英文正文；
4. 运行 `python tools/build_content.py`；
5. 运行 `python tools/check_project.py` 和 `python tools/check_route_map.py`；
6. 用仓库内置 SDK 编译 Release；
7. 运行 `tools/super_qa/check_text_contract.py` 和对应离线回归；
8. 停水复核四交易结果到共同尾段恰好一次、闭店/次日衔接；结构变更复核革命军入口、排期、读档和 E9。实机不可用或当前约束不允许时，登记缺口，不能标为发布可用；
9. 保存 diff、哈希、候选、日志和回退点。

任何一步失败，标为 `needs-fix` 或明确的待验证项。结构采用后同步 Content、代码、世界书、`docs/route_map.html`、`docs/ROUTE_MAP_MAINTENANCE.md`、阅读稿与 `site/index.html`（通过现有同步脚本）；验证旧档不跳过或重复叙事/结算。入库前复查自动回归夹具当前状态，不把旧报告中的 Cecil 故障或历史构建通过当作本轮结果。发布、上传、部署不属于本计划自动执行范围。

## 11. 阶段停止条件与作者决策点

### 拒绝当前候选，继续独立的离线工作

- 发现候选未经授权改动路线、结局、目标日、状态、旧档条件或交易实际结算；
- 发现模型越出该候选契约新增预算、客户、道具、选择、表情、角色或空间位置；
- 生成后结构方案无法提供完整 line map/key remap；
- 发现调用输入有未解决的冲突，或需要未经批准的模板修改。

### 可以继续但要登记

- 现有长连续仍存在，但本轮没有新增；
- P2 动作比例偏高，然而没有事实或结构问题；
- 英文尚未同步，但中文候选尚未进入采用阶段；
- 当前 runtime harness 若仍失败，且已明确归类为夹具问题，可继续候选研究；不能据此跳过后续入库回归。

### 必须交作者决定

- R1/R2 中确实改变章节、事实发生时点或存档入口的具体方案；
- 任何需要修改正式 `writer_prompt_template.md` 的方案；
- 超出约定调用上限或扩大素材、路线/存档兼容范围的方案。准备文件、离线审计和普通机械映射不逐项求批准。

## 12. 推荐执行顺序

按以下工作包推进。责任人中的 Agent 是本任务执行者，主笔和修订模型通过现有流水线调用，不另开并行 Agent。时间是工作量估计，不是日历承诺，不含作者审阅或实机等待。

| 工作包 | 责任 | 依赖 | 交付物与验收 | 估算 |
|---|---|---|---|---|
| W0 证据校准 | Agent | 无 | `baseline.json`、`evidence_notes.md`；区分历史/当前差异、纠正 QA 来源和统计口径 | 半天 |
| W1 工具与契约 | Agent | W0 | 输出隔离、输入来源、QA 父稿指定、场景合同检查；历史失败样本能被拦截且旧产物不变 | 半天至一天 |
| W2 两类输入与模板提案 | Agent | W0，可与 W1 独立推进 | 停水事实包、革命军两份可行性研究、模板未应用 diff；无空白事件问题转交作者 | 半天至一天 |
| W3 有界主笔试验 | 主笔；Agent 调度 | W1/W2 完成，输入冲突解决，必要决定已取得 | 停水最多 2 次、革命军可行方案最多 2 次；原始响应、路径映射和费用全记录 | 半天加服务耗时 |
| W4 定点 QA 与阅读 | 修订模型；Agent；作者抽检 | W3 合同合格 | C 明确继承 B；无目标跳过调用；完成阅读包、具体行评语和采用理由 | 半天加阅读等待 |
| W5 一场接入 | Agent | W4 胜出且具体结构/接入权限明确 | 首批只接一场；英文、阅读稿、必要代码/路线图、构建和实机证据齐全 | 依实际改动估算 |

**下一次执行首先交付 W0–W2**：把可调用输入、可行结构和最小模板 diff 准备完整，再进入付费调用或提交必要决定。不要先重跑同一组十次请求。

阶段有两种有效终点：

1. **验证有改善：** 至少一份候选在契约和阅读上胜出，有明确接入方案；完成实机后才进入小范围扩展。
2. **验证无改善：** 保存全量证据，明确是输入、结构、角色声音还是评价流程仍有问题，保留 A 并停止该假设的追加调用；不能把“没出错”写成文本质量提升。

首场接入通过后，再从 active 场景中按玩家可见度、长连续和重复解释选择下一批 2–3 场；没有改善证据就不推广。稳定化、英文扩面和发布仍遵循原总体计划。
