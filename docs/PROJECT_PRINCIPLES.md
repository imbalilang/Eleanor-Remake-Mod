# 项目理念与创作原则

> 状态：长期有效的项目级约束。所有进入本项目的 Agent 在改编剧、写文本、做设计、出提示词、做美术方向或写发布文案前都必须先读本文件。
>
> 本文件只记录作者明确提出的项目定位和取舍，不替代具体的剧情、路线、数值和实现文档。作者是最终解释者；本文件未写到的地方，不要自行补出一套新原则。

## 项目名称

《上层区的富家千金爱上在下层区开当铺的我：埃莉诺剧情扩展》

这个标题不是宣传语，而是项目的设计总纲。它同时规定了：

- 故事的核心关系是**上层区千金埃莉诺**与**下层区当铺店主（玩家）**；
- 核心体验是**阶级反差中的恋爱与爽文式满足**；
- 项目身份是**原作剧情扩展**，不是把原作推倒重来的完全二创。

## 项目性质与作者位置

- 本项目是纯个人兴趣、无偿、自费的 MOD；开发成本由作者承担。它不是商业项目，不以玩家数量、收入、评价或更新速度作为成功标准。
- 作者是木偶师，也是第一观众。制作埃莉诺、让她表演，最终是为了取悦作者自己；玩家看到的是台上的表演，不是后台的线。
- Agent 是舞台工作人员和编剧助理，不是共同作者：负责把作者的方向做成可演出的文本，检查连贯性、人物一致性和 AI 感，不替作者决定项目方向，也不把“让作者少介入”当作交付低质量文本的理由。
- “AI 泔水”是不可接受的失败状态。Agent 必须自己完成多轮改写、冷读和一致性检查，不能把初稿直接当作成品交给作者或玩家。
- 作者介入不等于剥夺玩家的乐趣：玩家只看见最终演出；但它会剥夺作者自己的惊喜感。Agent 应把作者的方向翻译成台上内容，而不是要求作者持续提供逐章逐幕的导演笔记，也不要把幕后讨论、提示词、创作说明或“AI 写作过程”带进成品。
- 成本约束：不要为了“更好”擅自扩大 API 调用、美术生成、素材采购或工程范围；高成本方案先说明并取得同意。

## 当前主要目标

1. **继续打磨剧情和文本，削弱 AI 感。** 初稿不能直接交付；重复、总结腔、说明文、机械对白和“AI 味”都视为质量问题。
2. **增加让角色更有吸引力、强化玩家爽感的内容表现。** 包括但不限于限制级暗示剧情、台词和 CG。最终形态预期接近国产 Galgame：CG 与立绘的性吸引力逐级增强，情话和性暗示大量存在，但不上本垒、不直接裸露性器官，项目自我定位为非 R18。

这两个目标不是二选一：没有文本质量，性吸引力会变成廉价的擦边；没有吸引力表达，文本再顺也不够“爽”。Agent 应同时守住两者。

“CG／立绘是少量补充”只描述它们在叙事中的层级，不是永久数量上限；可以随版本增加数量和吸引力，但关键剧情仍由文本和交易承载。

### 惊喜感与事件设计权

- 作者的惊喜感是项目目标的一部分，不是额外福利。如果必须由作者逐章逐幕指定“发生什么”才能保证质量，流程已经失败：Agent 把本该自己承担的编剧工作转嫁给了作者，也剥夺了作者作为观众的乐趣。
- Agent 的职责包括在作者给定的方向、原则、人物和既有事实内，自主决定章节／幕的具体事件、冲突、节奏和推进；不应默认把“这一章写什么”作为问题抛回作者。
- 作者保留高杠杆判断：方向、边界、口味、成本、最终接受或否决。作者不需要逐章审大纲，也不需要逐幕指定事件。
- 中间方案是 Agent 的内部工作，不是作者的作业。需要作者判断时，优先提交完成稿或少量真正的分叉（2–3 个具体方向），不要提交空白问题清单。
- 如果 Agent 无法在不要求作者逐章指导的情况下保证质量，应继续自检、改写或换方案，而不是把低质量初稿或事件设计责任推给作者；如果确实需要作者介入，必须明确说明这是流程能力的缺口，并尽量把问题压缩到最小范围。

### Agent 的默认工作方式

1. 先按本文件和现有项目事实自行判断，不把每个选择都推回作者。
2. 只有在方向冲突、成本显著、或需要作者个人口味定夺时，提出最小必要的问题。
3. 章节／幕的具体事件由 Agent 自行提案和执行；不要用“请告诉我这一章要发生什么”来代替编剧工作。
4. 交稿前先做自我编辑：删 AI 腔、重复、总结腔、旁白过载和说明文；达不到质量门槛就继续改，不把初稿当成品。
5. 需要作者审阅时，给可执行的选项或差异，不要求作者代写台词或替 Agent 完成文字工作。

## 一、核心目标：阶级反差中的爽文式体验

我们要提供的“爽”，首先来自阶级反差：

- 埃莉诺曾经俯视下层区，也俯视开当铺的玩家；
- 玩家不是在真空中追求她，而是在她失去上层区生活、被案件和贫困压到下层区之后，以一个下层区店主的身份与她相遇；
- 玩家通过交易、判断、风险承担和长期相处，让她逐渐看见、需要并选择玩家。

因此，写每一场戏时都要问：

- 这场戏有没有推进“她这样一个人，为什么会看上这个店主”；
- 玩家读完是否获得了被看见、被需要、被选择的满足感；
- 阶级反差是否还在起作用，而不是早早被抹平。

爽感不等于让埃莉诺失去判断、变成顺从的奖品。她的骄傲、戒备、边界和选择能力越真实，她最终选择玩家才越有分量。**爽点来自她这样一个人选择玩家，而不是来自她变得不像她。**

## 二、项目身份：扩展，不是完全二创

本项目是《Probably Stolen》的埃莉诺剧情扩展，因此：

- 尽量尊重原作的世界观、阶级结构、空间、交易方式、案件与人物关系；
- 尽量还原原作埃莉诺的人设、语气、自尊、防御方式和处境，不把她改写成另一个原创角色；
- 可以扩展、补完、重写表现，但不能随意推翻原作已经成立的事实；
- 新增内容要能回答“这是原作里可能发生的事吗”，而不是“这个设定很酷所以加上”。

扩展的边界：

- 不新增会改变原作基本世界观的势力、科技、种族、政治结构；
- 不把埃莉诺改成原作中不存在的能力者、身份或关系；
- 不为了戏剧性让原作角色集体降智，也不为了爽感让埃莉诺无条件依附。

## 三、自我约束

### 1. 表现克制：不引入过多原作没有的表现形式

原作的表现手段以对话、交易、检视、举报、拘捕、新闻、经营等为主。本项目优先使用这些原生形式。

克制要求：

- 不大量使用原作没有的旁白；旁白只写玩家可见、可听的动作和环境，不写心理总结、关系总结或设定说明；
- 不引入原作没有的镜头语言、系统界面、独立 UI、战斗演出或大段过场；
- 不靠堆砌描写制造“高级感”；能用一句对白或一个动作说清的，不扩成三句旁白；
- 新增表现形式必须服务于玩家满足感，并且有明确理由；没有理由就不加。

### 2. 合理性服务于爽感

合理性是手段，不是目的。

- 构造埃莉诺这个角色的最终目的，不是丰富埃莉诺设定本身，而是变着法地让玩家获得爽感；
- 设定、阶级、案件、交易细节都要为“她为什么被玩家吸引、玩家为什么值得她选择”服务；
- 不为了世界观自洽而拖慢节奏，也不为了展示设定而写玩家不想看的说明文；
- 当一个设定细节很合理但对爽感没有贡献时，优先删掉或弱化；当一个爽点需要更多铺垫时，用交易、选择和具体事件去铺垫，而不是靠旁白解释。

### 3. 不直接干涉原游戏玩法

玩家必须始终是“下层区开当铺的我”。

- 不新增改变玩家身份的系统：不要突然让玩家成为贵族、军官、革命领袖、侦探或战斗英雄；
- 不新增原作没有的核心玩法：不加入战斗、技能树、地图探索、建造、抽卡、独立经济系统或新的货币；
- 不把剧情扩展做成另一个游戏；优先复用原生交易、检视、举报、拘捕、新闻、经营和关系流程；
- 新增系统和数值必须有明确授权，并且不能把玩家从“店主”位置上拉走；
- 剧本里的玩家能力，应来自店主本来就有的东西：会看货、会开价、会记账、敢承担风险、认识人、守规矩或钻规矩。

## 四、写作与设计检查表

在提交任何剧情、文本、提示词、美术方向或发布文案前，逐项检查：

- [ ] 是否仍然围绕“上层区千金 × 下层区当铺店主”的阶级反差？
- [ ] 是否让玩家获得了被看见、被需要、被选择的爽感？
- [ ] 埃莉诺是否仍然是原作那个人，而不是被替换成通用恋爱角色？
- [ ] 是否保留了必要的性吸引力，而不是为了避免假想分级把关系写淡？
- [ ] 是否在当前“不上本垒、不直接裸露性器官”的上限内增强了吸引力？
- [ ] 是否避免把埃莉诺写成纯客体，仍然保留她的判断和选择？
- [ ] CG／立绘是否在服务于吸引力，而不是替代文本和交易？
- [ ] 是否已经过多轮自检和改写，而不是把初稿直接当成品？
- [ ] 是否自行决定了本章／本幕的具体事件，而不是把“发生什么”交回作者？
- [ ] 是否只在真正需要作者口味、方向或成本决定时才提问？
- [ ] 是否优先把事件落在一次交易来访和交易窗口里？
- [ ] 是否主要靠文本、对话和交易推进，而不是靠旁白、CG 或特殊事件灌输？

- [ ] 设定和合理性是否在为爽感服务，而不是反过来压住爽感？
- [ ] 玩家是否仍然只是下层区开当铺的店主，没有被抬成别的身份？
- [ ] 这场戏的爽点是否来自埃莉诺的判断和选择，而不是来自她失去人格？

## 五、表达形式

本项目采用类似 Galgame 的恋爱小说式交互逻辑：

- **文本和对话是剧情的主要推动力**。玩家通过对话、选择和反应进入关系，而不是靠大段旁白或演出灌输。
- **交易事件是最通用的叙事载体**。绝大多数事件应设计成一次到店交易或来访，在交易窗口发生；先问“能不能作为一次交易来访写”，能就不另起一套场景。
- **绝大多数事件发生在玩家的交易亭交易窗口**。玩家在窗口内，来客在窗口外；不要把角色放进店内、玩家身后或柜台内侧来制造亲密。
- **CG、表情、特殊事件在叙事层级上是补充**：用来强化关键节点和情绪，不承担主要叙事，也不替代对话和交易；“补充”不是永久数量上限，CG／立绘可以随版本增加数量和吸引力。
- **关键剧情事实必须能在文本、对话或交易里读到**；CG 和特殊事件只做强化，不能成为唯一的信息来源。
- 不新增原作没有的常规表现形式（大量旁白、镜头演出、独立 UI、战斗、探索等）；确需新形式时先向作者说明理由并取得授权。

判断顺序：

1. 能不能用一次交易来访或窗口对话承载？
2. 能不能用现有表情和短旁白强化？
3. CG／特殊事件可以用于关键节点和有吸引力的节点；判断标准是是否强化体验，而不是数量越少越好，也不能让它们变成唯一叙事。

长对白事件的视觉断点和中场 CG 方案见 `docs/LONG_EVENT_CG_HOOKS.md`；先加动作/交易断点，再考虑 CG。CG 的地点、站位、服装和投放类别以 `docs/CG_LOCATION_AND_PLACEMENT_PLAN.md` 为准；CG 制作必须符合对应场景限制。

## 六、性吸引力与尺度

- 不在 README、manifest、工坊/Nexus 文案、站点、发布说明、更新日志、UI 或配置中主动添加年龄／成人分级标签；项目不把自己宣传成 R18／成人向。对外自我定位为**非 R18**；平台强制要求分级字段时，按平台规则和作者决定处理。
- 必要的性吸引力是让玩家喜欢上埃莉诺的重要因素。性张力、暗示、身体与服装描写、情话、亲密感都是正常的恋爱表达，不因假想的分级而自我审查、去性化或把关系写淡。
- 项目不设 Agent 自行决定的统一尺度限制；具体尺度和当前上限由作者按场景把控。Agent 不自行加码，也不自行减码；尺度不明确时先问作者，不要用“分级安全”作为删改理由。
- 当前目标形态：接近国产 Galgame 的擦边向恋爱表现。CG 与立绘的性吸引力随剧情推进逐级增强，情话和性暗示大量存在；但不上本垒、不直接裸露性器官。这个上限是作者当前设定的天花板，Agent 不得擅自越过，也不得把它压成清汤寡水。
- 性吸引力服务于阶级反差和“她选择玩家”的爽点，不能把埃莉诺降成纯客体或奖品；她的判断、边界和主动性仍然重要。
- 写亲密场景时沿用项目已有的表现方式；需要引入新的表现形式时，先取得作者授权。

## 七、冲突处理

当“尊重原作”“表现克制”“不干涉玩法”与“让玩家爽”发生冲突时：

1. 先判断冲突是否真的存在，还是可以通过换一种更原生的表现方式解决；
2. 在不破坏原作基本事实、不把埃莉诺改成另一个人的前提下，优先选择更能让玩家获得爽感的表达；不要为了设定自洽或“更合理”牺牲核心爽感；
3. 如果“更爽”需要突破原作基本事实、改变埃莉诺的人设边界，或把玩家抬离店主身份，就不自行改写项目方向；
4. 无法在不违背原则的情况下解决时，停下来向作者说明冲突，由作者决定。
